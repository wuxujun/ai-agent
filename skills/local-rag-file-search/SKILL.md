# Local RAG File Search

## 目标

在允许的目录范围内，为用户找到可信的本地文件证据，并基于证据回答问题。

检索不是“把所有文件塞进上下文”。先缩小范围，再读取关键片段，最后引用来源。

## 允许范围

仅访问以下工作区路径：

- `${WORKSPACE}/docs`
- `${WORKSPACE}/knowledge`
- `${WORKSPACE}/uploads`
- `${WORKSPACE}/repo`

禁止访问：

- 用户 Home 全目录
- SSH 密钥、云凭证、`.env`、密码库
- 系统目录，如 `/etc`、`/var`、`/proc`、`/sys`
- 未经显式授权的挂载目录
- 符号链接指向的工作区外路径

遇到疑似敏感文件时，只报告其存在与风险，不读取内容。

## 输入理解

先将请求归类为一种或多种检索意图：

| 意图 | 典型问题 | 首选策略 |
|---|---|---|
| 精确查找 | “找 payment_v2 的 504 错误” | 路径、文件名、grep、BM25 |
| 语义问答 | “部署失败如何排查” | 向量检索、标题检索、重排 |
| 文档筛选 | “上周更新的 API 文档” | metadata 过滤、mtime、路径 |
| 对比归纳 | “比较两份设计文档” | 分别检索、按章节读取、证据对齐 |
| 代码定位 | “哪个服务调用了接口 X” | ripgrep、符号搜索、调用点上下文 |
| 文件发现 | “有没有迁移方案” | 文件名、目录、标题、关键词扩展 |

若用户同时给出术语、编号、错误码、类名、接口名或版本号，必须保留原词进行精确检索。

## 检索流程

严格按以下顺序执行，达到足够证据后停止：

1. **限定范围**
   - 根据用户指定的目录、项目、时间、文件类型和权限范围过滤。
   - 未指定范围时，优先搜索 `docs`、`knowledge`、`uploads`，再考虑 `repo`。

2. **发现候选文件**
   - 使用路径、文件名、扩展名和标题搜索。
   - 忽略 `node_modules`、`.git`、`vendor`、构建产物、缓存和二进制目录。
   - 默认最大返回 30 个文件候选。

3. **精确关键词召回**
   - 对原始查询中的专有词、错误码、版本号、函数名、字段名执行精确搜索。
   - 返回命中的文件路径、行号或页码、上下文摘要。

4. **语义召回**
   - 若精确检索不足，搜索语义相近的标题、段落和 chunk。
   - 对长文档按标题层级、段落、表格或代码块切分；不要跨章节硬拼接。

5. **融合与重排**
   - 优先级：权限过滤 > 文件类型/版本过滤 > 精确匹配 > BM25 > 向量语义相似度。
   - 同时命中精确词和语义相关的 chunk 优先。
   - 对 Top 20 候选重排，最终阅读 Top 3 到 8 个高质量片段。

6. **按需读取**
   - 先读标题、目录、摘要和命中上下文。
   - 仅在答案需要时扩展读取前后段落或完整章节。
   - 不因“可能有用”读取整份超长文档。

7. **生成回答**
   - 只基于已读取的证据回答。
   - 每个关键结论必须标注文件路径和定位信息。
   - 证据不足时明确说明缺口，并给出最接近的发现。

## 文件解析

| 文件类型 | 处理规则 |
|---|---|
| Markdown / TXT | 保留标题层级、列表、代码块和相邻段落 |
| PDF | 提取页码、标题、正文和表格；扫描件需要 OCR 标识 |
| DOCX | 提取标题、段落、表格和页序 |
| HTML | 移除导航与脚本，保留正文、标题和表格 |
| JSON / YAML | 保留 JSONPath / YAML path，避免仅输出整行 |
| CSV / Excel | 先识别表头、主键和行数；按行范围引用 |
| 源码 | 保留仓库相对路径、语言、符号名、行号和函数上下文 |
| 日志 | 按时间、级别、trace_id、error code 聚合 |

解析失败时：
- 报告文件类型、失败原因和可替代的处理方式。
- 不要假装已读取或理解文件内容。

## 检索规则

### 查询改写

为每个问题生成最多 3 个检索式：

1. 原始查询：保留错误码、标识符、版本和专有名词。
2. 术语扩展：加入中英文同义词、缩写或常见别名。
3. 任务导向：加入用户目标，例如“排查、配置、设计、部署、迁移”。

示例：

用户问题：`payment_v2 出现 504 怎么排查？`

检索式：
- `payment_v2 504`
- `gateway timeout upstream timeout payment`
- `payment_v2 runbook incident troubleshooting`

### Chunk 规则

- Markdown：按 `H1/H2/H3 + 段落` 切分。
- 代码：按函数、类型、类或模块切分。
- 表格：表头必须与每个数据片段一起保留。
- 每个 chunk 推荐 300 到 800 tokens，overlap 50 到 120 tokens。
- chunk metadata 至少包括：
  - `source_id`
  - `path`
  - `title`
  - `section`
  - `chunk_id`
  - `line_start`
  - `line_end`
  - `page`
  - `mtime`
  - `content_hash`
  - `acl_tags`

### 混合检索

推荐检索链路：

```text
Query
  -> ACL / 路径 / 文件类型过滤
  -> BM25 Top 50
  -> Vector Top 50
  -> RRF 融合 Top 30
  -> Reranker Top 8
  -> 上下文去重与相邻片段合并
  -> Evidence-grounded Answer
