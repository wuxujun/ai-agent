# Task 异常退出与热日志验收

日期：2026-10-12。实现与验收记录，未部署。承接 [持久化隔离恢复验收](Task持久化隔离恢复验收_2026-10-12.md)。不访问在线业务库，不调用模型，不修改源记录。

## 保持只读拒绝策略

需要可写恢复的 SQLite 热日志保持拒绝。OpenPersistentTaskRestoreSandbox 不删除日志、不调用可写连接、不自动恢复，数据库及日志保留供检查。专用格式标记与私有路径检查不是修复许可；本批次不新增修复命令。

若未来实施可写修复，须另行设计：先验证专用身份与路径，保留数据库及所有日志原始证据与 hash，再在新的私有副本进行有期限的恢复；证明不读取运行时配置、不连接在线 Store、不修改原现场。修复后关闭写连接并以只读方式重新验证完整包和独立记录，任何一步失败不得报告成功。

## 确定性故障矩阵

[回归代码](../internal/store/task_restore_crash_test.go) 使用真实 ImportJoint、约 1 MiB 的有效联合包、8 页缓存及 cache_spill=ON。子进程在插入 Task 记录后通过 SQL 临时触发器报告就绪并阻塞，或在 ImportJoint 提交返回后报告就绪并阻塞；父进程随后强制终止。每个子进程最多 20 秒，不依赖 sleep 猜测提交时间。

| 场景 | 必须观察到的证据与结果 |
|---|---|
| 大事务提交前强制终止 | 主数据库 hash 已改变，确认发生缓存溢写；日志大于 512 字节且具有真实同步日志头；只读重开返回 ErrTaskRestoreTarget，数据库及日志字节保持不变 |
| 大事务提交后强制终止 | 主数据库 hash 已改变；只读重开并逐记录验证成功，restore_ready=false/source_preserved=true；验证不改变数据库字节 |
| 空文件、截断、头部损坏、末页损坏 | 四种物理故障分别拒绝重开；损坏证据字节保持不变 |
| 小事务退出、正常取消和写入故障 | 保留既有测试，分别验证未提交记录不可见或回滚；不用于代替大事务热日志结论 |

重开新增 PRAGMA quick_check 全页结构检查，避免只验证 identity/schema 所读页面就暴露损坏数据库。它不代替原包/hash/关系和独立记录比较，不写数据库，也不授予执行权限。

这些测试证明当前强制进程终止场景下的提交保真与热日志拒绝策略；不模拟存储硬件故障、文件系统缓存丢失或物理断电，不宣称断电恢复保证。提交前热日志目标处于拒绝状态，不宣称已正常回滚或演练成功。
