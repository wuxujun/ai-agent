## 五项源码初核

| 原报告项 | 本轮可确认的源码事实 | 限制与下一步 |
|---|---|---|
| BUG-01：外部 RAG/MCP | `internal/memory/rag_search.go` 使用全局带 CookieJar 的普通 HTTP client；SSE endpoint 经 `base.Parse` 后直接携带配置授权值调用，所读分支没有同源拒绝。 | 当前主配置 `rag.search_url` 为空，该功能默认不执行。启用外部 RAG 前需用专用 httptest 验证跨源 endpoint/redirect 的凭据传递与私网拨号限制；共享 Cookie 的租户影响尚未复现。不得把静态检查直接写成已完成真实 SSRF/凭据泄露测试。 |
| BUG-02：孤立 awaiting_approval 取消 | `cancelTask` 的无本地 owner/无 bus 兜底仅处理 running；删除入口同时拒绝 running 和 awaiting_approval。 | 代码上存在无法直接 cancel/delete 的状态组合。还需专用持久审批夹具验证取消、并发 lease、pending/approved 记录及恢复入口的相互约束；不能只增加一个状态分支就声明整个取消闭环完成。 |
| BUG-03：审批恢复门禁 | `RecoverApprovedApproval` 将 resolution 参数替换后交给 executor；恢复分支没有普通 Next 路径的预算扣减与外部 trace 三类审计，所读 executor/middleware 未补齐参数 Validate。 | 工具自身的文件/网络 policy 仍存在，不能据此声称所有路径限制均可绕过。需分别复现参数/动作合法性、预算耗尽、覆盖参数和外部证据审计差异；保留消费 CAS 的至多一次边界。 |
| BUG-04：re-audit owner 与旧快照 | `reauditTask` 在排队/获取 lease 前加载 Task，获得 lease 后直接 Reaudit/Save；未绑定 `store.WithTaskLease` 或重新加载。SQL lease guard 对无 scope 上下文直接返回 nil。 | 应优先补排队期间 checkpoint 更新和丢失 lease 后写入的回归，再验证 reload、owner 绑定和 lease 生命周期。此问题不是未启用 owned adapter 才会触发。 |
| BUG-05：read_file 资源/编码 | `ReadFile` 使用 `os.ReadFile` 全量读取后截取 4000 字节，Evidence 直接保存该结果；Observation middleware 的 UTF-8 修复不覆盖 Evidence。 | 需要大/稀疏文件有界读取、多字节字符截断、非 regular file 与工作区路径竞争回归。报告所列 write_file TOCTOU 分支本轮未完整核验，不记为已确认修复范围。 |
