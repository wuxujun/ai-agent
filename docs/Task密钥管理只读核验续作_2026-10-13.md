## 原定实施顺序（默认无来源证明时仍保持归属 unverified）

1. 核对 HEAD、工作区及以上入口，保留所有未提交改动。先补 Codec 的空输入长度保护及 v1/v2 边界回归；不改变现有密文格式、key ID 算法或默认轮换行为。
2. 定义版本化 key_management 证据与可信只读密钥提供者。清单声明不能自行证明密钥存在。主/历史密钥仅从显式环境或秘密管理注入，不从 JSON、CLI 参数、config.yaml、数据库路径或工作区文件获取。离线命令仍不读取运行时 config、不初始化在线 Store 或执行器。缺失主密钥、历史版本、非法长度/base64、不可用提供者均拒绝核验。
3. 在已验证的专用沙箱中有配额地读取独立审批密文，实际验证 ActionPayload 与按状态要求的 ResolutionPayload。只在内存验证格式和必需关联：外层 tenant/task/request/版本，解密动作与 Request.Action，resolution 的语义；核对大整数参数保真。若旧格式明文缺少租户/任务绑定，必须明确只能证明外层关系和解密可用性；缺少独立来源绑定证据时不得声称已证明密文归属。不能从“解密成功”推断历史审批仍有效、副作用可重放或 approvals_and_effects 已通过。无审批时也要由可信检查器证明不存在，而不是清单自行省略类别。
4. 将当前密钥提供者版本/轮换状态和实际审批内容纳入状态绑定；评估前后复查，在轮换、撤销、密文变化或证据过期时使旧结果失效。版本标识必须来自可信来源；不输出原始密钥、密钥派生指纹或明文。环境来源的版本变化检测方案需明确设计，不能仅信任操作者上传的版本字符串。
5. 接入 ReadState/CheckEvidence 和离线 assess 的显式选择入口，保留 workspace 组合状态。报告仅给类别、脱敏原因及允许公开的证据摘要；所有其他未接入类别继续 missing/unverified，整体仍 blocked、restore_ready=false、source_preserved=true。

不复用在线 Engine 的审批恢复入口：它会获取租约、消费状态或调用工具。该检查器必须没有审批写入、模型、索引、外部网络写入或源记录移除能力。读取失败后保留专用数据库和证据，不修复热日志、不回填记录、不改写密文。

## 首轮实现与用法（默认无签名来源证明）

入口为 [task_restore_keys.go](../internal/store/task_restore_keys.go)、[readonly_keys.go](../internal/approvalcrypto/readonly_keys.go) 和 [离线 assess](../cmd/task-restore/admission.go)。应用代码可显式注入可信 `ReadOnlyKeyProvider`；当前 CLI 只支持 `environment`，尚未实现外部秘密管理客户端。未选择时不读取密钥环境，也不改变原数据库/workspace 入口。

```bash
go run ./cmd/task-restore assess \
  --directory DEDICATED_SANDBOX --task TASK --tenant TENANT \
  --key-source environment
# 可同时选择 --workspace-evidence BASELINE；密钥不通过 CLI 参数或文件传入。
```

主密钥从 `AI_AGENT_APPROVAL_ENCRYPTION_KEY` 注入；历史密钥从 `AI_AGENT_APPROVAL_ENCRYPTION_PREVIOUS_KEYS` 的逗号分隔值注入。主值最多 128 字节，历史值总共最多 4096 字节、32 项，每项最多 128 字节；空主值、空历史项、非法 base64 或非 32 字节密钥均拒绝。错误只归类为提供者不可用，不输出原始错误。

提供者直接比较内存中的环境值，变化时生成新的随机 32 字节不透明版本；不使用密钥 SHA 指纹或操作者版本字符串。扫描前后、CheckEvidence 及评估结束均复查。新进程/新提供者会创建新版本，所以跨 CLI 调用的旧密钥清单主动失效；一般使用不传 `--manifest` 的当前状态自动诊断。此方案检测本进程可见环境快照变化，不是秘密管理的全局撤销监视器，也无法证明两个观察点之间瞬时改变后恢复的状态。外部提供者必须提供真实轮换/撤销版本及取消、配额保证。

独立审批读取在专用只读 SQLite 事务内先检查总字节/记录配额（8 MiB、既有 MaxTaskExportDependencies），再按位置读取。核对 tenant/task/request/版本、动作名称和 resolution 状态；严格 JSON 保留 json.Number 的大整数精度，拒绝重复键/未知字段。Request.Parameters 是脱敏预览，不要求与执行参数相同。pending 必须没有 resolution；approved/rejected/consumed 必须存在并可解密，approved 为 true、rejected 为 false；expired 可以没有 resolution，有时必须为 true；consumed 的两种结果都只作为历史数据检查。没有恢复租约、转换审批状态或执行动作。

报告新增 `key_management` 脱敏摘要，schema 为 `task-restore-key-management-v1`，仅含审批数量、解密状态、来源绑定状态和固定原因码：

- 合法 v1/v2 审批：`decryption=verified`，`source_binding=unverified`，原因 `ciphertext_source_unverified`，类别仍不进入 verified_evidence。
- 空审批且密钥可用：可信读取证明没有独立审批，类别可以进入 verified_evidence，来源绑定为 not_applicable。
- 提供者不可用：`key_provider_unavailable`；密文认证失败或关系/语义错误：`payload_or_relationship_invalid`。v1/v2 认证失败都不猜测是缺少历史密钥还是损坏。
- 绑定或时效失败：摘要降为 unverified，原因 `stale_or_unbound_evidence`；评估期间状态变化时既有评估器清空 verified_evidence。

证据摘要纳入提供者随机版本；当前数据库指纹（含真实独立审批内容）与 workspace 版本共同绑定 StateRevision。现有 GCM 没有 AAD，且明文没有租户/任务/审批身份；首轮没有引入独立来源权威，不能把动作相同当作归属证明。第二轮已增加可选的签名证明验证；只有独立 trust pins、签名和完整清单均匹配时才能让含审批记录的 key_management 通过，详见来源绑定文档。真实源侧权威服务仍未接入。其他未接入类别继续 missing/unverified；整体 blocked、restore_ready=false、source_preserved=true，CLI 诊断结束仍退出 3。

本次回归覆盖真实 v1/v2 及主/历史轮换、各截断位置/损坏/未知版本、提供者非法值/撤销/并发读、关联和 resolution 契约、9007199254740993 保真、记录/字节配额、取消、扫描内轮换及评估后状态变化、过期/旧版本、workspace 组合与 CLI 显式选择/脱敏。只读测试比较数据库字节、源导出字节、workspace 文件与目录项。未使用生产密钥，未连接业务库、付费提供者或外部秘密管理服务。
