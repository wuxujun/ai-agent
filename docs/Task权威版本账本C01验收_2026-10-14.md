## 账本协议

Identity 包含随机 256 bit origin、显式 namespace SHA-256 和固定 prototype coverage。Resource scope 为 tenant/kind/resource ID；首版仅支持 task/session，标识为 1–128 个可打印 ASCII 字符。该协议原型不替代业务 Store 的全局 ID/权限规则，C02 必须保留那些约束。

每个资源记录 incarnation、非负递增资源 epoch、内容 SHA-256 与 tombstone；全账本拥有提交 epoch 和连续事件链。Mutation 明确 event ID、scope、operation、预期资源 epoch/incarnation 和内容摘要，拒绝未知类型与格式。以下是原型操作，不操作真实 Task 表：

| operation | 前提/结果 |
|---|---|
| create | scope 不存在或为 tombstone；匹配预期旧版本，新 incarnation 绑定 origin/event ID/全局提交 epoch |
| update | 当前 live 资源及预期版本匹配、内容确实变化；推进资源/全局 epoch |
| invalidate | 当前 live 资源及版本匹配，内容摘要保持；显式保守失效事件推进 epoch |
| tombstone | 当前 live 资源及版本匹配；保留 incarnation 与历史，清空当前内容摘要，不删除事件 |

所有提交在同一 SQLite 写事务内更新模型资源、事件和 head；先取得写锁，最后 CAS head。语句失败、取消或回滚不留下部分模型状态。原型没有执行业务回调，因此重复事件也无法重放生产副作用。

完全相同的 event ID/Mutation 返回原始 receipt，标记 Replayed，不重复推进版本；同 event ID 不同内容拒绝。原始 receipt 是该事件的历史版本，不能冒充当前 head：后续操作仍须匹配最新资源 epoch/incarnation。普通无值变化 update 拒绝；需要明确保守失效时使用 invalidate。

Snapshot 含完整提交历史和由它推导的当前资源。读取在一个只读事务内检查连续 epoch、唯一事件、前后 SHA-256、状态迁移和资源实体，物化资源必须逐条等于历史推导结果。JSON body 必须与固定类型编码逐字节一致，拒绝未知/重复键、尾随 JSON、缺字段与非规范整数；不输出正文，仅使用身份/事件标识和摘要。

最大 2048 个事件、1024 个资源、单 body 4 KiB、数据库文件 16 MiB；先检查 SQL 行数/字节与元数据/标签尺寸，再读取内容。SnapshotDigest 也严格校验有界历史与物化状态，不能只凭一个自报 head 摘要通过。达到容量或整数上限拒绝，不自动截断事件、归零或重建 identity。当前每次操作重放完整历史，适用于有界 fixture，不构成生产吞吐承诺。

每个 handle 使用可取消的操作 gate，避免自身 journal 与并发只读检查误冲突；数据库写锁和 CAS 保持事务语义。操作期限为 30 秒，SQLite busy_timeout 为 5 秒；读取/写入 context 贯穿事务。返回 Snapshot/Receipt 不与持久化数据共享可变切片。底层 SQLite 的取消回滚可能异步释放连接；回归在确认连接释放后核对最终保真，不把暂时 journal 存在当成恢复成功。

## 独立 floor 与回滚检测

Floor 从固定 source identity 开始，epoch=-1 表示尚未确认；没有隐式首次信任。Confirm 要求提供结构/历史已验证的 Snapshot，独立数据库保存 source epoch/head/SnapshotDigest：

- 较低 epoch 拒绝为 ErrRollback；相同 epoch 只允许完全相同快照。
- 较高 epoch 必须包含已确认旧 epoch 的同一个事件链锚点。旧库回滚后重新写入、更高计数但不同历史也拒绝，不能只比较数字大小。
- Matches 对 source 领先 floor 返回 ErrUnconfirmed，对落后返回 ErrRollback，对同代次分叉/不同 origin 返回 ErrConflict；不会顺手确认 source。
- Floor 只写自己的数据库；只读重开不能 Confirm。确认和拒绝不写源账本，旧源副本不覆盖原数据库。

**这里的独立是两个 fixture 数据库，不是实际权限/身份独立的控制面。** Confirm 接受测试代码选择的 Snapshot，没有认证远端调用者；同机拥有者仍能修改或复制文件。两个数据库同时回滚、新建 floor 的授权和实际不可回退存储不由 C01 证明，C04 还需可信 floor identity、独立认证/权限和耐久边界。不能把 Matches 成功传成恢复准入或真实 provenance。

## 验收结果

| 回归 | 实际结果与边界 |
|---|---|
| A→B→A | 内容恢复原值，epoch/head 继续推进，旧观察不复用 |
| tombstone/重建 | 历史和旧 incarnation 保留，重建获得新 incarnation，资源 epoch 不归零 |
| 重放/版本/租户 scope | 相同事件返回旧 receipt 不修改当前记录；不同内容、旧版本、其他 tenant 使用旧 incarnation 拒绝 |
| 语句失败与取消 | 已写入资源/事件后触发事务失败/取消，最终源快照不变；同事件 ID 可以在回滚后正常首次提交 |
| 并发 CAS/等待取消 | 两个匹配同旧版本的更新仅一个成功；handle 竞争时 deadline 传播 |
| 独立 floor | 领先未确认、旧源备份回滚、同 epoch/更高 epoch 分叉均拒绝；floor 只读重开保留确认 |
| 严格格式/预算/损坏 | 非法输入、无值变化、溢出、历史截断/重复 JSON/过大 body/标签/元数据/floor 与未知 schema 对象拒绝 |
| 私有文件与只读拒绝 | symlink、不私有权限、错 application_id、未知表和 journal 拒绝，拒绝前后主库字节/目录项数量不变 |
| 提交前独立进程退出 | 未提交事务不暴露新 epoch；若留 journal，只读入口拒绝并保留，未执行可写修复 |
| 提交后独立进程退出 | 重开读回完整已提交事件/资源；不代表物理断电保证 |
| 只读重开 | 查询级 query_only 拒绝 UPDATE，主数据库字节与目录项数量不变；返回切片修改不影响下一次读取 |
