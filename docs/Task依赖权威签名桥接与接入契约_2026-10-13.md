本轮新增 [权威签名桥接](../internal/store/task_restore_dependency_authority.go) 及 [签名/控制面回归](../internal/store/task_restore_dependency_authority_test.go)。它实现已有 session/execution 只读接口，由可信代码显式注入证据端和独立信任端；不提供默认网络客户端、环境公钥读取、HTTP/CLI 入口或在线配置加载。没有接入真实来源、调度控制面或身份服务，所有签名由本地测试随机 Ed25519 密钥生成。

## 两个提供者的职责

| 接口 | 输入/输出 | 必须由真实实现保证的事实 |
|---|---|---|
| `TaskRestoreDependencyAuthorityEvidenceReader` | 经过 v2 校验的 scope/预期摘要/预算及 kind，返回有界签名 envelope | 独立读取源历史基准、当前完整依赖目录及目标/执行隔离事实；证据不是对上传 JSON 的签名背书；只读访问、认证、取消和网络策略 |
| `TaskRestoreDependencyAuthorityTrustProvider` | 同一 scope/kind，返回当前 trust snapshot | 独立认证的控制面 pins、当前允许的 observation SHA-256、权限/撤销状态、签名 key_id/公钥、单调观察/信任代次与期限；不能从证据端或上传包直接提取 pins |

证据可经过不可信传输或存储；信任提供者必须来自独立可信配置。证据签名仅证明持有私钥的一方签过这些字节。完整性、当前状态和权限由独立信任端实际核对，桥接再核对 pin 与签名，不能通过一个本地“已验证”字段替代这些责任。

同一个可信服务可以实现两个客户端接口，但 pins 的来源与访问授权须独立于用户提供的包/证据，并能核对当前权威状态。请求中的 tenant/task/source/target 必须经过提供者的实际访问控制，不能原样回显后宣称认证完成。客户端必须限制输入/响应和总期限，遵守项目 outbound URL/private-network policy；本轮未实现任何具体传输。

## Envelope 与签名字节

envelope 固定为 `content` + `signature`。content 固定包含 schema=`task-restore-dependency-authority-v1`、kind=`session_dependencies` 或 `execution_leases`、key_id 和完整 observation。observation 分别使用 S01 的 `task-restore-session-observation-v1` 或 `task-restore-execution-observation-v1`。signature 是 JSON base64 编码的 64 字节 Ed25519 签名；envelope 不接受公钥、URL、路径、凭据或连接字符串字段。

`TaskRestoreDependencyAuthoritySigningBytes` 定义精确签名协议：

1. 严格解码 observation 到对应固定 Go 类型，拒绝未知/重复键、尾随 JSON 和超预算输入。
2. 按这些固定类型用 `encoding/json` 重新编码 observation，再编码固定 content；整数/string 与时间格式使用该类型的 Go JSON 契约。不能替换为其他任意 JSON canonicalizer。
3. 在 content 字节前加域分隔 `ai-agent/task-restore-dependency-authority/v1\n`（末尾为实际换行），对整串字节执行 Ed25519 签名。

这允许 JSON 空白差异，不允许改变 kind、key_id、观察内容或作用域。成员/边排序与合法关系仍按 S01 校验。签名函数只定义字节格式，不读取源、不持有私钥、不证明被签内容正确；真实签名服务必须独立生成观察。

observation 最大 8 MiB；envelope 最大 8 MiB + 16 KiB；单侧最多 1000 个任务、4000 条边。请求可设置更小预算，输出亦须满足它。提供者返回后复制字节/公钥，保留数据不与后续读取共享可变 slice；提供者也必须遵守不可并发修改返回值的契约。

## 独立信任 Snapshot

`TaskRestoreDependencyAuthorityTrustSnapshot` 包含：

- `KeyID`、32 字节 Ed25519 `PublicKey`、`Kind`、TaskID/TenantID/PayloadSHA256/SourceID/TargetID；所有绑定须与请求及 envelope 完全一致。
- `ObservationSHA256`：固定类型重新编码后 observation 的 SHA-256，须由独立控制面当前允许的观察取得，不能由上传 envelope 自证。
- `Revision`、`TrustRevision`：须与被签 scope 一致；Source snapshot 的 Revision 还须与历史 BaselineRevision 相符。
- `Generation`：64 位小写十六进制权威代次，不能以公钥 hash、内容 hash、UpdatedAt 或 lease TTL 代替；任一相关变更须推进，不复用旧值。
- `Status` 必须为 `active`；缺失、撤销或其他状态均拒绝。CreatedAt/ExpiresAt 必须当前有效，窗口不超过 15 分钟。

真实控制面须覆盖目录成员/边/高水位、Task/检查点原位更新、删除重建、源和目标租约/自然过期、派发隔离、权限与信任撤销。A→B→A 也须改变历史/当前代次；源完整性基准不能在状态变化后静默沿用。密钥轮换或权限变化而观察字节不变时，Generation 也须变化。

## 核验顺序与失效

桥接先验证请求，再读取当前独立 trust snapshot，读取有界 envelope，严格解析并核对所有 scope、key_id、当前 observation 摘要与修订，验证 Ed25519 签名，最后再次读取 trust snapshot。两次 snapshot 的所有字段与公钥必须相同且仍有效；任一中间变更、读取错误、撤销、到期或时钟回退均拒绝。信任 key_id/公钥来自独立提供者，envelope 不能替换它。

通过认证后，仍执行 S01 的会话完整性/目标匹配与终态/租约/隔离校验。有效签名不会放行成员遗漏、源基准版本错误、高水位不符、活动租约、缺少停止证明或非终态恢复。

输出是完成核验的 S01 observation：业务字段保持被签内容，scope 的 TrustRevision 替换为当前 key_id、公钥摘要、Generation、原 TrustRevision 的组合摘要；scope 时间收缩为签名观察和独立信任的交集，execution 还取执行隔离证明的最短到期时间。派生 scope 仅由桥接可信代码生成，S01 组合状态摘要会覆盖它；原 envelope 不被改写。旧 manifest 在代次、签名密钥或权限变化后失效，即使记录内容恢复原值。

内部设置 30 秒期限；真实客户端必须配合 context。Go 接口不能强制中止忽略 context 的实现。调用者取消原样传播，其他提供者错误/内部超时/无效证据统一返回脱敏的 `restore dependency authority unavailable`，不返回原始响应或凭证。桥接和完整评估的前后读取不构成与未来执行的原子事务，在线恢复仍需单独 fencing。

## 可信代码接入位置

真实客户端实现并审查后，使用 `NewTaskRestoreDependencyAuthorityReader(evidenceClient, trustClient)` 创建桥接，分别作为 `TaskRestoreDependencyReaders.Session` / `.Execution`，SourceID 使用独立配置的来源身份摘要，再传入已有 `TaskRestoreAdmissionOptions.DependencyReaders`。这些变量代表尚未实现的真实客户端，不是当前可直接运行的网络调用。

当前默认 CLI 不注入，原 manifest 仍不能自证。S02 本地 Store 不实现上述两个接口；不能直接作为证据端或 trust 端。专用离线沙箱的目录摘要 target_id 只适用于该沙箱，不能用它代表真实在线目标。
