# Task 联合快照导出

日期：2026-10-12。状态：当前工作区实现，未提交、未部署。承接 [Task/Trace 导出](稳定TaskTrace单任务导出_2026-10-12.md)，新增显式 joint 范围；未导入、删除或操作在线源数据。

## 请求及格式

```http
GET /api/retention/tasks/<task-id>/export?tenant_id=<configured-tenant>&scope=joint&byte_budget=1048576
X-API-Key: <administrator-credential>
```

现有管理员鉴权、明确租户、固定附件名、no-store、15 秒请求期限及响应字节预算保持不变。scope 省略或 task_trace 时仍为 task-trace-export-v1；scope=joint 返回 task-joint-export-v2。未知/重复 scope 返回 400，缺少联合读取契约的适配器返回 501；不能用多个公开读取方法拼成联合快照。适配器返回缺少 dependencies 的联合结果，或未经请求夹带 dependencies 的普通结果，均拒绝。

联合 payload 除 task/traces 外新增 dependencies，全部纳入原始 payload 字节的 SHA-256 和 payload_bytes。清单额外包含 approval_count / memory_count，包含零值。相同依赖集合按 ID 排序；原 Trace 保持物理顺序。独立审批变化即使不推进 Task.maintenance_version，也会改变联合哈希。

| 数据 | 导出范围 |
|---|---|
| dependencies.approvals | 所有 TaskID 匹配的 durable approval；保留原 Request、版本/状态、owner/lease、时间及加密 action/resolution payload |
| dependencies.task_owned_memories | 所有 TaskID 匹配的独立记忆，保留原 ID、租户/session、内容、时间和 embedding |
| dependencies.session | 关联的会话元数据，加上原 sequence 高水位；任务无 session 时为 null |

审批沿用 DurableApproval 持久化字段名（如 ID、TaskID、Version、ActionPayload），二进制 payload 为标准 JSON base64，保持密文，不解密、不读取或导出密钥。会话 next_sequence 是十进制字符串，因为普通 Session JSON 原本隐藏该字段。审批 Request.Parameters 的 JSON 数值用 UseNumber 读取，避免大整数被转换为 float64；其他既有整数表示不改，校验/解析客户端也须保留整数精度。

task-owned 以独立记录的 TaskID 为准；共享去重记忆若归属于其他任务，不会重新分配 owner 或纳入本包。原 Task 中嵌入的记忆继续保留，不推断它们都是本任务拥有的独立记录。其他任务、其他会话或其他来源的记忆不打包。

## 一致性与隔离

Memory 在现有 RLock 内完成 Task/Trace 和关联集合观察，再深复制审批（含嵌套参数）、记忆 embedding 和会话。SQL 在原导出事务内读取各集合，SQLite 维持同一 WAL 观察，PostgreSQL 为只读 Repeatable Read。联合读取不使用公开 GetApproval/ListMemories/GetSession 的独立连接。

校验审批/记忆的 TaskID、租户、唯一 ID，审批 Request 的关联 ID 和正版本；关联 session 必须存在且租户/ID 匹配，高水位不得小于 Task.SequenceNo 或为负。数据缺失、错租户、重复 ID 或异常关系返回脱敏 503，不遗漏出错记录后继续产出“不完整包”。记录数量超出上限返回 413。

单次存储观察不意味着业务对多个对象的分步写入已全部完成：活动任务、审批消费或异步记忆生成中途也可能被观察。联合哈希证明导出内容，不锁定将来的源状态，也不是 archive/purge CAS。

## Redis 的有界完整读取

旧审批/记忆索引未必完整，特别是 SaveMemory 的原始对象与索引写入分步发生。联合导出不把索引空集当作“无记录”，而在一次 EVALSHA_RO/EVAL_RO 中读取 Task、物理时间、session/counter，并对 approval:* / memory:* 原始键做完整有界扫描。原 Task、审批和记忆 JSON 原样传给 Go；Lua 不重编码正文或大整数。

当前限制为数据库最多 20000 个键、最多 400 次 SCAN（COUNT 256）、每类关联记录最多 1000 个。所扫描审批/记忆的原始总字节（包括其他租户、用于完整分类但不返回的记录）也计入读取预算；加 Task/Trace 时间/session 后超预算返回 413。原始命名空间有非法 JSON、错误类型、键名与记录 ID 不一致，或目标 Task 的跨租户关联时，拒绝导出。大数据库或混用命名空间环境可能因此拒绝，即使目标任务本身很小；生产规模优化需后续专用原子索引及只读完整性契约。

SCAN 的 COUNT 是工作量提示且可能返回重复记录，实现对原始键去重并核对 cursor 完整结束；命令语义见 [Redis SCAN 文档](https://redis.io/docs/latest/commands/scan/)。脚本只使用读命令，使用 [EVAL_RO](https://redis.io/docs/latest/commands/eval_ro/) 约束写入；不迁移、修复索引或获取租约。本批以独立 Redis 7.2.6 验收，不能据此宣布其他拓扑或生产规模通过。

## 预算、恢复与剩余范围

默认响应 1 MiB，允许 4096–8388608 字节，Trace 最多 10000 条；新增审批/独立记忆各最多 1000 条。复制/SQL 原始长度/Redis 扫描做预检查，最终完整 JSON 响应按实际编码字节检查；预算不是峰值 RSS 保证。超限无截断或部分附件。

source_preserved 始终 true，restore_ready 始终 false。已新增专用临时 SQLite 隔离导入/读回验证入口，见 [隔离恢复验证](Task隔离导入与恢复验证_2026-10-12.md)；执行租约、外部审计记录、workspace 文件、密钥、会话中其他任务和无关记忆明确排除。会话高水位只作观察保存，不意味着整个会话已完整归档。该接口不签发 retention eligible，不移除源记录，不执行审批，不调用模型，不上传或生成归档文件。

专用导入已显式校验清单/hash/租户/配额，并验证原时间、Trace 顺序、审批密文/状态、记忆和 session 关系；不走普通 SaveFullTask，不触发索引/付费模型或重新执行审批，不覆盖在线已有记录。[离线持久化隔离演练](Task持久化隔离恢复验收_2026-10-12.md) 已完成，支持关闭后只读重开。下一步为 PostgreSQL 在线验收、大事务异常退出/热日志/损坏和完整恢复准入条件，见 [续作交接](Task恢复验证续作交接_2026-10-12.md)。在线恢复执行和源记录移除继续是后续独立任务。
