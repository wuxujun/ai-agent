# 生产认证与审批权限说明

原始记录日期：2026-10-11，对应分析报告 F05。2026-10-13 按 G02 独立批次收尾可信个人身份、审批名单和禁止自批，提交标识以 Git 记录为准。未部署或连接真实身份服务；HA 继续延后。

## 已实现的行为

新增可配置的个人身份与本地审批授权：

- `api.auth.introspection.subject_claim`：指定可信 introspection 响应中的个人标识路径，例如 `data.sub`。一旦配置，该字段必须为有效字符串；缺失、空值、错误类型、控制字符、首尾空格或超过 256 字节均拒绝认证。
- `api.auth.bearer.require_subject`：要求 Bearer 凭证具有个人身份。JWT 使用已验证 token 的 `sub`；introspection 必须配置个人字段，不能降级为租户身份。对应环境变量为 `AI_AGENT_API_BEARER_REQUIRE_SUBJECT` 和 `AI_AGENT_API_INTROSPECTION_SUBJECT_CLAIM`。
- 个人审计 ID 为 `jwt-sub:<24 位小写十六进制>` 或 `introspection-sub:<24 位小写十六进制>`。摘要取 SHA256(`tenant_id + NUL + subject`) 的前 12 字节；不保存原始个人 ID。相同租户/个人在 token 刷新后保持同一个 ID，不同租户的同名个人分别计算。
- introspection 成功缓存同时保留租户和个人审计 ID；缓存仍以 token 摘要为键，过期时间不超过 token 的过期时间。改变个人字段配置会更换验证器；审批权限始终在请求时读取当前配置。

现有 issuer、audience、active、expiration、已知租户、URL/私网限制保持原校验。`X-API-Key` 仍只在本地校验，不转发给身份服务；管理员权限仍来自服务端租户配置，不来自上游 `roles/admin` 或客户端声明。

## 审批策略

策略位于 `api.tenants.<tenant>`，只限制 `POST /api/tasks/:id/approve` 和 `/reject`：

| approval_mode | 行为 |
|---|---|
| 省略或 `tenant` | 保持原租户级审批权限，兼容旧配置 |
| `deny` | 禁止该主体所属租户的审批决策，返回 403；可保留名单用于之后恢复 |
| `actors` | 仅允许 `approval_actor_ids` 中与已验证个人审计 ID 精确匹配的主体 |

`actors` 必须有非空、格式正确且不重复的个人 ID 名单。配置名单却省略模式或使用 `tenant` 会被拒绝，避免名单被悄悄忽略。租户级 `tenant:*`、`api-key:*` 和原始个人 ID 不能作为名单成员。

权限校验发生在审批解析、CAS 写入、恢复和 Redis 信号之前。上游角色声明、`X-Actor-ID` 和请求体 `actor_id` 均不能授予审批权限。读取租户内审批记录/统计的原有权限保持不变；禁用审批不会禁止阅读。

本地可信管理员仍保留现有跨租户访问能力；新策略按发起主体所属租户评估，没有新增管理员权限绕过。生产示例不授予租户管理员身份，也不配置静态管理密钥。已有部署若明确保留根管理密钥，其原有管理权限也会保留。

## 任务创建者与禁止自批（已实现）

任务创建接口（包括 Console Cookie 登录后的相同 API 路由）从已验证 `Principal.ActorID` 写入 `creator_actor_id`；请求体中的同名字段、`actor_id` 或 `X-Actor-ID` 不参与身份赋值。创建响应、完整任务及无 Trace 详情可返回该字段；紧凑列表摘要保持原形状。不保存原始 subject 或 token。

新增租户配置 `approval_disallow_self`，默认 `false` 保持兼容。设为 `true` 时：

- 创建任务要求已验证个人身份，API Key/租户级身份不能创建，返回 403。
- 批准和拒绝均要求个人创建者与个人审批者，且 ID 不同；换 token 不改变创建者身份判定。
- 按任务所属租户的策略校验，包括跨租户管理员；原有审批名单权限也必须通过。
- 历史任务创建者为空、非个人或格式无效时拒绝决策；不从审批人、旧 Trace、会话或请求字段推断创建者。如需停止任务，仍使用原有取消接口。
- 校验发生在决策请求解析、本地 channel、持久化 CAS、恢复和 Redis 信号之前。读取审批记录的权限保持原行为。

字段首次写入后不可通过正常保存改写：Memory、SQLite、PostgreSQL 更新保留已有值（包括空值）；Redis Lua 在任何写入或索引修改前拒绝不同值，返回 `ErrTaskCreatorImmutable`，保留任务及读模型。SQLite/PostgreSQL 启动迁移添加 `creator_actor_id TEXT NOT NULL DEFAULT ''`，历史值仍为空。Redis JSON 和 metadata 首次创建包含字段；恢复、状态迁移沿用原记录。部署时所有写入实例须使用支持该字段的新版本，旧 Redis 写入器不受新 Lua 约束；本批未进行混合版本部署验收。

策略支持有效重载；错误布尔值或其他非法候选拒绝重载并保留快照/revision。严格生产示例已设置 `approval_disallow_self: true`，审批仍默认 `deny`，不会自动切换正在运行的配置。

限制：不同个人 ID 代表身份服务中的不同主体，不能证明背后是不同自然人；多账号、跨身份来源映射及更换 issuer/subject 语义须由可信身份契约和名单治理保证。本批没有提供历史创建者补录或管理员绕过接口。

## 严格配置示例与启用

参考 [独立生产配置示例](../deploy/security/config.production.example.yaml)。它要求已知租户、独立 workspace、个人身份及 issuer/audience/expiration 校验，关闭身份成功缓存，使用 Team/Wiki/Brain 显式范围，审批默认 `deny`。

该文件是供复制、审核的完整配置入口，不会自动叠加到 `config.yaml`。其中 `.invalid` 地址、`data.tenant_id` 和 `data.sub` 都是占位，实际身份服务的个人字段尚未确认；不得把示例字段当成已验证契约。

启用前：

1. 确认真实服务返回稳定、唯一的个人 ID，以及正确租户、active、issuer、audience 和数字秒级 exp。个人 ID 不能使用租户 ID、显示名称或一次性 session/token ID。
2. 复制示例并替换真实端点、字段与租户范围，创建位于应用目录内的租户 workspace；保持默认拒绝审批。
3. 核对环境覆盖，尤其旧 `AI_AGENT_API_KEY`、认证模式/字段/租户约束设置。示例文件中的空密钥不能清除环境注入的旧管理密钥。
4. 通过环境或秘密管理提供 LLM 凭据、审批加密及 Console 会话密钥；不要写入配置。启用配置使用 `AI_AGENT_CONFIG_FILE` 指定经审核文件。
5. 从可信身份契约取得授权人员 subject，计算其个人审计 ID，经管理员审核后设置 `approval_mode: actors` 和名单；再验证已授权、未授权与过期用户的实际请求。

名单计算示例（只演示算法，输出占位个人的 ID 不代表授予权限）：

```python
import hashlib
tenant = "project-a"
subject = "replace-with-verified-stable-person-id"
actor_id = "introspection-sub:" + hashlib.sha256((tenant + "\0" + subject).encode()).hexdigest()[:24]
print(actor_id)
```

JWT 对应前缀为 `jwt-sub:`。不要将未验证请求中的 actor_id 直接复制为授权依据。

## 重载与验证

个人字段、Bearer subject 要求、租户审批模式及名单支持配置重载。有效候选应用后，下一次请求按新策略校验；非法模式、空 actors 名单或重复/错误 ID 会拒绝重载，并保留原快照及 revision。审批名单深复制，避免旧快照被新快照修改。

新增回归覆盖：个人身份/刷新/缓存/租户区分、无效个人字段、JWT 缺失个人主体、客户端与上游角色伪造、approve/reject 提前拒绝、合法名单与缓存身份下的撤权、读写权限分离、配置及环境绑定、有效/拒绝重载与旧快照保留。

复跑命令：

```bash

go test -race ./internal/api ./internal/config ./internal/store ./internal/orchestrator ./cmd/server
go test ./...
go vet ./...
```
