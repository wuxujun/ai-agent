# 可信终态时间与维护版本

更新日期：2026-10-12。实现位于当前工作区，未提交、未部署；不执行归档、导入、清理或运行数据回填。

## 持久化契约

内置 Memory、SQLite、PostgreSQL、Redis 在 Task 上维护三个只读字段，忽略保存调用者提供的对应值。

| 字段 | 含义 |
|---|---|
| `terminal_since` | 当前终态持续起点；未处于终态或历史起点未知时为空 |
| `last_maintenance_at` | 最近成功保存、状态变更或 SQL Trace 替换的存储时间，UTC |
| `maintenance_version` | 每个任务记录的维护序号；JSON 十进制字符串，初次成功写入为 `"1"`，历史未知为 0/缺省 |

成功的 CreateTask、SaveFullTask、SQL SaveTask、SQL ReplaceTraces 和匹配的 TryTransitionTaskStatus 每次递增一次；即使保存内容未变，也推进维护时间和版本。版本范围 1–9007199254740991，达到上限或发现负值时拒绝后续变更，避免跨 Go、Redis Lua 和 JSON 的整数精度差异。保存成功后同步调用者的生命周期字段，读取/克隆的时间指针不会共享可变存储。

首次创建为 completed/partial/failed，或从其他状态进入其中某个状态时，由存储生成 terminal_since。同一终态的重复保存保留原起点；恢复为 running/paused 等非终态时清空；终态之间改换状态也建立新的保守起点。重审/重新保存更新 last_maintenance_at，因此保留窗口使用它，而非仅使用首次完成时间。历史终态记录没有起点时，首次维护也不会把“现在”伪装成历史完成时间；只有之后实际发生状态转换才建立新起点。

版本和维护时间在同一次原子变更中提交。匹配失败、重复创建、错误租约、取消、版本耗尽，以及 SQL Trace 中途失败不推进版本。事务失败也不把新生命周期回写给调用者。服务时钟回退时，维护时间不小于此前可信维护时间；未来时间或起点晚于维护时间会使年龄评估保持未知。

## 后端与迁移

- Memory 在原有写锁内生成并提交字段，读取评估元数据时仅复制两个时间值，不复制完整 Trace。
- SQLite/PostgreSQL 增加 nullable terminal_since、last_maintenance_at 与 NOT NULL DEFAULT 0 的 maintenance_version，既有记录不回填。状态、生命周期与 Trace 写入保持同一事务。SQL 元数据保存保留原 Trace；独立 Trace 替换也推进维护版本。
- PostgreSQL 使用按任务 ID 的事务级 advisory lock，再读取已有行的 FOR UPDATE，串行化同 ID 的首次 upsert 与已有任务维护；事务结束释放锁。其锁语义见 [PostgreSQL 官方说明](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)。在线数据库验收为 **NOT_RUN**。
- Redis 在 Lua 内验证已有版本及租约后更新完整 Task、metadata 和 summary。版本拒绝发生于索引移除之前；回归比较所有应用 key 的 DUMP，证明拒绝不改变任务或索引。顶层 JSON 替换保留嵌套数组、转义文本和大整数，不对完整 Task 进行 cjson 重编码。读模型修复保留已有生命周期，不自行生成时间/版本。

SQL 迁移仍由既有存储初始化执行，升级时须评估表锁及备份。本轮只迁移测试数据库，没有重新初始化在线服务。可信保证要求所有写入者使用新实现；旧进程混合写入、直接 SQL/Redis 修改及其他自定义 Store 不在保证内。

## 只读评估变化

`GET /api/retention/tasks` 现在返回上述有界生命周期元数据，策略版本为 `diagnostic-v2`；旧 v1 游标不再匹配当前策略。

版本大于 0、时间完整且顺序正常时，terminal_age_source 为 `store_lifecycle`。提供 hot_days 后，最近维护尚未满指定天数会产生 blocked / retention_window_not_elapsed。历史缺失、未来维护时间和异常时间顺序保留 unknown_terminal_age，created_at/updated_at/Trace recorded_at 均不能替代终态时间。

期限满足也仍为 unknown：hold 策略、完整大小、联合快照及依赖证据尚未齐备。execution_ready 始终 false，不产生 eligible；管理员/明确租户、字节预算和只读 EVAL_RO 规则保持原契约。

maintenance_version **不是内容哈希、乐观写锁或联合删除 CAS**。它不覆盖审批、租约、审计、会话及所有外部依赖的独立变更，也不阻止旧快照覆盖内容；删除后重新创建同 ID 会重置版本。稳定导出仍须建立完整单任务快照、内容哈希、大小预算及依赖一致性校验。
