## 模拟契约与检查

默认仍运行本地 Postman simulation。本仓库 `candidate-model` mock 增加仅测试使用的 `POST /_scenario/<name>`，场景切换后对下一次实际 planner 请求生效；不是应用 API，不应部署至真实环境。mock 源自仓库 planner 契约，未查询或复用供应商拥有的远端 mock，也未发布远端资源。不声称合成错误覆盖供应商契约。

| 场景 | 注入行为 | 验证目标 |
|---|---|---|
| timeout | 20 秒不发响应头，超过候选配置的 3 秒超时 | 请求被及时终止，任务 failed |
| http-json | HTTP 500 + JSON 合成敏感标记 | 错误状态保存，上游正文不泄露 |
| http-html | HTTP 500 + HTML 合成敏感标记 | 代理错误正文不泄露 |
| malformed-stream | HTTP 200 + 非法 JSON SSE 帧及 DONE | 无有效决策时失败，不伪造完成 |
| success | 恢复固定合法流式停止决策 | 后续新任务正常 completed |

每个故障均要求六秒内进入 failed，依赖请求次数为 1–2（测试任务调用预算为 2），终态 SSE 可读且应用 `/ping` 正常。再执行一个正常任务，最后重启同一候选并读回四条失败记录及成功任务/答案。没有对原失败任务进行重试。正常恢复只证明该候选进程在本地合成依赖恢复后可执行新任务，不代表自动业务重试或供应商可用性。

任务 JSON、终态 SSE 及应用全部 `.log` 检查合成上游标记未出现；Postman 日志包含故意注入的模拟正文，不提交 Git。此检查不能证明所有形式的敏感数据都已脱敏。

## 验收结果

首轮 42 项通过；超时约 3.092 秒，其余故障约 0.111–0.113 秒，每种只收到一次模型请求。正常任务成功，累计五次模型请求、未知依赖为 0。随后将失败耗时断言从整体执行窗口收紧到六秒，并将最终子进程退出码也纳入成功条件，执行完整复跑，最终证据见下方续录。

超时请求取消后，Postman 不一定产生完整响应 request 事件；mock 模型计数、任务终态和耗时共同作为证据。500 JSON/HTML、损坏 SSE 和恢复成功请求在 Postman 日志中分别有 500/500/200/200 的响应事件，未把缺失的超时响应日志当作成功响应。

隔离仍使用新 SQLite、随机测试密钥、空 `.env`、最小环境及 macOS 禁止非 loopback 出站策略。未操作 8088 的任务、配置或进程；真实身份和审批 CAS 仍按用户要求暂缓。全仓 Go 测试 59 个有测试包通过（含缓存），Python 编译、Node 语法与 diff 检查通过。本轮仅修改验收夹具、mock 和文档，无新增生产共享状态，无新增并发实现。
