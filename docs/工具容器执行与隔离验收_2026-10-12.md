## 执行行为

`tool.sandbox.mode: docker` 启用后，通过显式本地 Unix socket 调用 Docker Engine API v1.45，每条命令创建独立容器。不使用任务提供的 Docker CLI、远程地址、主机 Docker context 或代理环境；不自动拉取镜像，不在失败时回退到主机执行。命令白名单、工作区政策、高风险审批、超时和输出限额继续生效，任务不能自行指定挂载、镜像或容器参数。

服务启动先检查配置、daemon 能力及镜像；执行时再次检查。要求 Linux daemon、runc、内置 seccomp，以及可实施的 CPU、内存、swap 和 PID 限制；缺少能力、有效设置漂移或 create 警告均拒绝执行。镜像只接受已在本机存在的完整 `sha256:` image ID，必须具有 `ai-agent.execution-image.version=1` 标签且不能声明额外 volumes。标签是运维审核契约，不能替代镜像来源和内容审核。

容器使用数字非 root UID:GID，丢弃全部 capabilities，开启 no-new-privileges、init、默认 seccomp、只读根文件系统、独立 IPC/cgroup namespace、禁用网络和日志落盘。唯一主机 bind mount 为已授权工作区 `/workspace`，非递归、rprivate；`/tmp` 为有容量上限的 tmpfs，允许工具执行临时编译产物。工作区不能含主机 socket、FIFO 或设备，扫描不跟随工作区内符号链接；符号链接在容器命名空间中解析。

服务环境只继承管理员审核的额外名单；镜像内未授权变量显式清空。PATH、HOME、临时目录、Git 全局配置及 Go 缓存/工具链路径由后端管理，主机 Go 缓存路径不会映射进容器。stdout/stderr 分开读取，每路保留最多 1 MiB，超过后继续排空，Docker 日志驱动为 `none`。

取消、超时、启动失败和正常退出均使用独立清理上下文，验证随机 ownership label 后只强制移除本次容器，并复查 404；不操作其他容器/volume。create 响应丢失时按随机名称检查所有权并清理。清理最多 10 秒，无法确认则返回 `ErrCleanup` 并输出关联 task/trace 的脱敏错误，不能转换成 rg 无匹配或普通 tests-failed 结果。控制器失联时，镜像中的 coreutils timeout 自行终止命令，期限为剩余命令预算向上取整（最长 3601 秒）；它不会自动删除容器元数据。

## 配置与镜像

先构建并审核专用镜像，再配置不可变 image ID：

```bash
docker build -t ai-agent-execution:reviewed deploy/security/execution-image
docker image inspect --format '{{.Id}}' ai-agent-execution:reviewed
```

Dockerfile 默认使用本次核验的 `golang:1.26.8-bookworm` repository digest，并安装 coreutils、Git、编译器、Node、Python 和 ripgrep；构建 context 只包含 Dockerfile。基础 digest 固定，APT 软件包版本仍随仓库更新，因此每次重建均须重新审核、记录 image ID。自定义镜像须保留 `/usr/bin/timeout` 及执行契约。

在主 `config.yaml` 的现有 `tool` 段配置，例如：

```yaml
tool:
  timeout_seconds: 120
  environment_allowlist: []
  sandbox:
    mode: docker
    socket_path: /var/run/docker.sock
    image: "sha256:<image inspect 返回的完整 64 位小写十六进制 ID>"
    user: "65532:65532"
    cpus: 1
    memory_mib: 256
    pids_limit: 64
    tmpfs_mib: 64
```

Docker Desktop 可使用其实际 Unix socket 路径。本次为 `/Users/xujunwu/.docker/run/docker.sock`；不要复制成其他机器的固定值。运行服务账户须能访问该 socket，工作区权限须允许配置的容器 UID 写入；只调整专用任务目录，不能放宽整个项目或主机目录的权限。不要把服务 `.env`、密钥、数据库或 socket 放入任务工作区。

sandbox 所有字段为重启必需项，热重载拒绝变化并保留旧快照；环境名单和 timeout 仍按原配置规则更新。Docker timeout 必须为 1–3600 秒。默认资源适合小命令，首次 Go 编译可能需要更大的临时空间、内存及 PID 预算；本次 Go 验收使用 CPU=2、memory=1024 MiB、tmpfs=512 MiB、PID=128。无网络意味着不能临时下载 Go modules/npm/pip 依赖，需预先放入审核镜像或任务工作区。

## 实际验收

本机 Docker Desktop 4.89.0 / Engine 29.7.2、Linux arm64、cgroup v2；应用测试使用 Go 1.26.8 darwin/arm64。镜像 ID：`sha256:a84d1362c1de4d985823d92c0808eebf96134a6242db308f0d9a2bb54942c3af`。

真实 `TestDockerLive` 六个场景通过：

- UID=65532、NoNewPrivs=1、CapEff=0、Seccomp=2；只读根目录，工作区可写。
- 工作区外 host sentinel 的符号链接不可读，Docker socket不可见，服务秘密环境不可见，外网连接失败。
- cgroup CPU/memory/PID 值匹配；实际创建子进程达到 PID 上限，分配超限内存被 OOM 终止。
- Go 测试、Node、Python 可执行，rg 的退出码保留。
- 启动独立 session 的子进程后取消，容器清理后子进程不能再写工作区。
- 不使用控制器取消，容器内 watchdog 仍以 code 137 终止超时命令。

真实 `TestRunCommandDockerLive` 通过：双路各 2 MiB 输出被排空并截断、Go 断言失败保留 tests-failed 观察结果、rg 无匹配返回正常空结果。故障夹具覆盖 create 响应丢失、有效策略漂移、取消、清理失败、外国所有权、错误脱敏、缺少 seccomp/镜像契约和无主机回退。

## 边界与后续

本次验收证明所列场景在本机 Docker 环境满足断言，没有完成目标生产 Linux/x86 环境验收或完整逃逸审计。容器共享 daemon 的内核；Docker socket 是服务的高权限控制面，须由可信运维维护，不能暴露给任务。主机对工作区/daemon 的并发恶意修改不在本次隔离保证内；任务工作区写入没有磁盘配额，仍需存储预算和保留策略。

宿主进程强制崩溃可能留下已停止容器元数据；create 响应丢失的极端延迟也不能保证容器始终在有限清理窗口内可见。恢复流程应按所有权核对专用容器，不能用全局 prune。watchdog 限制命令存活时间，不能替代运维恢复与残留对账。默认 local 模式仍以服务账户执行；接收不可信代码前必须显式启用并在目标环境验收 Docker 模式。

F05 真实身份字段契约及在线验收仍为 NOT_RUN，HA/DAG 灰度继续按用户要求延后。下一步独立工作可推进 F06 的 SSE 断线对账/重放契约。

资源与挂载语义参考 Docker 官方 [资源限制](https://docs.docker.com/engine/containers/resource_constraints/)、[bind mounts](https://docs.docker.com/engine/storage/bind-mounts/) 和 [seccomp](https://docs.docker.com/engine/security/seccomp/)。
