## 首批范围

先以专用 SQLite fixture 验证控制面账本和原子协议，不将 fixture 声称为真实环境。Memory 可以验证接口和锁行为，缺少跨进程持久化，不能作为真实权威账本。PostgreSQL 后续需专用数据库；Redis 后续需证明脚本、持久化、回滚检测及完整目录覆盖，均不隐式加入首批。

读取仍采用 S01 session observation v2 / execution observation v1，S03a envelope v1。首批 session 覆盖完整同会话成员及可信目录中的无环边；跨会话/未知依赖语义拒绝。执行仅证明终态记录的诊断条件，不授权非终态恢复或终态重跑。

运行模式、检索和工具支持必须有明确 coverage 契约：完整会话成员是保守范围，不能把 Task.SequenceNo 自动解释为依赖边。`recentSessionMemories` 会读取之前完成任务的内容；其他长期记忆、外部 RAG、工具副作用仍属于独立 memory_index / approvals_and_effects 等检查器，没有覆盖时整体验证不能完整。不能因控制面接入而跳过其他强制类别。

## 耐久身份与变更账本

建议在真实 Store 数据库的事务域内保存权威元数据，而不是依赖日志尾随或独立旁路计数器。以下名称为设计实体，源码/数据库尚未创建。

| 实体 | 最小字段与不变量 |
|---|---|
| authority origin | 不可变随机 incarnation、namespace 身份、schema/coverage 版本；首次可信登记后不能通过换路径/重建库复用原身份 |
| mutation head | 每个资源 scope 的非负有界 int64 epoch，提交时严格增加；达到上限拒绝写入，不能溢出/归零 |
| mutation events | 提交事件 ID、origin/资源/epoch、事件类型和脱敏内容摘要；成功写入与事件原子提交，失败/回滚不发布事件 |
| resource incarnations | Task/Session ID 的创建 incarnation 与 tombstone；删除/重建仍保留历史代次，不能用新行代替同一历史实体 |
| dependency catalog | 明确语义版本、完整成员目录与显式边，tenant/session 隔离；无边必须是已覆盖运行模式的权威事实 |
| export baseline | v2 payload hash、源 origin、完整会话与 Task/Trace/边摘要、导出时 session-data epoch、覆盖版本；由源侧同快照产生 |
| dispatch gate | tenant/任务闭包作用域、gate incarnation/epoch、phase、操作者受信身份摘要、创建/撤销版本；没有隐式自动解除 |
| execution attempts | 唯一 attempt、实例/进程 incarnation、task/tenant、获得 gate/lease epoch、开始/退出/最后 flush 与清理回执 |
| trust floor/outbox | 已提交 epoch 的发布记录；独立信任端持久化最高已确认 origin/epoch、权限与撤销版本，不能接受回滚后的旧值 |

authority origin 和最高代次不是公钥 hash、数据库文件 hash、UpdatedAt 或 MaintenanceVersion。代次序列允许事务预留产生空洞，但已提交值不能回退或复用。跨资源 Revision 用固定排序的 `{origin, coverage, resource, epoch}` 向量编码，Generation 包含当前权威/权限/撤销代次并编码成 64 位小写十六进制摘要；摘要输入是不可复用的版本身份，而不是记录内容。

session-data epoch 覆盖成员、Task、物理 Trace、Session/高水位和依赖边；lease/gate/权限有各自 epoch，完整观察向量包含它们。这样租约/隔离元数据变化不会伪装成 Task/Trace 内容变化，任何相关变化仍使旧观察绑定失效。任何合法的 Task/Trace/会话数据变化都使原 export baseline 失效，必须从当前源重新联合导出并建立新完整基准；不能把旧包的基准版本更新成当前值。

历史包没有同期完整基准时继续 unverified。启用账本后的第一次扫描只能建立当前基准，不能补造以前的依赖完整性。迁移/修复/覆盖版本变化要求重新登记并使旧 pins 失效。

## 原子写入与回滚检测

每个写事务的顺序为：锁定必要资源 head/gate，检查 tenant/incarnation 和所需版本，完成业务写入，推进相关 epoch 并写事件/outbox，一起提交。状态 CAS 未匹配、失败租约获取、无记录的 release 或其他无值变化操作不能假装成功事件；需要保守失效时必须作为独立权威事件明确记录。

必需覆盖清单：Task 创建、完整保存、Trace 原位更新/重排/截断与追加、状态/生命周期维护、Session 创建/修改/序号分配、依赖目录更新、lease 获取/续约/释放、单记录删除、迁移和受控管理写入。合法序号空洞保留；Task 改变归属时必须同时覆盖原/新 scope，是否允许迁移仍由现有权限与业务契约决定。未进入目录的旧写者、直接 SQL、未知 Store 适配器或后台路径都阻止 coverage 通过。

自然租约到期也改变观察语义：写账本的独立维护流程把过期事件推进 epoch；在过期尚未物化、时钟偏差未证明或维护失败期间不签执行证据。只读观察不顺手清除或补写过期记录。

业务写入与事件同事务提交；独立信任发布可使用 outbox。发布失败不能报告业务事务已回滚，也不能继续提供旧证据。签名/信任读取必须重新核对当前业务 head；当前 head 未获独立确认时该作用域无权威证据。重试以已提交 event ID 去重，不重新执行业务操作。

独立信任端持久化最高 origin/epoch，拒绝旧库备份恢复、账本截断、epoch 倒退及 incarnation 重用。两个数据库一起回滚不能由本机内容 hash 发现；没有独立不可回退的信任 floor 时，回滚检测保持 unverified。仓库内实现也必须有独立权限/耐久存储边界，不能把业务进程自签和同库 pins 叫作独立权威。

## 执行隔离状态机

| phase | 操作/观察 | 可以签 stopped 证明吗 |
|---|---|---|
| open | 正常派发；无隔离声明 | 否 |
| blocked | 控制流程已持久化禁派发 gate；未收齐既有 attempt | 否 |
| draining | 取消旧 attempt，等待执行、最后持久化与工具清理回执 | 否 |
| sealed | 闭包、实例清单、attempt 全集均有权威完整性，退出/清理与无活动 lease 已核对，信任端已确认当前代次 | 可生成短期诊断证明；仍不执行恢复 |
| revoked | 新事件、权限撤销、工具/实例未知、证据到期或兼容覆盖变化 | 否；禁派发 gate 继续保持 |

gate 是未来独立控制流程的写操作，assess 和权威只读提供者不会创建它。解除 gate 也须另行受控操作并推进代次；证据到期/进程重启/控制面不可达不会自动恢复派发。取消请求、消息总线成功发布或 Handler map 删除，只使 phase 进入/保持 draining，不生成 sealed 回执。

租约获取必须在同一持久化事务内检查禁派发 gate；核心 Engine/Coordinator 同时检查并注册 attempt，防止省略 Handler 或 lease context 的调用绕过。所有启动扫描、审批恢复、关闭回滚及其他直接执行都必须覆盖。现有唯一 owner 约束保留，新增 gate/attempt 代次不能用复用 owner 字符串代替。

attempt 从注册保留到 Engine 调用退出、最后持久化完成、续约停止及工具清理完成。退出记录可以保留失败/未完成原因；“没有记录”不等于“没有旧执行器”。应用崩溃或 heartbeat 丢失进入 unknown，必须由可信实例/宿主机隔离与 ownership 对账确认；租约过期无法补发退出回执。不能使用全局 prune、批量删除或去清理其他任务的进程/容器。

闭包新增成员、旧执行器重注册、重新派发或下游清理回执撤销立即失效 sealed。当前只接受 `dispatch-disabled-executors-stopped-v1`，不凭空提供下游 fencing-only 证明。外部副作用是否已经发生仍需单独对账；stopped 只证明停止，不授权副作用重放。

## 观察、签名与信任角色

观察器使用只读身份，在同一数据库快照读取完整 baseline/current/target 与 epoch 向量；跨实例/工具控制面的回执按前后版本复查。签名端独立取得这些观察，核对 coverage 与信任 floor，才调用已有 signing-bytes 协议；不会为上传 JSON 原样签名。

签名服务权限不能管理 trust pins 或主动解除 gate。独立 trust 服务核对当前完整观察摘要、tenant/task 权限、origin、代次与撤销，再向 S03a 返回 active pin。私钥来自秘密管理；不写入导出、配置文件、文档、日志或 Git。两个角色若部署在同一仓库代码中，仍须通过运行身份、写权限与独立耐久 floor 分离。

目标成员/Task/Trace/序号与租约必须由目标自己的当前观察取得。当前专用 SQLite 单任务恢复沙箱没有其他完整成员或真实目标 identity，不能升级成线上目标。源、目标、调度和信任版本均进入 S01 组合绑定；前后观察没有替代未来在线执行的原子 fencing。

不新增默认认证或自动加载 `.env`/运行配置。未来启用需启动验证 coverage、后端支持与身份；失败关闭该作用域的权威证据。依赖初始化/身份/schema 的变更按重启要求处理，不在热重载中伪装为已就绪。API/配置若后续新增，应独立定义并同步 Sample；本设计尚无新 HTTP 路由或配置项。
