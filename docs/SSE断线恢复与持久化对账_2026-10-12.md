## GET 观察流契约

`GET /api/tasks/:id/stream` 保留原有 `message` / `data:` JSON，响应增加 `X-SSE-Recovery: snapshot`。每次连接先订阅本地 EventBus，再读取持久化 Task，立即发送带 `snapshot` 字段的事件并 flush，避免初次读取与订阅之间漏掉状态变化：

```json
{
  "task_id": "example",
  "status": "awaiting_approval",
  "snapshot": {
    "trace_count": 12,
    "step_count": 4,
    "updated_at": "2026-10-12T12:00:00Z"
  },
  "token_usage": { "prompt_tokens": 100, "completion_tokens": 50, "total_tokens": 150 }
}
```

每约 15 秒读取 Store 并发送当前快照，包含非终态状态；本节点收到终态提示时也立即读 Store。只有持久化状态为 completed/partial/failed 才发送确认答案/错误并关闭连接。初次 Store 读取失败时，缺失任务返回 404，其他故障返回脱敏 503；认证/租户检查阶段的错误仍由原有中间件处理。最近终态缓存和 live 终态不能覆盖 Store：旧缓存不会让仍在运行的任务错误关闭，已建立连接后存储不可读时只发送 `: reconciliation-unavailable` 注释，不暴露后端错误，并于下一次轮询重试。

在连接可写、Store 可用条件下，丢消息/跨处理器状态恢复等待通常不超过一个 15 秒轮询周期加读取时间；单次存储读取上下文最多 3 秒。客户端写入阻塞、浏览器后台节流、存储持续失败或网络故障不属于此延迟保证。GET 断线只终止观察并取消读取/释放订阅，不取消任务执行。POST run/run-all 的执行流保持现有语义，特别是 run-all?stream=true 断开仍取消其执行上下文。

该端点不发送 `id:`，也不使用 `Last-Event-ID` 进行精确续传。携带旧 ID 的重连仍要通过认证和 Task 租户检查，并接收当前快照。token、step、approval 是本节点即时提示，可能遗漏、重复或滞后；客户端以快照及持久化读取为准。`snapshot.trace_count/step_count/updated_at` 是观察值，不能当作事件游标或内容版本；Trace 重排/截断时，既有 sequence/event_id 也可能对应不同内容。原生 EventSource 的重连和 Last-Event-ID 行为参考 [WHATWG SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header)。

## Console 对账

Console 在 message、open、error 或页面恢复可见时，合并触发约 300 ms 后的 Task summary、当前 Trace 页和审批记录查询。正在加载时延后执行该刷新，保留可见页每 8 秒轮询。页面切换、退出或终态时关闭 EventSource，并清理刷新计时器和 visibility listener；旧连接回调不能更新新页面。

Console 不从 token 拼接恢复最终答案。其他客户端应在首次连接、重连及终态提示后读取同样的持久化 API：

- `GET /api/tasks/:id?view=summary`
- `GET /api/tasks/:id/trace?limit=100`，按 `next_cursor` / `has_more` 分页并刷新当前页对账。
- `GET /api/tasks/:id/approvals`，恢复持久化审批 ID。

响应样例与 POST/GET 区别见 [Task API](task-api.md)，可执行请求见 [HTTP 样例](../Sample/agent-api.http)。

## 验证结果

新增 `sse_recovery_test.go` 覆盖：

- 两个独立 HTTP 处理器、两个独立 EventBus 和两个 SQLite Store 连接共用数据库，真实断开 A 后在 B 携带旧 Last-Event-ID 重连，恢复断线期间的 awaiting_approval 状态与 Trace，再仅靠 Store 轮询恢复 paused 和 partial/最终答案。
- 重连的错误凭证和其他租户无法读取任务。
- 旧 sticky 终态不覆盖正在运行的 Store 状态；短暂 Store 失败时拒绝未确认终态且不暴露上游错误，恢复后发送确认结果。
- 阻塞写入并填满 32 条订阅缓冲，终态事件被丢弃后仍由 Store 对账闭合，订阅释放。
- 初次 GetTask 中发生终态更新/发布，禁用周期兜底后仍立即恢复，验证订阅在读取之前建立。
- 初次 Store 故障与任务缺失分别返回脱敏 503/404，并释放已建立的订阅。

这些测试使用真实 HTTP/SQLite 和故障夹具，周期轮询缩短为 20 ms 以保持回归快速；生产仍为 15 秒。跨处理器共存于本地测试进程，不是正式双节点/负载均衡器 HA 部署验收，也没有声称完整 token 重放。

浏览器现有 Chromium、Firefox、WebKit 各 18 场景，共 **54 项通过**。新增两个场景以夹具驱动 open/error 生命周期，验证无需等 8 秒即可读取真实 Task/Trace/approvals 并关闭终态连接；保留真实独立 SSE 请求被中断后的轮询验证。不是代理自动重连、真实移动设备或所有浏览器发行版本验收。

全仓 51 个含测试包通过；api/orchestrator 竞态、新增 SSE 用例单独竞态、定向 vet、JavaScript 语法和差异/文档链接检查通过。普通 Go 测试仍不需要浏览器、真实身份凭证、付费模型或外部数据库。

## 后续边界

完整精确流重放需要持久化 token/事件序号、保留窗口、去重、跨节点订阅及额外验收，本次没有把这些能力等同于状态对账。快照读取仍会读取完整 Task/Trace，长 Trace 与大量并发订阅的容量应在 F10 建立基线；快照计数不是快照隔离事务，Task/Trace/approvals 查询也不构成一个联合事务。

F05 在线身份验收仍待字段契约与专用凭证，HA/DAG 按用户要求延后。下一项独立工作可推进 F10 的 Task/Trace 增长、分页及订阅容量基线。
