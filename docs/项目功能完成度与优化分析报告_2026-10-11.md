## 1. 总体判断

项目已经形成较完整的 AI Agent 运行时：任务创建、执行、检索、工具调用、人工审批、持久化、恢复、答案审计、会话管理和浏览器操作台均有代码实现及测试。它已超出原型阶段，可作为受控环境中的任务执行服务使用。

**当前主要缺口是发布与生产验收闭环，而不是核心功能缺失。** 多 Agent DAG 已实现，但默认仍为 Legacy、Canary 0%；真实双实例部署有短时验证，完整一小时负载、独立审批、故障恢复及灰度门禁仍未完成。另发现 GitHub Release 打包流程缺少输出目录，属于正式发版前应修复的问题。

建议下一阶段先完成“发布流程修复 → 运维脚本闭环 → HA 故障验收 → DAG 小流量灰度”，然后以业务评测数据优化检索和答案质量。动态插件和新增团队能力应排在这些工作之后。

### 1.1 完成度口径

本报告按以下状态评价，避免用缺少需求分母的百分比制造精度：

| 状态 | 定义 |
|---|---|
| 已实现并有回归 | 主路径、服务装配和相应测试存在；不等于在所有真实依赖环境验收 |
| 已实现，外部验收待补 | 代码及离线/模拟测试存在，真实环境、持续运行或业务质量证据不足 |
| 部分实现 | 具备一部分目标能力，关键环节仍缺失 |
| 尚未交付 | 当前没有完整可用实现，或明确在范围外 |

测试通过只能说明被测试的行为满足断言；本文没有进行正式需求验收、完整安全审计或逐行审查，也没有计算测试覆盖率。

## 5. 当前发现与优化优先级

### F01 / P0：正式 Release 工作流缺少 `dist` 目录

后续状态：已修复目录缺失并补充回归；正式发版仍需远端构建与发布验证。详情见 [修复记录](P0-Release打包修复记录_2026-10-11.md)。

**类型：已复现的发布缺陷。** [.github/workflows/release.yml](../.github/workflows/release.yml) 的准备步骤只创建 `build_stage/<artifact>`，压缩步骤却写入 `../dist/<asset>`，没有创建 `dist`。在不存在该目录的干净环境中，tar 无法创建目标文件；Windows zip 分支也依赖同一个缺失目录。Linux 路径已在临时夹具中复现退出 1。

影响：平台二进制可以编译成功，但构建任务无法完成打包/上传，正式发布被阻断。该问题与 HA `build-bundle.sh` 的历史成功是不同路径，不能用后者证明 Release 工作流正确。

建议：在归档前显式创建输出目录；增加干净目录下完整打包及包内容校验。顺便核对手动 `workflow_dispatch` 版本对应 tag/ref，明确提交身份、SHA256 清单和必要 CLI 的分发范围。后者是发布治理建议，不作为本轮已复现缺陷。

完成标准：五个平台均生成非空归档，可解包，包含预期二进制/配置/skills，并能从清单追溯源码；正式发版前核验实际 CI 运行结果。

### F02 / P1：HA 观察脚本仍未形成稳定停机闭环

**类型：代码可见的运维缺口，历史事件已有佐证。** [observe-load.mjs](../deploy/ha/freestyle/observe-load.mjs) 验证身份和预算，但没有像创建器那样读取并拒绝 `automaticRestart=true`；它只停止 Agent 节点服务，对 Control 未显式停止 Prometheus/stub 后再 pause，也没有四台 pause 后延时统一复核清单。`pausesConfirmed` 表示当时 pause 响应确认，不能证明稍后仍稳定暂停。

创建器已经要求 `automaticRestart=false`，减少了新环境风险；观察器仍可能收到旧状态文件或已改变的环境。现有 12 项 Node 测试通过没有覆盖上述闭环。

建议：补自动重启配置校验、Control 服务停机、全节点延时清单复核；资源复活或状态未知时记录失败并明确告警。保持证据先导出、部分失败也继续处理其他明确节点的行为。

完成标准：模拟自动重启配置漂移、暂停后复活、Control 停机失败和清单查询失败，均不能输出稳定停机成功；在下一次专用环境重建时留存真实复核证据。

### F03 / P1：完整 HA 与 DAG 发布证据不足

**类型：已明确的验收待办，不是已发现执行器 Bug。** 代码已有共享存储、租约、恢复与灰度能力，但当前记录尚不足以批准全量 DAG 或宣称生产 HA。

建议：按同一干净发布提交重建并核验包，在专用存储上复跑契约；执行至少一小时连续窗口，独立验收审批、取消、SIGTERM、崩溃、旧 owner fencing、恢复副作用和 SSE 对账。随后按计划进入 20%/50%/100% 门禁与回退；门槛不满足保持 HOLD。

完成标准：所有验收项有与提交、配置、窗口一致的证据；pending/null 不算通过；真实 LLM 质量与应用 HA 分开报告。存储服务冗余、备份/恢复、RPO/RTO 需另列范围和结果。

### F04 / P1：进程执行的隔离边界需明确并加强

后续状态：最小环境与可选 Docker 执行后端已实现，并通过本机真实隔离验收。默认仍为 local，目标环境部署验收、磁盘配额与崩溃残留对账待补。下文保留原评估基线，实施及验证边界见 [容器验收记录](工具容器执行与隔离验收_2026-10-12.md)。

**类型：架构限制，面向不可信代码/多租户执行时优先处理。** [runner.go](../internal/tools/runner.go) 使用 `exec.CommandContext`，设置工作目录、超时、输出界限及进程组取消；[政策](../internal/policy/policy.go) 允许 Python/Node/bash/sh 等通用解释器。工作目录和可执行文件白名单不会限制被执行代码访问其他文件、网络或继承进程环境。

高风险审批已存在，应保留；它不能代替 OS 级隔离。另 [internal/workspace/doc.go](../internal/workspace/doc.go) 明确该包是早期原型、不是文件系统沙箱、未接入生产入口。

建议：明确受信任运维工具与不可信代码执行的支持范围；后者放入独立执行容器/进程身份，限制挂载、网络、CPU/内存/进程数，使用最小环境变量集合，避免把上游凭据继承给任务。文件工具现有 `os.Root` 防护继续保留。

完成标准：隔离环境内的越界读取、外网连接、子进程扩散、资源超限与秘密环境读取均有独立验证；不应只测试路径参数被拒绝。

### F05 / P1：生产租户策略与审批角色仍需产品化

后续状态：个人身份与审批名单已实现，严格生产示例默认拒绝审批；真实身份字段与启用验收、完整 RBAC 仍待完成；后续已补创建者身份持久化及可配置禁止自批（历史身份缺失时拒绝决策）。详见 [实施说明](生产认证与审批权限说明_2026-10-11.md)。下文保留原评估基线。

**类型：配置及身份能力边界。** 默认不要求已知租户/专属 workspace；introspection 默认不要求 expiration/issuer/audience。代码支持更严格策略，但仓库默认并非严格生产模板。

`Principal` 已有 `ActorID`，审批会持久化操作者；JWT 可使用已验证的 subject 派生稳定标识，API Key 是租户级标识，introspection 当前回退为 `tenant:<id>`。因此不能再写“完全没有审批人字段”，也不能据此宣称可区分同租户每个操作员。当前没有完整的 viewer/operator/approver 角色模型或创建者自批限制。

建议：提供经过验证的生产配置基线，要求租户 workspace 与 Team/Wiki/Brain 范围；由可信身份服务提供稳定个人主体；按需要增加审批角色和自批规则。issuer/audience/expiration 的要求应与真实身份服务契约共同确定。

完成标准：未知租户、越权 workspace、无审批角色、身份过期和自批策略均有服务端测试；实际登录链路 fail-closed，并能审计个人操作者。

### F06 / P2：SSE 持久化对账与精确重放边界

后续状态：GET 首次/重连快照、非终态/终态周期对账及 Console 恢复触发已补齐；真实 HTTP/SQLite 独立处理器与慢消费者回归通过，三浏览器 54 项通过。精确 token 重放未实现，正式 HA/LB 验收仍延后。下文保留评估基线，当前契约见 [SSE 恢复记录](SSE断线恢复与持久化对账_2026-10-12.md)。

**类型：产品能力限制。** 事件总线是进程内的，慢客户端可能丢中间事件；存储轮询只兜底终态。当前足以支持“实时提示 + 定期读取 Task/Trace”，不等于任意节点可重放全部 token 和步骤。

建议：先明确产品是否需要精确流续传。如果需要，设计持久化事件序号、Last-Event-ID、授权、保留与跨节点订阅；优先复用持久化 Trace，避免引入重复状态源。若仅要求状态最终一致，则明确刷新/重连后的对账行为与延迟目标。

完成标准：强制断线、跨节点重连和慢消费者时，结果不丢失；若声称事件精确续传，必须另外证明无漏项及可去重。

### F07 / P2：真实业务质量、成本与检索性能基线不足

完成标准：形成可复现基线与回归阈值；样本不足或依赖错误不能算成功。付费/在线评测另按用户明确预算执行。
