## 修复范围

### 孤立任务取消与审批恢复边界

只修改无本地活动 owner、无审批 bus 的数据库取消兜底。支持 running、awaiting_approval、paused；先获取 task lease，再 reload 并复查 tenant/状态。仍有其他实例 owner 时返回 409，不覆盖其 checkpoint；等待期间已成为终态则拒绝，不拿旧 Task 回写。

成功取消保存 failed / `termination_kind=user_cancelled` / `error_code=task_canceled`。新增 termination kind 区分明确用户取消与历史 client_cancelled/timeout/shutdown 可恢复中断；审批恢复和启动筛选不会自动恢复 user_cancelled。API 请求字段及成功响应形状未改变，Task 详情可返回新 kind。

先持久化不可恢复的取消状态，再逐条以版本 CAS 将 pending/approved 审批置 expired；与并发 pending->approved 竞争时重读并有限重试。Task 和这些审批变更不是同一事务：若审批失效失败，返回错误，但 Task 已经 fail closed，不能因此执行已批准动作；相同 cancel 可幂等重试清理。rejected/consumed 记录保留，不伪造清理或重放。单任务删除不再被 awaiting_approval 状态卡住；这不代表已修复审计 BUG-07 的关联记录残留。

本地活动任务取消、审批 bus 转发仍保留原异步信号语义，不将此兜底修复宣称为所有取消路径的审批失效协议。专用 owned gate 也没有被普通 cancel lease 绕过。Console allowed_actions 增加 paused 的 cancel；相关 API 行为见 [task-api](task-api.md) 和 [HTTP 样例](../Sample/agent-api.http)。

### re-audit 的 checkpoint 和 owner

获得并发槽和 task lease 后重新读取并验证 tenant、终态及非空答案；审计/保存上下文绑定相同 owner。ExecutionLease 续租失败会取消流水线上下文，保存时仍由 Store 严格 guard 检查实际当前 owner/有效期，防止 monitor 尚未感知的 lease 替换造成脏写。丢失 ownership 返回 409；自定义 Store 未提供 TaskLeaseStore renewal 返回 501。最后先停 renewal，再按原 owner 释放，避免旧清理释放 peer lease。

没有为终态 re-audit 自动建立专用 owned attempt 或开启实验配置，也没有修改答案审计的业务规则。

### read_file 有界、根约束及编码

保留既有 workspace policy，使用 `os.OpenRoot` 约束所有路径组件，路径/符号链接变化不能逃出已打开的工作区根。打开前及 descriptor 打开后都要求 regular file；Unix 非阻塞 open 防止 regular file 被替换为 FIFO 后在 Stat 前阻塞。读取上限 4001 字节，规范化非法 UTF-8 后按完整字符边界返回至多 4000 字节，Evidence 不再保存截断的非法字节。工具入口在读取前后检查请求取消。

该修改仅覆盖 read_file，不修改 write_file、apply_patch、SQL 或其他工具。原报告 BUG-05 中 write_file 的目录 TOCTOU 仍需单独核验/处理；Windows 本轮仅交叉编译，不宣称实际 Windows 路径竞争或命名管道验收完成。工作区内部 symlink 仍受 Root containment 约束，未将目录树清理纳入实现。

## 回归与失败记录

- 修复前，read_file 的中文/非法字节回归失败；读取 8 MiB 文件只返回 4 KB 时分配约 8.4 MB；FIFO 无 writer 时阻塞。修复后分别检查字符完整性、返回大小、分配上界和立即拒绝特殊文件。
- 修复前，Memory/SQLite re-audit 在获得 lease 时 checkpoint 更新后仍读取旧答案，且丢失 lease 后能覆盖 peer。回归覆盖新答案、新 running 状态、peer owner 保存与真实 renewal 拒绝后的 pipeline 取消（synctest，不等待真实 30 秒）。
- 取消回归覆盖 Memory/SQLite 三个可取消状态、pending/approved 失效、重复请求、随后单任务删除、peer busy、获锁后状态变化、审批写失败的 fail closed 与并发决策 CAS。
- 初版取消夹具缺失 RiskLevelHigh，部分用例在创建审批时失败；修正 fixture 后完成实际取消测试，不把夹具失败当作缺陷复现。peer busy/旧快照覆盖在修复前已有独立失败记录。
- 文档更新脚本一次使用字符串调用 Path 方法失败，已修正；没有丢弃已有文件或把失败当作成功验证。
