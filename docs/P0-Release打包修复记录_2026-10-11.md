## 问题与修复

GitHub Release 工作流在干净检出中只创建 `build_stage/<artifact>`，却直接向 `../dist/<asset>` 写入归档。tar 和 zip 都不会自动创建缺失的父目录，导致五个平台在压缩步骤失败。

在 [.github/workflows/release.yml](../.github/workflows/release.yml) 的压缩步骤中，先执行 `mkdir -p dist`，再进入 `build_stage`。归档名称、平台矩阵、包结构和发布入口保持原契约。
