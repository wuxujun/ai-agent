## 发现与修复

首轮系统 Chrome 套件为 23/24：390px Trace 区域聚焦后按 End 没有到达第 100 条。虚拟列表新增仅针对区域本身的无修饰 Home/End 处理，显式设置 scrollTop 并刷新虚拟窗口；不接管文本输入、详情子控件或带修饰键的组合。320/390px 回归现在同时检查 End 到末尾、Home 回首条，以及筛选输入的焦点、内容和列表滚动保持。

首轮修复后的额外输入框测试把 macOS End 当作行尾光标操作，导致 22/24；改为平台无关的焦点/值/列表滚动断言后，定向及完整套件通过。没有弱化列表首尾检查，也没有增加等待时间来掩盖失败。

新增原生 EventSource 场景：第一次请求返回有限的 `text/event-stream` EOF 和 retry 指令，浏览器自动发起第二次请求；该请求放行到真实认证 Go SSE 路由，核验 `X-SSE-Recovery: snapshot` 和 200。隔离任务在断开窗口内取消后，页面重新读取 Task、Trace、approvals 并显示已保存的失败终态。只冻结页面时钟控制 300ms 对账，没有用伪 EventSource 替换浏览器网络实现。此证据仍不代表线上代理、TLS 或负载均衡器故障验收。
