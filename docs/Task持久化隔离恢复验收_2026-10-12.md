## 离线命令

父目录必须已经存在。输入为私有文件中保存的完整 task-joint-export-v2 JSON；不接受 v1。命令不读取运行时 config，不初始化在线 Store、模型、索引或执行器。

```bash
go run ./cmd/task-restore import \
  --file /private/path/task-joint-export.json \
  --tenant tenant-a \
  --parent /private/path/restore-sandboxes \
  --byte-budget 1048576

go run ./cmd/task-restore verify \
  --directory /private/path/restore-sandboxes/task-restore-XXXXXX \
  --task task-id \
  --tenant tenant-a
```

import 先完整校验包，再新建随机私有目录、事务导入，关闭可写连接，重新打开只读连接，逐记录验证。成功输出 JSON：

```json
{
  "sandbox_directory": "/private/path/restore-sandboxes/task-restore-XXXXXX",
  "verification": {
    "task_id": "task-id",
    "tenant_id": "tenant-a",
    "verified": true,
    "target": "persistent_isolated_sqlite",
    "source_preserved": true,
    "restore_ready": false,
    "payload_sha256": "<原 payload SHA-256>",
    "trace_count": 2,
    "approval_count": 1,
    "memory_count": 1,
    "source_backend": "redis",
    "reopened": true
  }
}
```

verify 可在另一进程中重复读回。报告不包含目标/Trace/记忆正文、审批密文或密钥。reopened=true 表示已关闭写入连接后重开验证，不证明系统断电恢复，也不授予在线执行或删除权限。参数错误退出 2，读取/存储/验证失败退出 1。输入必须为普通文件，字节预算 4096–8388608，默认 1 MiB；命令使用中断取消及 30 秒期限。

## 隔离边界

CreatePersistentTaskRestoreSandbox 只接受已有父目录，使用 MkdirTemp 新建 0700 目录，并以 O_EXCL/0600 创建固定 isolated-restore.sqlite 文件。不接受已有数据库文件、Redis/PostgreSQL DSN 或在线连接，无法覆盖现存数据库。SQLite 使用 DELETE journal 和 synchronous=FULL。

OpenPersistentTaskRestoreSandbox 仅只读重开专用目录；拒绝目录/文件符号链接、非普通数据库文件、非私有权限（POSIX）、数据库 identity/schema 版本不符、额外业务表或缺失必需列。检查路径与文件身份后，以 mode=ro、query_only=ON、trusted_schema=OFF 打开；不迁移表、不修复索引、不重放审批。普通在线 SQLite 数据库即使放到同名文件也会被拒绝，文件字节不变。数据库 identity 是格式标记，不是来源签名；不把恶意伪造格式的文件视为可信来源。

数据库分别保存原始联合包、规范预期快照、原 payload hash 和各独立恢复记录。重开验证会重新验证原包及其清单/hash/关系/配额，将预期与原包比对，再逐条读取 Task、Trace、审批、记忆和 session。缺失/新增/乱序/修改记录、损坏原包或清单均失败；不会用损坏的预期快照直接报告成功。对持久记录读回先检查数量与总长度。

原物理时间、Trace 序号、审批版本/状态/owner/密文、大整数参数、embedding、session 高水位和所有正文保真；不获取执行租约或恢复运行。源文件和源数据库不传入目标数据库连接，导入/验证不会修改源记录。

失败时已创建的目录和文件保留，不做自动删除。无效包在创建目录前拒绝。取消或写入故障回滚导入事务；有独立进程在提交后直接退出及小事务提交前退出的回归。若异常终止留下需要可写恢复的 SQLite 热日志，只读重开会拒绝，保留现场；当前不实现自动热日志修复或断电恢复保证。

HTTP `POST /api/retention/imports/verify` 继续使用临时沙箱，不接受服务器文件路径或持久目标参数。成功报告新增 source_backend 字段；原鉴权、预算、脱敏错误和 restore_ready=false/source_preserved=true 保持不变。持久目录只由离线命令创建，避免 HTTP 上传积累服务器文件。

## 验收

Memory/SQLite 源联合快照均通过完整依赖的持久化导入、关闭/重开及源快照不变检查。进程退出后数据可验证；导入中途取消没有残留记录；重复 ID 不覆盖；只读重开拒绝写入；跨租户、正文/hash/包损坏、缺失记录、序号改变、格式身份/版本改变、额外表、缺失表、符号链接和权限不符均拒绝。

Redis/PostgreSQL 外部测试都需要 AI_AGENT_RUN_EXTERNAL_INTEGRATION=true、AI_AGENT_RESTORE_DEDICATED_DB=true 及相应专用连接。测试创建独立 fixture Task/session/审批/记忆，不删除源记录；导入前后比较完整源联合快照。Redis 额外比较所有应用键 DUMP，确认没有源数据写入。这些是各源后端的联合包恢复到专用 SQLite 的验收，不是 Redis/PostgreSQL 恢复目标后端。
