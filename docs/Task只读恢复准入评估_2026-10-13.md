# Task 只读恢复准入评估

日期：2026-10-13。状态：实现与验收记录，未部署。承接 [完整恢复准入设计](Task完整恢复准入设计_2026-10-12.md)。已实现版本化清单、只读诊断评估器和离线 assess 入口；workspace 的实际文件检查器已接入（见本文件末尾）；其余外部依赖可信检查器及在线恢复尚未实现。所有结果继续 decision=blocked、restore_ready=false、source_preserved=true，不签发 eligible 或清理许可。

## 离线使用

仅评估已存在的专用持久化 SQLite 沙箱；不创建数据库或输出文件，不读取在线 config、不连接在线 Store，不解密审批或执行工具。使用已有 import 创建的目录：

```bash
# 构建为独立可执行文件，保留命令自身的退出码。
go build -o /private/path/task-restore ./cmd/task-restore
/private/path/task-restore assess \
  --directory /private/path/restore-sandboxes/task-restore-XXXXXX \
  --task task-id --tenant tenant-a

# 可选：提供只含绑定和证据摘要的清单。
/private/path/task-restore assess \
  --directory /private/path/restore-sandboxes/task-restore-XXXXXX \
  --task task-id --tenant tenant-a \
  --manifest /private/path/dependencies.json
```

未提供 manifest 时，程序在内存生成当前绑定和空证据清单，输出九类 missing 与 online_restore_not_implemented。可从输出 binding 构造待评估清单；不向磁盘写入模板。提供完整摘要清单但不提供独立 workspace 基准时，声明仍报告为 unverified；用户清单本身不能证明外部依赖有效。

可执行文件退出码：3 表示已完成诊断但准入被阻止；1 表示读取/解析/核验/输出失败；2 表示参数错误。本阶段 assess 不返回 0。用 go run 运行时，Go 包装进程会将命令的非零退出报告为 exit status 3 等，不能直接依赖包装进程获得子命令退出码。命令继承既有中断取消与 30 秒期限。

## 清单契约

schema 为 task-restore-dependencies-v1，最大 64 KiB，拒绝重复 JSON 键、未知字段、尾随 JSON、重复类别、未知类别、错误版本及非法摘要。evidence 缺失或为空是有效的待补清单，评估结果为 missing。

以下为格式示例，尖括号内容需替换为实际绑定；该示例不构成已验证证据：

```json
{
  "schema": "task-restore-dependencies-v1",
  "binding": {
    "task_id": "task-id",
    "tenant_id": "tenant-a",
    "payload_sha256": "<v2 payload 的 64 位小写十六进制 SHA-256>",
    "target_id": "<目标身份的 64 位 SHA-256>",
    "target_version": "isolated-sqlite-v1",
    "runtime_version": "task-restore-diagnostic-v1",
    "policy_version": "read-only-admission-v1",
    "state_revision": "<当前状态的 64 位 SHA-256>"
  },
  "created_at": "2026-10-13T12:00:00Z",
  "expires_at": "2026-10-13T12:05:00Z",
  "evidence": []
}
```

每条 evidence 仅含 kind 和 sha256；摘要用于与可信检查器实际核验的证据对比，不当作路径、URL、DSN 或正文读取。原 workspace 文件清单、密钥版本和审计细节由未来各类可信检查器验证；本阶段不接受这些正文作为上传证据。

| kind | 必须由可信检查器证明的范围 |
|---|---|
| workspace | 文件依赖清单、路径/权限/租户根隔离、大小/hash/预算 |
| key_management | 历史密钥版本可用、审批密文可验证；不输出密钥或明文 |
| external_audit | 外部审计引用、审批依据和连续性 |
| session_dependencies | 其他任务/依赖图/会话高水位、跨租户和 ID 冲突 |
| execution_leases | 当前执行状态、旧执行器隔离、租约与重跑策略 |
| approvals_and_effects | 当前有效审批、幂等性和副作用对账 |
| memory_index | embedding 模型/维度/索引兼容与访问权限 |
| target_compatibility | 独立目标、运行时/schema/工具/策略/预算兼容 |
| isolated_drill | 全依赖专用目标演练、源不变、故障拒绝 |

即使某类依赖不存在，也必须由可信检查器证明“不适用”的事实并返回 verified；清单不能自行省略、声明 not_applicable 或绕过类别。

## 可信读取与拒绝原因

EvaluateTaskRestoreAdmission 先严格验证原 v2 包。Task/tenant/payload hash 必须与清单一致；目标身份、目标版本、运行时版本、策略版本及状态版本必须与可信 ReadState 结果完全一致。缺失检查器或沙箱未核验不获得通过。

TaskRestoreAdmissionReader 是进程内可信只读接口，不能从上传清单反序列化。CheckEvidence 只有 verified/missing/conflict 三种已知状态，其余状态或错误报告为 unverified。verified 还必须匹配完整绑定与证据 hash，具有有效核验时间和到期时间。清单及观察窗口最多 15 分钟，拒绝未来时间、零时间、已过期或过长窗口；结束时复查时效，评估前后复查状态，状态变化或时钟回退都阻止准入。适配器必须传播 context 并在状态版本中覆盖所有相关外部状态；前后对比不能替代未来在线执行时的原子租约/fencing。

离线适配器真实验证现存沙箱独立记录，检查文件/目录身份、私有权限和路径，使用主数据库 SHA-256 作为 state_revision、规范目录路径 SHA-256 作为 target_id。数据库指纹读取最多 64 MiB，支持取消；导出包长度检查与读取在同一只读事务内。核验前后数据库指纹变化即失败。runtime_version 和 policy_version 在此指离线诊断器契约版本，不代表在线服务配置或当前租约状态。workspace 文件适配器已接入，其余外部证据适配器尚未接入；不能把沙箱数据保真冒充全依赖验证。

报告 schema 为 task-restore-admission-diagnostic-v1，新增 verified_evidence 仅列出仍有效的已核验类别及摘要；报告包含当前可信 binding、checked_at、包/清单摘要、evidence_complete、decision、固定恢复标志及 kind/code 阻止清单。不会输出用户证据正文、原目标/Trace/记忆、审批密文、路径或原始适配器错误。证据摘要完整且所有可信观察通过时，evidence_complete 可为 true，但仍追加 execution/online_restore_not_implemented，decision 仍 blocked；这个分支目前仅以 fake 验证接口契约，不代表生产依赖验收完成。

主要原因：missing、unverified、conflict、artifact_binding_mismatch、state_binding_mismatch、sandbox_unverified、evidence_binding_mismatch、expired_or_invalid_time、expired_during_assessment、state_changed、clock_moved_backwards、online_restore_not_implemented。格式错误没有诊断报告，返回脱敏失败。
