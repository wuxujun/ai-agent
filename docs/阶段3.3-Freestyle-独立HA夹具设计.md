# Freestyle 独立 HA 夹具设计

本文件是当前只读基线之后的具体实施设计，尚未部署。现有 `read_file` 夹具不产生审批、Replan 或可计数副作用；本次一小时负载继续使用它，配置和 0% 灰度保持不变。目标仅为已创建的四台专用 Free VM，应用包保持干净 `9aeb24b`，累计 6 小时限制不重置、不提高。

## 夹具与配置

下一版离线服务保留现有 LLM Bearer 认证、固定 schema、输出上限及无正文日志。在相同 Control 私网 18080 增加专用计数路径 `/ha-fixture/counters/<run-id>`，复用现有 A/B 到 Control 的限定规则；计数路径使用每次演练独立的 capability token，不使用 Freestyle key、应用管理员 key 或模型 token。只接收预先登记的 run ID、节点标签及有限场景，不接受任意文件路径或命令。

计数器必须记录每次有效调用，不通过幂等键吞掉重复调用，否则无法检测重复副作用。Control 在进程锁内追加序号并 fsync 到私密日志，再返回序号；报告只保留 run ID、节点、时间、序号和总数，token 不进入报告。日志及登记文件为 0600，状态目录 0700。计数服务重启后从日志恢复序号，解析错误时停止，不清空或复用旧 run。

A/B 安装同一 root 所有、不可由 ai-agent 修改的 `ha-effect-probe.py`，核对 SHA256。它只连接固定 Control 地址、固定路径，读取专用 capability，发送一次请求，无自动重试；请求和响应均有边界与超时。提供受控的执行前等待点，以便在工具真正发出副作用前注入取消、失租或崩溃。等待最多 60 秒，到期失败，不能无限挂起。计数调用已成功后再遇到取消时仍记录为已发生的副作用。

专用 Team 白名单仅扩展为 `read_file`、`execute_code`，命令只由离线夹具生成固定 `python3` 与已校验脚本参数。保留 `execute_code` 的 High 风险、正常审批、Workspace 边界及进程取消；不启用任意软件开发工具。租户仍只允许该测试 Team、专用目录和有限任务预算。A/B 的配置、Team 和 probe 摘要必须一致，先静态校验和一条审批预检，再进入故障矩阵。当前 stub 不接受该 schema，不能直接修改白名单后继续负载。

Replan 使用独立场景：首次固定动作返回一次可识别的夹具失败；第二次规划返回有限纠正动作。每个 run 最多一次纠正，记录反馈和 Replan Trace 摘要。普通只读成功不能充当 Replan 覆盖。

## API 与观测协议

使用同一 `ha_test` 租户身份，显式指定本次 run 唯一任务 ID。现有接口为：

| 操作 | 接口 | 判断依据 |
|---|---|---|
| 创建及执行 | `POST /api/tasks`、`POST /api/tasks/:id/run-all` | 创建节点、执行 owner、实际状态 |
| 查询审批 | `GET /api/tasks/:id/approvals?status=pending` | 从 B 获得明确 approval ID，核对任务、租户及固定动作 |
| 批准/拒绝 | `POST /api/tasks/:id/approve`、`POST /api/tasks/:id/reject` | 只提交 approval_id，不覆盖动作参数；后查持久化决定 |
| 取消 | `DELETE /api/tasks/:id/cancel` | 200/202 只代表接纳，继续核对终态及副作用 |
| 状态与 Trace | `GET /api/tasks/:id`、`GET /api/tasks/:id/trace` | A/B 脱敏快照一致、审批 consumed 状态、错误和恢复轨迹 |
| 实时事件 | `GET /api/tasks/:id/stream` | 注入前已连接，记录事件时间；故障中跨节点重连后核对持久化状态 |

并发决定使用同一明确 approval ID，记录每个响应状态及唯一持久化决定。成功可能为 200 或跨节点 202；其余请求应体现 CAS 冲突，不能把多个 202 或一次 forwarded 响应直接解释为工具已经执行。恢复代码可能将任务置为 paused，随后明确 `run-all`，持续核对原审批及计数器；不循环批准所有 pending 动作。

实时 SSE 的流日志只保留事件类型、时间、任务 ID、状态和摘要，不保留原始回答、审批正文或秘密。跨节点重连不预设进程内 SSE 提供历史重放；最终以持久化状态判定。

## 故障矩阵

| 场景 | 执行步骤 | 必须独立断言 |
|---|---|---|
| 批准/拒绝 | A 等待审批；B 分别批准与拒绝新的任务 | 批准路径一次有效计数；拒绝路径零计数，两节点状态一致 |
| 并发 CAS | A/B 并发提交同一审批决定，随后重复提交 | 只有一个持久化决定，计数不超过一次；保留冲突响应 |
| 跨节点取消 | A 执行受控等待，B 发出取消 | 旧执行器停止，等待释放后不再新增计数；已发生动作如实保留 |
| SIGTERM | 等待审批或执行前等待时停止 A，再恢复 | 退出耗时、paused/恢复轨迹、原审批可读、计数不重复 |
| 批准前崩溃 | A pending 时 SIGKILL；租约到期后 B 批准及恢复 | 同一 keyring 正常解密，原审批恢复，计数一次 |
| 消费后、副作用前崩溃 | 观察 consumed 且 probe 进入执行前等待后注入 | 记录可观测断点；计数零或一次，不能宣称必定执行一次 |
| 失租/续约失败 | 仅隔离指定 A 的专用存储流量，预设自动恢复 | 原连接确实中断，旧 owner 退出，不能覆盖新 owner 结果；外部副作用另查计数 |
| 实时 SSE | 上述每个故障前连接 A，故障期间连接或重连 B | 流事件与持久化终态一致，不以事后终态 SSE 代替实时覆盖 |
| Replan | 一次固定失败及一次纠正 | 有真实反馈和 Replan Trace，预算未越界，不放开其他工具 |

`RecoverApprovedApproval` 在工具执行前把 approved CAS 为 consumed，源代码明确选择至多一次消费；在 CAS 成功后、执行前崩溃可能丢失该次动作。此时 consumed 且零计数是需要记录和复核的行为，不自动重试同一高风险动作，不将它写成恰好一次或无损恢复。租约 fencing 保护持久化写入，也不能撤销已经发生的外部动作。

probe 等待点位于工具已启动、外部副作用提交之前，不能把它改写成精确覆盖 CAS 后、工具尚未启动的窄窗口。后者如需实测，应另备可校验的插桩发布版本并单独记录身份，不能称为当前干净 `9aeb24b` 包的结果。

失租注入实现前核对真实续约周期、任务租约及存储连接范围。采用 guest 网络隔离时必须限定指定 VM/端口、覆盖既有连接、有自动恢复，并保留平台控制通道；不猜数据库表名或执行批量数据修改。Freestyle pause 保存内存，不是冷启动或 SIGKILL 证据。

## 续接与完成条件

1. 先读取本轮导出结果和四台实际累计秒数。恢复顺序为 Storage → Control → A → B，每步检查依赖和挂载；本轮结束时 A/B 应用服务显式停止，VM 恢复后还须逐台启动服务并检查 readiness。不得重新创建环境、重新 bootstrap 或复用旧 run ID。
2. 完成新夹具实现、离线回归、配置验证和 A/B 摘要检查后，再执行上述矩阵；所有注入只针对专用资源，每项保留任务 ID、注入/恢复时间、断言和计数日志摘要。
3. 分别保存 runtime、配置版本、Team、工具和 probe 版本。基线 JSONL 的 unknown 样本不改标为 Legacy；后续 DAG 证据也不能沿用 Legacy 场景结论。
4. 独立断言及审批/Replan 复核完成后，才推进 20%/50% 的完整比较窗口与 100% 稳态；不调低门槛，不伪造人工复核通过。本轮准备耗时已占累计预算，先按实际剩余时间规划，时间或免费额度不足就暂停，不自动扩展。
