## 审批恢复 owned adapter

`Engine.RunOwnedSQLiteApprovalRecovery(ctx, store, task, approval, options)` 显式复用 C03b2 owned 生命周期：先原子登记唯一 attempt/lease，再 reload Task，在同一 scope 中调用现有 RecoverApprovedApproval 或 RecoverRejectedApproval，随后 exit/最后 flush/cleanup/停止 renewal/finalize。

审批 TaskID/tenant、批准/拒绝状态在登记前校验。现有 durable approval lease、状态/版本 CAS、解密、消费先于动作执行和防重放行为保留；没有替换审批权限或降低原风险流。

owned wrapper 通过私有上下文 key 携带 source Store 与固定 identity。`beginApprovalRecovery` 只在核对相同 Store、启用的 checker、scope 和既有 lease/admission 成功后复用外层所有权并 reload checkpoint；内层 cleanup 为 no-op，不另开普通 task owner，不停止外层 renewal，也不提前释放 task lease。审批自身的 lease 仍由原 recovery 方法管理。

普通 recovery 调用没有该私有 marker，继续沿用原来的 task lease 获取/续租/释放路径；只传一个 C03 attempt ticket 不能让它跳过外层所有权管理。默认 HTTP 与启动扫描没有改成调用新 adapter。

## Coordinator detached checkpoint 修复

`persistTaskDetached` 原先用 context.Background 重建上下文，丢失 task lease/tenant/request values。现改为接收实际执行 ctx，使用 WithoutCancel + 10 秒 timeout，保留 scope、owner、请求 runtime 与 trace 信息，脱离取消但不移除所有权守卫。

reviewed/research workflow 的 SaveCheckpoint closures 均传入其执行 ctx。没有更改 DAG 默认关闭/legacy 配置，没有自动将 detached flush 当作 attempt 完成回执。

新增回归通过 guarded callback 证明取消后仍可保存，owner 被替换后旧 scope 写入被拒绝且旧 checkpoint 不覆盖新值。该测试是 context/callback 集成夹具；因 store→memory→multiagent 已有依赖，不能从 multiagent 包内测试导入 Store；原先尝试产生测试 import cycle，已改用本地 guarded callback，未声称这个用例直接运行了 Store lease guard。C03b2/Store 的真实 SQLite owner 回归仍由全仓一起执行。

## HTTP/启动/关闭覆盖矩阵：待下一批实现

| 入口 | 当前实际边界 | owned 接入要求与验收 |
|---|---|---|
| runTaskStep JSON | Handler 预留 activeRun，普通 UUID owner/90 秒 lease；Engine.Next 后 SaveFullTask，defer 释放；request timeout 60 秒 | 替换 task owner 的创建/续租/flush/finalize 整段；不能在原 lease 已获取后再嵌套 Start。保持 semaphore、错误状态及事件行为 |
| runTaskStep SSE | goroutine 交接 activeRun/semaphore，客户端断连 handler 可先返回，worker 最后 SaveFullTask | attempt 归 worker，退出/flush/cleanup 完成前不能发布完整回执；断连不等同 stopped；保留 SSE 订阅/终态事件语义 |
| runAll async/SSE | detached request values + pausable timeout，预留 slot 后普通 owner 获取 lease、reload/CAS；worker keeper、最后 flush、defer release | 把 owned admission 与状态 CAS/注册顺序统一；202 响应前后失败不泄漏 slot/lease；保留订阅、取消与原 final event 顺序 |
| API approval recovery | task_approval_handler 在后台调用现有 Recover*，普通 approval-recovery UUID | 显式选择 owned adapter、instance/attempt 生成与 gate 版本必须来自可信代码；保持审批原授权、消费和并发限制 |
| 启动审批扫描 | cmd/server/build.go startup-recovery owner 调用 Recover* | 与 HTTP 相同 adapter/身份契约；重启 unresolved attempt 保持 unknown，不自动续旧 instance 或重放已消费动作 |
| CancelTaskByID | 发取消并可能提前移除 activeTasks | map 缺失不证明 worker/工具退出；durable attempt 保留到确认退出/flush/cleanup，取消失败也不能解除 gate |
| Shutdown/Wait | Wait 等待 worker；超时可继续；rollbackInterruptedTask 会重新获取普通 lease | 超时不签完整回执；状态回滚不能伪装为新执行或绕过 closed gate；要单独定义受控维护 scope，而非复用已 complete 的 attempt |
| Coordinator checkpoint | 本轮已保留 detached ctx/lease values | 还需实际 owned Coordinator/DAG fixture 的取消、并发 checkpoint、lease loss 矩阵；不能凭保留 context 宣称完整集群 fencing |

HTTP adapter 必须在可信构造代码中显式选择，默认 nil；不能从请求/Task/恢复包选择提供者、instance 身份或 cleanup。需要保持 tenant/RBAC、预算、日志脱敏、中间件/SSE、status CAS 和 rollback 语义。没有新增 endpoint/请求字段/配置项，所以本轮不修改 Sample API 合约。
