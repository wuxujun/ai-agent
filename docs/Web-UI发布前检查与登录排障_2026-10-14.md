## Bearer Token 与会话密钥

当前主配置使用 `api.auth.mode: introspection`。用户输入组织身份服务签发的访问 Token，后端携带 `Authorization: Bearer <Token>` 请求配置的 HTTPS 校验接口，按可信响应提取 active 与 tenant 等字段。本项目没有对应外部身份系统的登录/Token 签发接口，不能用随机字符串或自行签名 JWT 代替现有身份服务承认的 Token。准确配置以运行时环境和 `config.yaml` 为准。

`AI_AGENT_CONSOLE_SESSION_KEY` 是服务端会话 Cookie 的 AES-GCM 加密/校验密钥，不是登录 Token，不替代 Bearer 认证。要求标准 Base64 解码后为 32 字节；可用 `openssl rand -base64 32` 生成一次并保存至秘密管理或受保护的环境配置。多个实例须一致、更换后旧会话失效，不要每次启动重新生成，也不要提交 Git 或发送到聊天。

## 本机登录报错排障

用户报告：

```json
{"error":"console session is not configured"}
```

源码在 Bearer 校验通过、创建加密 Cookie 失败时返回该错误。重点检查运行进程读取到的 `AI_AGENT_CONSOLE_SESSION_KEY` 是否缺失、Base64 非法或解码长度不为 32；不是通过更换 Bearer Token 来修复此配置错误。此处理顺序不代表完整真实身份/权限验收已经完成。

本次只读检查的快照（本机时间）：

- 项目 `.env` 中有一个该变量定义，非空，格式符合 Base64/32 字节；只检查元数据，未输出密钥。
- 8088 服务工作目录为项目根目录；当时进程启动于 22:35:54，`.env` 最后修改于 22:42:01。
- `.env` 在启动时通过 `godotenv.Load` 加载，已有进程环境变量优先；普通配置热重载不会重新加载 `.env`。

上述时间差支持“运行进程可能尚未加载新配置”的判断；本次没有读取实际进程密钥值，也没有重启在线服务。已建议用户在原 IDE/终端停止并重新启动，再刷新 `/console` 登录。若仍报错，检查 IDE/启动脚本是否以同名环境变量覆盖 `.env`，以及工作目录/环境文件是否正确。**当前状态是待用户确认，不能记为已修复或登录成功。**
