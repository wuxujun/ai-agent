## 已验证行为

生命周期配置把模型请求超时设为 60 秒、run-all 上限设为 120 秒；mock 的 hold 场景等待 120 秒，不提前发送响应头。模拟服务统计 active_holds、aborted_holds，只有服务端连接确实关闭且响应未正常完成时才记录中断。这样取消和关闭在远早于超时的时间完成，不能归因于三秒自然超时。

| 操作 | 最终实测 | 状态及证据 |
|---|---|---|
| 排队时 DELETE cancel | 0.006 秒 | failed / client_cancelled，未增加模型请求 |
| 执行时 DELETE cancel | 0.063 秒 | failed / client_cancelled，error_code=task_canceled；依赖连接已中断，终态 SSE 可读 |
| 活跃请求期间 SIGINT | 0.041 秒 | 候选退出码 0；依赖连接中断，端口释放 |
| 同库重启 | 无额外模型调用 | 原成功任务和答案保留；两条取消任务仍 failed / client_cancelled；关闭中断任务为 paused / shutdown_rollback |
| 显式 run-all 恢复 paused 任务 | completed | 新增一次正常模型请求，固定答案一致，等待连接为 0、未知依赖为 0 |

没有自动重试取消任务，也没有声明暂停任务会自动执行。两次启动日志均绑定候选版本，候选哈希保持。最终应用与模拟服务退出码均为 0、端口关闭；报告为 `/private/tmp/ai-agent-candidate-local-wd9ax0qm/result.json`，同目录保留日志和临时 SQLite；汇总为 `/private/tmp/ai-agent-candidate-lifecycle-20261025-final.log`。

## 未通过尝试与工具边界

首次夹具误将运行中 API 取消的 termination_kind 预期为 user_cancelled。源码和实际记录表明该路径使用 client_cancelled，user_cancelled 是孤立任务取消路径的类型；已修正测试预期，没有放宽 failed、error_code、持久化及连接中断断言。本轮未更改此现有语义。

第二次通过本地 Postman simulation 转发时，候选已经记录 context canceled 并保存取消状态，但转发层至 mock 的等待连接未在三秒观察窗口关闭。因此该运行不通过连接中断验收，不能宣称 Postman 转发路径取消完整。记录保留在 `/private/tmp/ai-agent-candidate-local-dq_ndir_/result.json`。转为同一 mock 直接 HTTP 验证候选与依赖之间的取消传播，没有绕过 TLS 或修改生产配置。模拟契约仍来自仓库 planner，不代表供应商的取消/计费行为。

首次直接运行的应用检查通过，但 Node 默认 SIGINT 退出码 -2，使整体清理检查失败。已增加仅关闭自身 HTTP server/连接的信号处理，最终完整重跑退出码均为 0。失败尝试不计为通过。原 Postman 故障路径另外回归，不用直接 HTTP 成功覆盖其取消限制。
