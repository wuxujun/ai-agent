## 跨入口与失败回归

| 场景 | 检查内容与边界 |
|---|---|
| 两个 Handler 并发 `/run` 与 `/run-all` | 使用独立 active map、共同专用 SQLite；恰一方成功、一方 409、Planner 一次、唯一 attempt complete；专项连续五次验证，不代表两个真实独立生产进程/写者 |
| 审批 owner 清理期间竞争 | 另一个 Handler 的 JSON/SSE `/run`、`/run-all` 均由 durable protocol 拒绝；直接 Engine 无 scope 拒绝；peer 审批 dispatcher 不能抢占旧 owner |
| Shutdown 超时 | 返回 deadline，保留 cleanup 中的 token、attempt 与 lease；不走 legacy rollback，不把超时当 stopped；原 owner 随后仍可完成清理 |
| 真正 SQL 写入失败 | callback 保持 task/tenant 身份，写入 NaN 触发 NOT NULL 失败；事务内较新 Goal 不落库；exit 已记录、cleanup 仍执行，flush/cleanup 完成摘要不提交，lease 保留 |
| 执行/cleanup 阶段 ownership loss | 显式触发 fixture monitor.Lose；执行阶段失效不做最后 flush，cleanup 阶段失效不 finalize，两者仍尝试 detached cleanup。此项是 monitor 失效传播测试，不是生产网络分区/主机隔离验收 |
| 自然到期 | fixture 停止 renewal 后真实 TTL 到期，stale scope 不 flush、不完成，新的 attempt 也不能替换 unresolved；不能以 TTL 到期自证停止 |
| cleanup 超时后返回合法摘要 | 等待真实 10 秒 cleanup deadline 后返回格式合法摘要，仍拒绝确认与 finalize |
| SSE cleanup 错误/panic | `/run`、`/run-all` 均不向本响应发送成功 terminal；不输出 fixture 私有错误文本，attempt 保持 exited/unresolved |

测试均使用 fake Planner/Executor/Cleanup；NaN 失败发生在专用 SQLite 实际写入路径，不修改 schema 或使用在线数据库。

## 强制终止子进程

测试父进程只终止自己启动的测试二进制子进程。子进程使用全新私有 SQLite，先提交对应边界，再发送 ready marker 并等待；父进程 `Process.Kill`，不执行任何 child defer 或 Store.Close。父进程等待退出后，只对专用库进行 SQLite 正常重开/可能的 hot journal 恢复，再用保留的本地 pin 只读核验。该 pin 是 fixture 绑定，绝非独立权威。

| Kill 边界 | 重开后的预期 |
|---|---|
| prepared scope 已登记/reload，未执行 | running attempt，无 exit/flush/cleanup 摘要，原 Task 不变 |
| 执行 callback 中，结果仅在内存 | running attempt，内存修改不落库，无 exit/flush/cleanup 摘要 |
| exit 与最后 flush 后，cleanup callback 内 | exited attempt，最后 Task 已持久化，但未提交 flush/cleanup 完成回执 |
| finalize 已提交 | complete attempt，exit/flush/cleanup 摘要和 lease absent 一起保留；gate 仍 open，不因此生成 stopped 权威证据 |
| 批准消费 CAS 后、fake effect 前 | approval consumed、Task 仍 awaiting_approval、无 trace/副作用 marker；没有自动重放许可 |
| fake effect 后、Task checkpoint 前 | approval consumed、专用 marker 存在，但 Task/trace 尚未保存；没有退出/cleanup 回执，不自动重放消费过的动作 |

未完成边界的 task lease 在随后自然到期后仍为 expired-unresolved，attempt/摘要保持不变；普通重开 Store 也无法通过普通 lease 绕过专用 gate。审批自己的 consumption lease 未被本测试等同于 task lease，也没有补造其清理/权威回执。审批窗口的 fake executor 只写专用 marker，不执行任何真实工具；重开后原 RecoverApprovedApproval 入口拒绝 consumed 记录，不能以缺 trace 为由重复副作用。

这里没有测试任意 SQLite 指令中途断电、文件系统/磁盘耐久故障、真实子进程/容器残留对账或宿主机隔离；也没有在全部 HTTP/SSE/启动入口分别 kill 一个完整 server。专用 writer 的可信重开/恢复还未提供，普通 Store 重开不等于已接入 owned 生产重启。不得把本矩阵升级为全覆盖 crash/stopped 验收。
