# 只读归档候选评估接口

日期：2026-10-12。已实现管理员只读诊断入口及分页/预算回归，未实现归档执行、源记录移除或自动清理。没有修改运行配置、扫描真实业务库或提交部署。

## 请求与权限

```http
GET /api/retention/tasks?tenant_id=tenant-a&hot_days=30&limit=20&byte_budget=65536
X-API-Key: <administrator credential>
```

该路由位于既有 AccessLog/recovery/error/tracing、Console session、Auth 和 AdminMiddleware 覆盖中。只有经服务端验证的管理员可调用；普通租户返回 403，未认证返回 401。`X-Admin`、body 角色或查询参数不能授予权限。管理员也必须明确提供已配置 tenant_id，不支持跨租户全扫描；default 管理身份可明确查询 default 范围，历史空 tenant_id 不自动视为 default。

| 参数 | 契约 |
|---|---|
| tenant_id | 必填、服务配置中已知租户；未知/缺失返回 404 |
| hot_days | 可省略，省略产生 retention_period_unset；提供时 1–3650，不改变运行保留策略 |
| limit | 默认 20，1–50；后端最多读取 limit+1 条元数据供下一页判断 |
| byte_budget | 默认 65536，4096–1048576；约束整个成功 JSON 响应，不是 Task/归档大小上限 |
| cursor | 最长 2048 字符，绑定租户与本次 hot_days/hold 集合/策略版本 |
| hold_task_id | 可重复，最多 20 个，每个最多 256 字节；只增加阻止原因，不能替代服务端 hold 策略 |

非法/重复的单值参数、未知参数（包括 dry_run=false）、格式损坏的 query/cursor 或改变策略后复用游标返回 400。普通 GET 不接受写入模式。每次读取最多 5 秒；接口错误只返回固定消息，不包含后端正文或凭据。

## 响应与分页

```json
{
  "read_only": true,
  "execution_ready": false,
  "policy_version": "diagnostic-v2",
  "tenant_id": "tenant-a",
  "hot_days": 30,
  "assessed_at": "2026-10-12T12:00:00Z",
  "items": [
    {
      "task_id": "task-example",
      "tenant_id": "tenant-a",
      "status": "failed",
      "created_at": "2026-09-01T12:00:00Z",
      "updated_at": "2026-09-02T12:00:00Z",
      "trace_count": 12,
      "lease_active": false,
      "approvals_unresolved": false,
      "assessment": "unknown",
      "terminal_age_source": "unavailable",
      "content_hash": null,
      "estimated_task_bytes": null,
      "reasons": ["unknown_terminal_age", "hold_policy_unverified", "task_size_unverified", "joint_snapshot_unverified"]
    }
  ],
  "count": 1,
  "limit": 20,
  "byte_budget": 65536,
  "has_more": false,
  "next_cursor": ""
}
```

响应可包含 terminal_since、last_maintenance_at 和字符串 maintenance_version；时间缺失或时钟异常时 terminal_age_source=unavailable，否则为 store_lifecycle。示例保留历史年龄未知任务的形式。响应只包含有界元数据和原因，不返回 goal、答案、Trace/evidence、审批 payload、workspace、创建者个人身份或其他正文。成功响应为 `Cache-Control: no-store`。内置后端已持久化 terminal_since / last_maintenance_at / maintenance_version，可信且满足最近维护保留窗口后仍缺少联合内容版本/hold/导出大小证据，因此本阶段只会产生 blocked/unknown，**不会返回 eligible，也不能据响应执行移除**。updated_at/created_at/recorded_at 不用于猜测终态年龄，content_hash 不用 metadata hash 代替。

按 created_at DESC、ID DESC 排序，游标排他。响应超过字节预算时在条目边界截短，以最后一个实际返回记录生成 next_cursor；下一页不会跳过被截掉的记录。若首条元数据也无法放入预算则 413。返回条目和 limit+1 预读记录都检查租户/ID/时间；异常适配器的跨租户预读不能泄露 has_more 提示。页间不是事务快照，写入/插入仍可能改变后续观测，游标不是授权 token、冻结清单或 purge CAS。

## 分类原因

| 原因 | 状态/含义 |
|---|---|
| task_not_final | blocked：created/running/awaiting_approval/paused |
| partial_may_resume | blocked：partial 可能恢复 checkpoint |
| unrecognized_task_status | blocked：未知状态不作为归档候选 |
| requested_hold | blocked：本次请求明确 hold |
| active_execution_lease | blocked：观测到活动 lease |
| unresolved_approvals | blocked：审批尚未 consumed/expired；approved/rejected 也不自动视为消费闭合 |
| lease_state_unverified / approval_state_unverified | unknown 条件：后端不能给出可信观察 |
| session_dependency_unverified / trace_count_unverified | unknown 条件：session 依赖或 Trace 数量未验证 |
| retention_window_not_elapsed | blocked：可信最近维护尚未满指定保留窗口 |
| retention_period_unset / unknown_terminal_age | unknown 条件：缺少期限/可靠终态时间 |
| hold_policy_unverified / task_size_unverified / joint_snapshot_unverified | unknown 条件：缺少全局 hold、完整导出大小与联合版本 |

有任何 blocked 条件时 assessment 为 blocked，同时保留 unknown 原因；否则为 unknown。明确 hold 不是执行授权，设定 hot_days 也不会把未知年龄提升为可信年龄。

## 后端与只读边界

`TaskRetentionReader` 为可选 Store 能力，未实现的自定义适配器返回 501，不回退到可能修复索引的摘要 API。后端不可用、未知/损坏读模型、超限字段或返回错租户时为脱敏 503，不能伪装成空页。

Memory 在同一读锁内选取有上限的元数据页、读取 Trace 数量和 lease，并检查未闭合审批；不深复制 Task/Trace。扫描仍随任务/审批总量增长，通过请求上下文取消限制。SQLite/PostgreSQL 单条参数化查询只选择元数据和关联 COUNT/EXISTS，不加载正文/审批密文；SQL 仍可能扫描该任务的 Trace 索引来计数，不能当作 O(1) 扫描。

Redis 使用 [EVALSHA_RO/EVAL_RO](https://redis.io/docs/latest/commands/eval_ro/)（需要支持该能力的 Redis 7+），仅读取既有摘要索引、摘要字段和 lease TTL；不调用 ensureTaskSummaryIndexes，不读取完整 Task/Trace，也不做索引修复。缺少两个既有迁移 marker、缺失/错位摘要或单条摘要 JSON 超过 64 KiB 时返回 503，由独立运维流程处理。本入口不会使旧读模型自动可用。

Redis 的 approvals_unresolved、trace_count 为 null，分别标记未知；缺少 TTL 的 lease 也为 null，不能当作无活动租约。Redis 使用已有索引状态，混合旧写入者可能使其滞后；它仍只是诊断观察，joint_snapshot 始终未验证。没有声称 Redis Cluster、只读副本和真实混合版本集群验收。
