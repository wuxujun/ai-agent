# 用户 6492 的跨租户审批能力

**2026-10-24 更新：已新增 `TestExternalCrossTenantAuthAcceptance` 独立验收入口，操作及本地验证见文末。** 原同租户入口保持严格契约；此前“须提供独立入口”为历史待办。真实身份与目标数据库在线验收仍为 NOT_RUN。

用户已明确确认：真实身份服务的 `data.userid` 是个人用户 ID，同时用作应用中的租户隔离 ID；`6492` 可以跨租户批准和拒绝其他人的任务，但不能审批自己创建的任务。

本次实现该能力的可配置入口，**未启用运行配置、未重启或部署，真实身份审批验收仍为 NOT_RUN**。审批授权来自本地已审核名单，不从上游 `admin/roles`、请求体或请求头推断；代码没有硬编码 6492 特权，也没有赋予管理员权限。

## 配置契约

新增 `api.tenants.<tenant>.approval_cross_tenant`，默认 `false`。只有启用该开关、`approval_mode: actors`、`approval_disallow_self: true`，且经过认证的个人 ActorID 精确匹配该租户名单，才可访问其他租户的 `POST /api/tasks/:id/approve` 和 `/reject`。配置还必须要求 Bearer 个人身份。错误候选拒绝重载，保留原快照及 revision；有效撤权在后续请求生效，已缓存身份不能保留撤销的能力。

以下是供审核的**配置片段**，不是可以替代完整运行配置的文件：

```yaml
api:
  auth:
    bearer:
      require_subject: true
    introspection:
      tenant_claim: data.userid
      subject_claim: data.userid
  tenants:
    "6492":
      admin: false
      approval_mode: actors
      approval_disallow_self: true
      approval_cross_tenant: true
      approval_actor_ids:
        - introspection-sub:d7fdba6d3c45837bca943c3f
```

该摘要按既有算法 SHA256(`"6492" + NUL + "6492"`) 的前 12 字节计算。字段语义由用户确认；真实服务是否返回字符串 `"6492"`、active/issuer/audience/exp 的实际格式和值仍待契约核验。当前解析器要求 userid 为字符串，不会自动把数字或任意字段强制转换为可信身份。不要为运行该片段关闭既有身份、URL/私网、已知租户或 workspace 校验；完整候选仍需保留审核后的 HTTPS 端点、可信 metadata 检查和各用户范围。

开关只允许审批决策。跨租户任务详情、Trace、SSE、审批列表、运行、重审、取消、删除、会话及管理接口保留原有边界。调用者需要从合法业务流程获得目标 task ID / approval ID，本批没有提供跨租户浏览或待办列表。审批成功响应沿用原接口，包含原审批请求及结果消息。

跨租户授权人员在所有目标上都必须满足个人创建者与审批者不同，即使目标租户没有启用禁止自批；历史任务的创建者缺失或不是有效个人 ActorID 时返回 403，不补写或猜测创建者。普通用户的审批权限仍按其原租户策略执行；若要禁止其他用户自批，须在对应租户启用 `approval_disallow_self`。撤销跨租户能力可设为 `approval_cross_tenant: false`；如同时改为 `deny`，也应关闭该开关，避免形成非法候选。

显式 `approval_id` 必须属于 URL 中的任务。HTTP 本地解析和集群接收端都进行任务绑定；其他任务的 ID 不会被解析，也不会回退为解析另一条审批。该检查同时防止用其他任务的路径绕过自批限制。

## 验证与边界

本地回归包含：跨租户 approve/reject，显式/隐式审批 ID，API 创建者捕获，持久化加密决策及审计身份，未授权/失效/缺失凭据拒绝，静态密钥与伪造角色不能取得个人授权，自批和刷新 token 拒绝，历史未知创建者拒绝，Console Cookie/CSRF，跨租户读取/执行/管理权限保持隔离，缓存身份下撤权及决策前撤权，错误任务审批 ID、Redis 消息任务绑定，配置启用/撤权及非法重载保留快照。

真实身份服务验收入口 `TestExternalProductionAuthAcceptance` 保留原来“独立个人字段、同租户多人”的严格契约，没有为了此次按用户隔离模式而放宽它。其五凭据流程不能直接验证当前业务模式；后续须针对 creator 与 reviewer 属于不同 userid 的模式提供独立的真实身份入口，并核验审核候选。此前同租户 reviewer/unlisted 的凭据要求不再直接适用于本模式。

## userid 同字段的独立验收入口（2026-10-24）

新增 [cross_tenant_auth_acceptance_test.go](../internal/api/cross_tenant_auth_acceptance_test.go)，原入口 `TestExternalProductionAuthAcceptance` 仍要求 subject 与 tenant 字段不同。新入口只接受 `tenant_claim: data.userid`、`subject_claim: data.userid`，使用三位不同用户作为 creator、reviewer 和 unlisted。用户 ID 由环境提供，没有在入口中硬编码 6492 特权。

新入口要求独立、已审核的配置文件：纯 introspection、HTTPS 真实端点、issuer/audience/有效期/已知租户检查、禁私网、身份缓存为零、强制个人身份与 workspace 隔离，且没有静态管理密钥或 admin 租户。三位用户都须有明确的 workspace/Team/Wiki 范围，配置 `approval_mode: actors`、`approval_disallow_self: true`，名单包含各自按既有算法生成的个人 ActorID；三者中仅 reviewer 开启 `approval_cross_tenant`。这是本验收夹具的严格前提，不表示生产环境的所有用户必须具有相同审批策略。unlisted 指没有跨租户能力的已认证用户，不能用“未知用户被认证拒绝”代替越权验证。

所需环境变量如下；凭据通过本地秘密管理或安全的环境注入提供，不放入命令参数、Git、报告或聊天：

| 变量 | 含义 |
|---|---|
| `AI_AGENT_AUTH_ACCEPTANCE_CONFIG` | 已审核的独立 YAML 路径；不自动加载 `.env` 或环境配置覆盖 |
| `AI_AGENT_AUTH_ACCEPTANCE_TENANT` | creator 的 userid/租户 ID |
| `AI_AGENT_AUTH_ACCEPTANCE_REVIEWER_TENANT` | reviewer 的 userid/租户 ID，例如审核确认后的 6492 |
| `AI_AGENT_AUTH_ACCEPTANCE_UNLISTED_TENANT` | 没有跨租户授权的第三位 userid/租户 ID |
| `AI_AGENT_AUTH_ACCEPTANCE_CREATOR_TOKEN` | creator 专用有效凭据 |
| `AI_AGENT_AUTH_ACCEPTANCE_REFRESHED_TOKEN` | 同一 creator 刷新后的另一份有效凭据 |
| `AI_AGENT_AUTH_ACCEPTANCE_REVIEWER_TOKEN` | reviewer 专用有效凭据 |
| `AI_AGENT_AUTH_ACCEPTANCE_UNLISTED_TOKEN` | 第三位用户的有效凭据 |
| `AI_AGENT_AUTH_ACCEPTANCE_EXPIRED_TOKEN` | 已过期的专用凭据 |

五份凭据必须不同、非空、无空白及控制字符，且符合 Console 的 2500 字符限制。注入后显式执行：

```sh
AI_AGENT_RUN_CROSS_TENANT_AUTH_ACCEPTANCE=true GOARCH=arm64 go test ./internal/api -run '^TestExternalCrossTenantAuthAcceptance$' -count=1 -v -timeout 120s
```

只有该命令显式开启后才会通过生产认证客户端访问审核配置中的真实身份服务。测试在进程内注册 API/Console 路由，使用 Memory Store、临时 Console 会话密钥和测试审批加密密钥：确认三位用户的 userid/ActorID、creator 刷新稳定性、过期/缺失凭据拒绝、创建者捕获、两种入口的 approve/reject、CSRF、自批/越权拒绝、跨租户读取隔离、加密决策与通知身份，并模拟撤销本地跨租户开关后的拒绝。它不会启动服务、执行任务/工具、恢复旧任务、修改运行配置或部署；撤权仅修改进程内测试快照，不是线上热重载验收。失败只打印阶段及状态，不输出凭据和响应正文。

该入口通过也只证明真实身份服务与本地路由/Memory Store 组合，不能替代真实浏览器、代理/TLS/SSE、目标数据库的审批 CAS/重启持久性及实际生效配置验收。普通全仓测试跳过外部入口；跳过不能计为真实身份通过。本次只运行本地合成身份夹具及配置前检，没有读取已有凭据或调用真实身份端点。
