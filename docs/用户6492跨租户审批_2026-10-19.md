# 用户 6492 的跨租户审批能力

用户已明确确认：真实身份服务的 `data.userid` 是个人用户 ID，同时用作应用中的租户隔离 ID；`6492` 可以跨租户批准和拒绝其他人的任务，但不能审批自己创建的任务。

本次实现该能力的可配置入口，**未启用运行配置、未重启或部署，真实身份审批验收仍为 NOT_RUN**。审批授权来自本地已审核名单，不从上游 `admin/roles`、请求体或请求头推断；代码没有硬编码 6492 特权，也没有赋予管理员权限。

## 配置契约

新增 `api.tenants.<tenant>.approval_cross_tenant`，默认 `false`。只有启用该开关、`approval_mode: actors`、`approval_disallow_self: true`，且经过认证的个人 ActorID 精确匹配该租户名单，才可访问其他租户的 `POST /api/tasks/:id/approve` 和 `/reject`。配置还必须要求 Bearer 个人身份。错误候选拒绝重载，保留原快照及 revision；有效撤权在后续请求生效，已缓存身份不能保留撤销的能力。

以下是供审核的**配置片段**，不是可以替代完整运行配置的文件：

```yaml
api:
  auth:
    bearer:
      require_subject: true
    introspection:
      tenant_claim: data.userid
      subject_claim: data.userid
  tenants:
    "6492":
      admin: false
      approval_mode: actors
      approval_disallow_self: true
      approval_cross_tenant: true
      approval_actor_ids:
        - introspection-sub:d7fdba6d3c45837bca943c3f
```

该摘要按既有算法 SHA256(`"6492" + NUL + "6492"`) 的前 12 字节计算。字段语义由用户确认；真实服务是否返回字符串 `"6492"`、active/issuer/audience/exp 的实际格式和值仍待契约核验。当前解析器要求 userid 为字符串，不会自动把数字或任意字段强制转换为可信身份。不要为运行该片段关闭既有身份、URL/私网、已知租户或 workspace 校验；完整候选仍需保留审核后的 HTTPS 端点、可信 metadata 检查和各用户范围。

开关只允许审批决策。跨租户任务详情、Trace、SSE、审批列表、运行、重审、取消、删除、会话及管理接口保留原有边界。调用者需要从合法业务流程获得目标 task ID / approval ID，本批没有提供跨租户浏览或待办列表。审批成功响应沿用原接口，包含原审批请求及结果消息。

跨租户授权人员在所有目标上都必须满足个人创建者与审批者不同，即使目标租户没有启用禁止自批；历史任务的创建者缺失或不是有效个人 ActorID 时返回 403，不补写或猜测创建者。普通用户的审批权限仍按其原租户策略执行；若要禁止其他用户自批，须在对应租户启用 `approval_disallow_self`。撤销跨租户能力可设为 `approval_cross_tenant: false`；如同时改为 `deny`，也应关闭该开关，避免形成非法候选。

显式 `approval_id` 必须属于 URL 中的任务。HTTP 本地解析和集群接收端都进行任务绑定；其他任务的 ID 不会被解析，也不会回退为解析另一条审批。该检查同时防止用其他任务的路径绕过自批限制。

## 验证与边界

本地回归包含：跨租户 approve/reject，显式/隐式审批 ID，API 创建者捕获，持久化加密决策及审计身份，未授权/失效/缺失凭据拒绝，静态密钥与伪造角色不能取得个人授权，自批和刷新 token 拒绝，历史未知创建者拒绝，Console Cookie/CSRF，跨租户读取/执行/管理权限保持隔离，缓存身份下撤权及决策前撤权，错误任务审批 ID、Redis 消息任务绑定，配置启用/撤权及非法重载保留快照。

真实身份服务验收入口 `TestExternalProductionAuthAcceptance` 保留原来“独立个人字段、同租户多人”的严格契约，没有为了此次按用户隔离模式而放宽它。其五凭据流程不能直接验证当前业务模式；后续须针对 creator 与 reviewer 属于不同 userid 的模式提供独立的真实身份入口，并核验审核候选。此前同租户 reviewer/unlisted 的凭据要求不再直接适用于本模式。
