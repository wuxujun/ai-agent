更新日期：2026-10-13。基于 `5052421` 与上一轮未提交的只读密钥检查器续作；本次实现签名来源证明的离线验证；代码、测试与本文随本批提交，提交标识以 Git 记录为准，未推送、未部署。保留现有工作区改动。主交接：[密钥核验续作](Task密钥管理只读核验续作_2026-10-13.md)、[恢复验证交接](Task恢复验证续作交接_2026-10-12.md)。

## 核验范围

现有 AES-GCM v1/v2 没有身份 AAD；解密成功只能证明密钥可用、动作与 resolution 符合格式和状态契约。本次增加独立的 Ed25519 来源签名，核验完整审批清单与联合包的关系，不改变密文格式或在线审批生命周期。

只有独立配置的可信来源公钥、来源 ID、租户与期望源快照 ID 全部匹配，签名及每条记录摘要正确，且证明仍在有效期内，才报告 `source_binding=verified`。密钥可用并实际解密检查也通过时，`key_management` 可以进入 `verified_evidence`。单独的解密检查仍保持来源 unverified。

签名证明只说明可信来源对某个快照中记录归属的声明，不证明审批当前有效、执行授权、副作用完成、旧租约可用或动作可重放。`approvals_and_effects` 等其他未接入类别保持 missing/unverified；整体仍 `blocked`、`restore_ready=false`、`source_preserved=true`，CLI 正常完成诊断仍退出 3。

## 独立信任配置

应用代码通过 `TaskRestoreApprovalSourceTrustProvider` 注入信任。CLI 只在明确选择 `--approval-source-trust environment` 时读取以下环境值：

| 环境变量 | 含义与限制 |
|---|---|
| `AI_AGENT_RESTORE_APPROVAL_SOURCE_PUBLIC_KEY` | 来源 Ed25519 公钥，标准 base64 编码的 32 字节；输入最多 128 字节 |
| `AI_AGENT_RESTORE_APPROVAL_SOURCE_ID` | 可信来源 ID，1–256 字节可打印 ASCII，无空白/控制字符 |
| `AI_AGENT_RESTORE_APPROVAL_SOURCE_TENANT` | 该来源公钥获授权的单一租户，1–256 字节，必须与实际租户及证明一致 |
| `AI_AGENT_RESTORE_APPROVAL_SOURCE_SNAPSHOT` | 从独立来源或控制面确认的期望快照 ID，1–256 字节可打印 ASCII |

公钥和这些 pins 必须通过独立可信渠道配置，不能照抄待核验 JSON 的自报字段或从依赖清单提取。签名权威必须从其权威源独立读取数据并声明完整清单，不能给上传者自造、仅内部一致的沙箱包背书。控制这些信任配置的调用方属于信任边界；签名本身不能验证配置操作者是否可信。

提供者对上述环境值直接进行内存比较；任何变化，包括公钥撤销、租户/来源/快照变化，都产生新的随机不透明版本。版本必须是 64 字符小写十六进制，不是密钥派生指纹。新实例/进程创建新版本，跨 CLI 调用的旧清单主动失效。读取前后、CheckEvidence 与评估结束均复查；额外比较来源、公钥及 scope，避免扫描期间提供者状态改变。

环境提供者只观察本进程可见的环境状态，不提供远程全局撤销监视，也不能证明两个观察点之间短暂改变后恢复的状态。外部可信提供者应从真实权威控制面取得当前版本、scope 和撤销信息，遵守取消与配额契约。当前未实现外部权威服务、源侧签名服务或生产信任配置上线；本次验收使用独立的本地测试签名密钥。

## 证明格式与签名契约

schema 为 `task-restore-approval-source-v1`。`TaskRestoreApprovalSourceEvidence` 只有 `content` 和 base64 编码的 `signature`；证明内不接受验证公钥、私钥、文件路径或信任配置。严格拒绝未知字段、重复 JSON 键、尾随数据、错误签名长度、null 清单和超配额输入。

`content` 按 Go 结构体固定顺序包含 schema、source_id、snapshot_id、tenant_id、task_id、payload_sha256、created_at、expires_at 和 approvals。审批清单按 approval_id 严格递增，数量必须与独立沙箱记录一致；最多 1000 条，证明输入最多 1 MiB。每条记录绑定：

- 审批 ID、Task/tenant、Request ID、Version、Status、Request.Action。
- ActionPayload 与 ResolutionPayload 的原始密文字节 SHA-256；缺失 resolution 使用空字节串的 SHA-256。
- 完整 DurableApproval 的规范化 JSON SHA-256，包括 Request 预览、时间、Owner 和 LeaseExpiresAt。

`TaskRestoreApprovalSourceRecordFor` 给出完整记录摘要契约：对 `encoding/json(DurableApproval)` 使用既有 `canonicalRestoreJSON`，保留 json.Number 的整数精度。此函数不解密，也不赋予输入来源权威。版本和参数中的大整数必须保持原值，不能经过浮点数中转。

`TaskRestoreApprovalSourceSigningBytes` 是唯一签名字节契约：UTF-8 域分隔符 `ai-agent/task-restore-approval-source/v1` 加换行，再追加 Go `encoding/json` 对固定 `TaskRestoreApprovalSourceContent` 的编码。来源侧应使用此函数或完全兼容的实现；普通 JSON 排序器、不同时间格式或任意原始 JSON 字节不等价。本仓库离线命令不接受私钥，不提供签名动作。

签名覆盖联合包 payload_sha256、完整清单和 source snapshot ID，因此跨租户/任务替换、遗漏/追加记录、Action/Resolution 调包、改状态/版本或脱敏预览都会失败。上传者即使重算全部普通摘要，也不能更新来源签名。已签名的空清单可以证明来源声明的无审批；若明确选择来源证明，空数据库也不能绕过错误签名或不可用信任。

证明有效窗口最多 15 分钟，不接受未来创建时间、过期或无效窗口。可信观察的失效时间取当前检查五分钟窗口与来源证明 expiry 的较早者，评估结束时再检查时效，不延长来源证明寿命。

## 离线使用与状态绑定

```bash
go run ./cmd/task-restore assess \
  --directory DEDICATED_SANDBOX --task TASK --tenant TENANT \
  --key-source environment \
  --approval-source-evidence SIGNED_PROOF.json \
  --approval-source-trust environment
# 可同时增加 --workspace-evidence BASELINE.json。
# 加密密钥、公钥与信任 pins 从独立环境/秘密管理注入，不放入 CLI 或证明文件。
```

两个来源参数必须同时出现，并且同时选择密钥提供者。旧入口及不选择来源证明时的行为保留。应用侧新入口为 `AssessPersistentTaskRestoreAdmissionWithOptions`，旧 WithWorkspace/WithKeys 包装器继续可用。

选择来源证明时摘要 schema 为 `task-restore-key-management-v2`；成功原因码是 `source_and_decryption_verified`，签名/scope/记录不符为 `source_evidence_conflict`，不可用信任或无效时效为 `source_evidence_unverified`。JSON/结构/参数错误返回通用读取/核验失败，不输出原始秘密管理错误、签名、公钥指纹、来源身份、快照 ID、记录摘要或明文。

证据摘要包含来源证明摘要、随机信任版本与验证状态；再与当前数据库指纹（含独立审批内容）、加密密钥版本及 workspace 状态组合绑定。policy 版本为 `read-only-source-keys-v1`，同时选择 workspace 时为 `read-only-workspace-source-keys-v1`。旧清单绑定、source pins 更新、撤销、密文/证明变化及过期都会使旧证据失效。

核验器只读现有专用 SQLite 和显式证明/基准输入；不初始化在线 Store、执行器、模型、索引或网络客户端，不改写密文、审批状态或租约，不修复热日志，不清理源。源证明文件读取沿用文件身份及预算检查，所有内存对象均受既有导出配额或新增证明配额约束。
