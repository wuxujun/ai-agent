## 作用域与可信来源

首批设计采用保守范围：恢复单个任务的诊断，覆盖其完整会话成员，以及可信依赖目录明确列出的跨任务边。会话内任一成员缺失、并发变化或归属不明，均阻止该类别通过。检查点节点图与跨任务依赖图分开验证；无法识别的运行模式/依赖契约保持 unverified。

必须区分三个独立观察对象：

1. **导出时源基准**：由独立源侧权威在一致快照内记录完整成员、关系、任务内容摘要、会话高水位及观察版本，并绑定原 v2 payload hash。事后对包内单任务生成摘要不能补证导出时完整性；没有历史基准时，旧包继续 unverified，不能从当前源状态倒推历史。
2. **当前源状态**：只读观察源任务、会话和依赖目录，及租约、调度/执行器隔离状态。源身份由操作者可信配置选定；声明不能指定连接、提供者或公钥。首批要求与已绑定基准相符；合法源变化也要求重建证据，不能静默合并。
3. **当前目标状态**：现有专用 SQLite 沙箱仅证明单任务导入保真。完整依赖目标必须另有可信只读观察，检查成员可用性、ID/序号冲突与租户隔离；未来在线目标不能借用离线沙箱的 target_id。

独立操作者选择的本地基准可以用于契约回归，但不能称为真实源权威。带有效签名的历史快照只能证明历史观察；当前撤销状态、源变化和旧执行器隔离仍须重新核对。提供者访问身份、权限、时钟与撤销版本必须来自可信控制面。

## 拟新增只读接口

建议新增窄接口 `TaskRestoreSessionDependencyReader`、`TaskRestoreExecutionObservationReader`，不扩展成通用可写 Store。以下是设计名称，源码尚无这些定义。

输入为经严格 v2 校验取得的 task/tenant/payload hash、可信代码选择的源与目标身份、预算及 context。不得接收声明中的 DSN、URL、文件路径、owner 或“已验证”标志。返回不可变观察及可信来源版本；无接口/不可达/超预算/无法保证快照完整性返回无法核验，不能返回空集合成功。

| 会话观察字段组 | 必须验证的内容 |
|---|---|
| scope | source/target 身份摘要、tenant/task/session、payload hash、schema/依赖目录版本 |
| session | 记录摘要、状态、精确 int64 高水位；无会话也须核对实际 Task 与可信依赖目录 |
| members | 完整且唯一的任务 ID、tenant/session、正序号、内容摘要与持久化修订；成员数与快照完整性证明 |
| edges | 权威目录中的依赖边、方向、语义版本和闭包；重复/悬空/跨租户边拒绝，循环按已明确的依赖契约检查 |
| target availability | 每个必需成员的隔离目标记录摘要/版本、目标冲突结果；目标只有单任务而源有其他成员时不能通过 |
| revisions | 源成员目录/任务/会话/权限修订、目标成员目录修订、基准信任与撤销修订 |

不得用“没有读到边”证明“不存在依赖”。只有权威目录明确覆盖该运行模式和完整作用域，才能证明零边。无 session 的任务仍可能有其他任务依赖，不能自动跳过。序号可有空洞，但同会话不得重复、非正或超过高水位；高水位下降和成员被替换均拒绝。

| 执行观察字段组 | 必须验证的内容 |
|---|---|
| task execution | 源/目标状态与内容修订、完整检查点摘要、检查点 schema、运行时/工具/Team 配置版本 |
| lease | 所有权摘要、租约存在性、到期时间/服务端观察时间、单调所有权代次与修订；租约不复制、不续约 |
| exclusion | 权威调度阻止新派发的作用域/代次、旧执行器停止确认或受下游强制执行的 fencing 证明、撤销状态 |
| policy | 独立且版本化的恢复策略：首批只允许终态记录的只读诊断；非终态恢复及终态重跑仍待后续实现 |
| revisions | 执行器/调度/租约/策略/权限/信任修订及有效期限 |

终态采用现有 `IsTerminalTaskStatus`（completed/partial/failed），不自动授权重跑。非终态检查点即使可解析，也必须具备运行时兼容、旧执行器隔离和工具副作用核验；首批保持 unverified。任一未到期租约阻止通过；已到期或缺失租约本身也不能证明旧进程停止。下游不支持 fencing 时必须有可信停止/隔离确认，不能由本地 boolean 自证。副作用对账属于 `approvals_and_effects`，执行状态类别通过也不替代它。

## 原子观察、版本与时间

Memory 在一个读锁内复制完整成员/关系/执行状态；SQL 在同一显式只读事务内读取，PostgreSQL 使用 RepeatableRead。不调用 schema 初始化、索引修复、租约守卫 UPDATE、序号分配或恢复流程。Redis 若后续支持，应使用受限只读原子脚本并读取独立 sequence key；普通 ListTasks 分页或依赖不完整的索引不能证明全集。

首批预算建议：每次观察最多 1000 个任务、4000 条边、8 MiB 序列化数据、30 秒总期限，并限制检查点读取；计数/字节检查先于大对象复制。超过限制返回 unverified，不截断成员后声称完整。ID/版本字段、JSON、精确整数与未知状态采用严格校验，摘要使用固定排序的版本化规范编码；正文仅在受限内存中检查，不写入报告。

内容 hash 不能检测 A→B→A 后恢复原值的变化。当前 `UpdatedAt`、`MaintenanceVersion` 与 owner/expiry 都不能充当完整的单调观察代次；TTL 也不能作为稳定 revision。可信提供者必须覆盖创建/删除/重建、成员变更、任务/检查点更新、租约获取/续约/释放/自然过期、派发隔离和权限/撤销变化。没有这样的变更目录或权威代次时，不得在首批适配器中将内容指纹称为完整版本保证。

将本地沙箱/workspace/key 修订与源、目标、依赖目录、租约、隔离和信任修订按类别带名称组成规范向量，再 hash 到现有 `StateRevision`。加入新提供者时升级 PolicyVersion；旧 manifest 绑定失效。`CheckEvidence` 返回的 Binding 必须与同一观察向量一致，不能把旧缓存重新贴到新 binding。ReadState 必须在评估结束时重新观察所有有关权威。

跨数据库与调度控制面不能靠多次读取获得全局事务。采用先读权威代次、读取有界快照、再读代次的方式；任一变化拒绝。本方案只形成有时限的诊断，不宣称与未来执行原子。在线恢复仍需在执行入口建立新的身份与原子 fencing。

有效期取 manifest、各观察、信任/撤销证明、执行隔离证明中的最短期限，上限为现有 15 分钟；本地建议窗口 5 分钟。SQL 当前使用应用时钟、Redis 使用服务端 TTL，应明确时钟来源与偏差界限；未知偏差不能证明到期。过期、未来时间、检查中到期、时钟回退或自然过期改变观察语义均拒绝，不能将续约视为旧证据延长。

## 与现有准入报告衔接

只通过可信代码向 `TaskRestoreAdmissionOptions` 注入可选提供者；默认 CLI 不加载在线配置，不自动连接源或目标。CLI 真实来源选择与凭证管理另行实现，不能新增上传 manifest 自证入口。

新类别仍复用既有 `verified/missing/conflict` 观察状态。已证明的缺少必需记录为 missing；租户、关系、冲突、活动租约或策略矛盾为 conflict；缺权威、版本覆盖不全、网络错误、未知运行模式为 unverified。详细原因如需输出，应另加固定枚举摘要，不塞入原始错误、路径、owner、任务正文、检查点、凭证或连接信息。

未提供 manifest 时，可以在完成真实观察后生成类别摘要声明；摘要只来自提供者核验结果。仅生成 claim 不能升级验证状态。两类即使通过，其他五类剩余证据及在线流程未完成时仍 blocked，不签发清理或归档执行许可。

## S01 实施与回归

本轮新增 [只读依赖接口与校验](../internal/store/task_restore_dependencies.go)、[回归测试](../internal/store/task_restore_dependencies_test.go)，并通过 [可选准入参数](../internal/store/task_restore_admission_persistent.go) 接入。`TaskRestoreSessionDependencyReader` / `TaskRestoreExecutionObservationReader` 由可信代码选择，通过有界、严格 JSON 返回观察；上传 manifest 不能构造提供者。默认 CLI 参数和行为不变，未自动连接在线配置或 Store。

`NewTaskRestoreDependencyAdmissionReader` 先严格校验 v2 包，再由包内 Task、物理 Trace 和 Session/高水位分别生成预期摘要；源身份使用独立摘要 pin，目标身份来自基础只读观察。实际提供者负责认证来源、历史完整性与单调修订、撤销核验，不能仅返回操作者上传的 JSON。接口与格式校验不能代替这些权威责任；本轮仅使用 fake 提供者，未实现真实适配器。

首版限定 `complete-same-session-dag-v1`：完整同会话成员按 ID 排序，边按 from/to 排序，拒绝重复、悬空、循环、跨租户、错误序号和目标差异；合法序号空洞允许，高水位保持精确 int64/字符串编码并必须匹配包内基准。无会话仅支持单任务且零边的可信完整性观察；跨会话依赖保持 unverified。

执行观察只支持 `terminal-diagnostic-only-v1`，匹配 Task/Trace 摘要和状态；非终态保持 unverified。当前源的活动租约或目标任一租约存在均 conflict。源的过期租约只在可信提供者已证明其到期、派发禁用及旧执行器停止时可验证；格式校验不会自行访问时钟服务或提供停止证明。隔离证明必须有当前修订与有效期；未提供证明时，租约缺失/过期不能获得通过。

观察最大 8 MiB、1000 个成员、4000 条边，提供者获得预算和 30 秒 context（必须配合取消）；拒绝未知/重复 JSON 键、尾随 JSON、非法标识/版本、错误绑定及无效时间。提供者返回后立即复制，观察正文不进入报告。提供者错误和内部期限超时降为 unverified；外部调用取消传播。Go 接口无法强制终止忽略 context 的实现，实际适配器必须遵守接口约束。

组合状态摘要覆盖基础 state_revision、各类别观察摘要与状态，PolicyVersion 同时升级并保留基础策略摘要。每次类别核验前读取完整组合观察，结束后重读；基础状态/权威代次变化、检查点原位变化、信任变化、租约或隔离修订变化使旧绑定失效。原有 workspace/key 观察只在与当前基础绑定一致时才组合绑定，结束仍复查。所有权代次等单调语义由可信提供者保证，代码不会将现有存储内容 hash 冒充该保证。

无 manifest 时，可选注入的提供者产生观察摘要声明；无提供者维持原缺失/无法核验行为。假权威证据齐全可使 `evidence_complete=true`，但仍固定 blocked、restore_ready=false、source_preserved=true。该结果不证明生产依赖或在线执行准备。

## S02 实施与回归

新增 [本地只读观察](../internal/store/task_restore_local_observation.go) 与 [专项回归](../internal/store/task_restore_local_observation_test.go)。MemoryStore / SQLiteStore 实现独立 `TaskRestoreLocalObservationReader`，只读取已打开、由可信代码选择的专用 fixture Store；没有新 CLI/HTTP 入口、连接字符串或自动配置加载。**该接口不实现 S01 的两个可信权威接口**，不会被 `DependencyReaders` 自动采用。

输入必须明确非空 task/tenant，预算为 4 KiB–8 MiB、1–1000 个任务。Memory 在单个读锁内读取根任务、Session/高水位、完整会话成员、Task/物理 Trace 与各成员租约，限制扫描总任务数 20000；锁竞争使用可取消等待，不遗留等待锁的 goroutine。SQLite 使用一个只读事务，先检查根租户/Session、成员数量与字节预算，再读取完整成员和租约；不调用普通分页列表、初始化/迁移、序号分配或 UPDATE 租约守卫。没有 session 时只观察指定任务，仍不能证明外部依赖不存在。

复用 SQL 联合导出的事务内快照读取部分至 `readSQLTaskExportSnapshot`，让多个任务共享同一事务；原导出入口仍自行开始/提交事务，PostgreSQL 的 RepeatableRead 保持。Trace 读取按已预检数量 + 1 分配，避免会话中每个少 Trace 任务都为万 Trace 预留容量。

观察不返回 Task、Trace、Session 标题或 owner 正文，只返回固定 schema、作用域标识、高水位、任务状态/序号、Task/Trace/Session 摘要和租约 owner 摘要/时间/本地 active/expired/absent 状态。总输入复制与输出均受字节预算限制，总 Trace 上限 10000；返回切片独立拥有。租户/Session 不匹配、重复序号、越界/非法状态和不完整物理序列拒绝，序号空洞允许；高水位保留精确 int64 字符串编码。

`ContentSHA256` 是当前本地观察的内容指纹，包含完整成员、检查点内容及当前租约状态。它无法证明 A→B→A 历史，现有 UpdatedAt/MaintenanceVersion 不被提升为完整单调修订。结果始终 `status=unverified`，固定列出历史基准、依赖图、单调修订、旧执行器隔离及目标兼容五类缺口。租约 expired/absent 不构成停止/禁派发证明，也不赋予恢复或重跑许可。
