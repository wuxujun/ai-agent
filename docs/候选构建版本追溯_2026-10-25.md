## 验证方式

1. 本地 clone 的 HEAD 与预期提交一致，构建前后 `git status --porcelain` 为空，源副本没有 `.env`。
2. `go version -m server` 直接核对 revision、dirty、平台、CGO 和 trimpath 设置，结果保存在 go-build-info.txt；没有执行 server。
3. 版本字符串在二进制中唯一出现；对相同干净副本使用相同 linker 参数运行现有 `TestCurrentMatchesInjectedVersion`，确认 [buildinfo.Current](../internal/buildinfo/version.go) 返回核验版本，退出 0。此处只执行无服务依赖的 buildinfo 包测试，不执行应用启动逻辑。
4. `shasum -a 256 -c SHA256SUMS` 校验 server 和五份 metadata/日志，六项全部 OK。

初次核验脚本错误地要求 trimpath 构建 metadata 中必须出现 `-ldflags`，该断言失败，不计为通过。Go 1.26.9 的 `cmd/go/internal/load/pkg.go` 明确在 trimpath 模式省略 linker flags，避免记录系统路径。本轮保持 trimpath，不把缺少该字段当作注入失败；独立核验版本字符串与现有注入测试，并在 build-provenance.json 明确记录构建参数。不能宣称 `go version -m` 直接报告了应用版本。
