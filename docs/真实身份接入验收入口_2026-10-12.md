## 当前缺少的可信契约

`config.yaml` 使用 `https://api.thinktown.com/api/auth/check`，把 `data.userid` 映射为租户。历史记录描述的是应用的字段用法，没有证明身份服务将该字段定义为租户，也没有给出稳定个人字段。

需要身份服务负责人确认以下事实，可提供脱敏成功响应及错误/过期响应的契约。不要在聊天、文档或 Git 中提供真实凭证。

| 项目 | 当前应用行为 | 需要确认的内容 |
|---|---|---|
| 请求 | HTTPS GET；Bearer 通过 Authorization 传递；不转发 X-API-Key | 是否为服务支持的实际认证契约 |
| 租户 | 配置点分隔字段路径，当前 `data.userid` | 它是租户、项目还是个人？是否满足已配置租户 ID 的格式及作用域 |
| 个人身份 | 单独配置 `subject_claim`，必须是稳定非空字符串 | 真实字段路径；换 token 后是否保持；不同账号是否唯一 |
| active | 配置字段，要求布尔值 true | 实际路径、数据类型、禁用/撤销时的行为 |
| issuer | 当前实现校验顶层 `iss` | 实际值及是否确实返回顶层字段；不能从 JWT 配置推断 introspection 的 issuer |
| audience | 优先 `data.aud`，缺失时读取顶层 `aud`；字符串或字符串数组 | 实际值、类型及服务端约束 |
| expiration | 优先 `data.exp`，缺失时读取顶层 `exp`；数字 Unix 秒 | 实际路径、数字类型、时钟及过期/撤销行为 |

如果真实契约与上述解析路径不同，应先修改解析配置或实现并补回归，不能把严格约束关闭来获得“通过”。脱敏响应只能帮助确定字段类型和映射，不能证明账号唯一性、登录成功或撤销及时性。

## 验收入口及前置条件

入口是 `internal/api/production_auth_acceptance_test.go` 中的 `TestExternalProductionAuthAcceptance`。普通全仓测试默认跳过，只有 `AI_AGENT_RUN_AUTH_ACCEPTANCE=true` 才能触发外部请求。

显式指定已审核候选配置和预期租户；配置文件使用独立 Viper 读取，不加载 `.env`，不叠加应用运行环境变量。该结果适用于这个文件，不能代替正在运行实例的最终有效配置验收。

入口先检查：

- `introspection` 模式、个人 subject 要求、已知租户、独立 workspace、issuer/audience/expiration 校验。
- 个人字段与租户字段不同、成功缓存关闭、私网放行关闭、端点不是 `.invalid` 等示例占位地址。
- 无静态根管理密钥、无租户静态密钥或管理员权限。
- 目标租户具有显式 Team/Wiki 范围，审批为 `actors` 且开启 `approval_disallow_self`，名单格式有效。

严格生产示例仍默认 `approval_mode: deny`，因此不会通过允许独立审批的这一项验收。应在确认真实个人身份并审核名单后生成独立候选文件，保留原示例默认拒绝行为。Brain 未授权范围仍由原有项目校验负责，本入口不覆盖 Brain 访问。

需要五个不同的专用测试凭证，预先通过秘密管理注入以下环境变量，不放入命令参数、配置文件或日志：

| 环境变量 | 要求 |
|---|---|
| `AI_AGENT_AUTH_ACCEPTANCE_CREATOR_TOKEN` | 创建者有效凭证 |
| `AI_AGENT_AUTH_ACCEPTANCE_REFRESHED_TOKEN` | 同一创建者刷新后的另一个有效凭证 |
| `AI_AGENT_AUTH_ACCEPTANCE_REVIEWER_TOKEN` | 同租户另一人的有效凭证，其个人审批 ID 已在候选名单 |
| `AI_AGENT_AUTH_ACCEPTANCE_UNLISTED_TOKEN` | 同租户第三人的有效凭证，其个人审批 ID 不在候选名单 |
| `AI_AGENT_AUTH_ACCEPTANCE_EXPIRED_TOKEN` | 明确已过期/失效、预期被拒绝的测试凭证 |

凭证必须非空、互不相同、无空白或控制字符，并满足 Console 的 2500 字节输入上限；有效凭证需在整个验收窗口内有效。不同 subject 不一定对应不同自然人，真实账号关系仍由身份服务契约保证。

在仓库根目录执行（先注入上述五个凭证，示例不包含其值）：

```bash
AI_AGENT_RUN_AUTH_ACCEPTANCE=true \
AI_AGENT_AUTH_ACCEPTANCE_CONFIG=/absolute/path/config.reviewed.yaml \
AI_AGENT_AUTH_ACCEPTANCE_TENANT=project-a \
go test -v -count=1 -timeout=2m ./internal/api -run '^TestExternalProductionAuthAcceptance$'
```

身份请求使用生产 introspection 实现及网络政策。测试使用本地 Gin 请求和 Memory Store；Console 会话密钥只在测试进程临时设置。任务只创建及解决审批，不执行工具，不调用 LLM，不写生产任务/数据库，也不修改或重载运行中实例。外部行为仅为向指定身份服务验证测试凭证；超时、错误响应或身份服务不可用会使验收失败。

## 覆盖与边界

同一入口的 fake 夹具在普通测试中执行，确保验收脚本自身可回归。在线启用后检查：

1. 创建者、刷新凭证身份相同；reviewer/unlisted 是同租户的不同个人主体，且均非管理员。
2. 过期和缺失凭证返回 401；服务不可用的 503 不算凭证正确拒绝。
3. API 与真实 Console 登录/加密 Cookie 路由创建任务，创建者取已验证主体，伪造请求字段不改变它。
4. Console 缺少 CSRF 返回 403。
5. 创建者（含刷新凭证）、名单外人员和过期凭证不能批准或拒绝；本地审批 channel 不受影响。
6. 名单外人员仍可读取租户内审批记录；独立 reviewer 能批准/拒绝，并正确记录个人审批 ID。

所有失败断言只输出场景、HTTP 状态及固定原因，不输出 token、配置原文、个人原始 ID、Cookie 或响应体。验收文件解析/校验错误也不回显输入内容。

该入口不是生产部署验收：未覆盖在线 PostgreSQL/Redis 审批 CAS、真实部署的环境覆盖/Console 会话密钥、跨实例恢复、身份服务撤销延迟、浏览器发行版本或完整 RBAC。运行成功也不能证明 issuer/subject 的业务语义或不同账号背后的自然人关系。仍需核验已部署配置、真实角色名单及服务访问链路。
