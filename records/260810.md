## 三、PostgreSQL 与 ParadeDB 选择分析

ParadeDB 不是完全独立于 PostgreSQL 的另一种协议，而是以 PostgreSQL 为基础并提供 `pg_search` BM25 搜索能力。因此：

- 标准 PostgreSQL + pgvector 更适合当前事务、任务状态、Session、租约和向量记忆存储。
- 当需要 BM25、专有名词/错误码精确召回、全文搜索和向量混合排序时，ParadeDB 更有价值。
- 仅将 DSN 指向 ParadeDB，而不创建 BM25 索引和调用 `pg_search` SQL，不会自动获得 ParadeDB 搜索收益。
- ParadeDB Community 的 BM25 索引恢复、物理复制和 PITR 能力需要谨慎评估；生产关键搜索建议评估 Enterprise/BYOC。

## 五、ParadeDB 混合检索实现

### 5.1 配置

新增/启用：

```bash
AI_AGENT_STORE_TYPE=postgres
AI_AGENT_STORE_VECTOR_SEARCH=paradedb
AI_AGENT_STORE_PGVECTOR_DIMENSIONS=1536
```

`store.vector_search` 现在支持：

- `in_process`：读取候选后在 Go 中排序
- `pgvector`：使用 PostgreSQL/pgvector 余弦距离
- `paradedb`：融合 ParadeDB BM25 与 pgvector 排名

### 5.2 实现内容

- 显式 `paradedb` 模式下自动检查/启用 `pg_search`。
- 为 `memories` 创建 covering BM25 索引，覆盖：
  - `id`
  - `tenant_id`
  - `session_id`
  - `goal`
  - `final_answer`
  - `key_findings`
  - `timestamp`
- 使用 `goal ||| query`、`final_answer ||| query`、`key_findings ||| query` 做 BM25 候选检索。
- 使用 `paradedb.score(id)` 排序 BM25 结果。
- 分别获取 BM25 和 pgvector 候选，再使用 Reciprocal Rank Fusion（RRF）融合名次，避免直接混合不可比的 BM25 分数和余弦分数。
- 融合后继续应用已有的记忆时间衰减。
- BM25 或 pgvector 任一路径失败时使用剩余路径；全部失败时回退到原有进程内排序。
- 保留租户和 Session 过滤。

### 5.3 验证

- 在事务内验证 `pg_search 0.20.7` 的 `bm25`、`|||`、`@@@` 和 `paradedb.score` 语法后回滚探测索引。
- 新增真实 ParadeDB 混合排序集成测试。
- 测试使用三个随机 ID 的 Memory 验证“BM25 与向量均匹配”的结果排在首位。
- 修复了集成测试清理顺序，确保 Store 关闭前逐条删除测试 Memory。
- 曾遗留的三条集成测试 Memory 已按明确 ID 逐条删除，最终残留数为 0。

## 六、PostgreSQL UTF-8 错误分析与修复

### 6.1 故障

任务 `3288ca7b-933a-4e70-9909-7138e8cba04a` 执行时出现：

```text
failed to persist run-all progress
pq: invalid byte sequence for encoding "UTF8": 0xc2 0x0a (22021)
```

数据库中该任务最后状态为：

```text
status=running
step_count=0
trace rows=0
task lease rows=0
```

因此失败发生在第一条 Trace 保存前；任务没有活动租约，修复并重启后可以直接重新调用 `run-all`。

### 6.2 根因

`internal/tools/middleware.go` 原逻辑：

```go
result.Observation = result.Observation[:4000] + "\n...[truncated by middleware]"
```

该逻辑按字节切片。如果第 4000 字节是 UTF-8 多字节字符的首字节（本次为 `0xC2`），切片会丢失后续字节，然后直接追加以 `0x0A` 开头的换行，形成 PostgreSQL 拒绝的非法序列 `0xC2 0x0A`。

### 6.3 修复

源头修复：

- 工具 Observation 先通过 `strings.ToValidUTF8` 规范化。
- 超过 4000 字节时向前寻找合法 UTF-8 边界，再追加截断标记。

持久化防线：

- PostgreSQL Store 新增 `postgresText`。
- 对 Task、Trace、Memory 的直接文本列写入前统一执行 UTF-8 验证。
- 非法字节使用 Unicode replacement character `U+FFFD` 替换。
- JSON 字段继续由 `encoding/json` 负责有效 UTF-8 编码。

### 6.4 回归验证

新增测试覆盖：

- 3999 个 ASCII 字节后追加 `¢`，确保第 4000 字节恰好是 `0xC2`，验证截断结果仍为合法 UTF-8。
- 直接输入 `before\xC2\nafter`，验证工具边界和 PostgreSQL 边界均转换为 `before�\nafter`。
- 在真实 ParadeDB 中保存含非法 UTF-8 的 Task Trace，确认写入成功且读回内容正确。
- 测试任务按唯一 ID 清理，数据库残留数为 0。
