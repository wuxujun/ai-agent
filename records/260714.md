# ParadeDB 支持情况分析

## 结论

当前项目对 ParadeDB 属于 **PostgreSQL 兼容接入**，不是 **原生 ParadeDB 集成**。

| 场景 | 支持情况 |
| --- | --- |
| 将可读写 ParadeDB 当作 PostgreSQL 存储 | 基本支持 |
| 使用 ParadeDB 内置 pgvector 做向量检索 | 支持，但有权限前提 |
| 使用 ParadeDB `pg_search` / BM25 全文检索 | 不支持 |
| 使用 ParadeDB 混合检索 | 不支持 |
| 将只读逻辑副本作为应用主存储 | 不支持 |
| 已经过 ParadeDB 集成测试 | 没有 |

## PostgreSQL 兼容接入依据

项目已经实现完整的 PostgreSQL Store：

- 启动入口接受 `store.type=postgres` 和 PostgreSQL DSN：`cmd/server/main.go:114`。
- 使用标准 `lib/pq` PostgreSQL 驱动：`internal/store/postgres.go:15`。
- 建表语句主要使用标准 PostgreSQL 类型、事务、外键和 `ON CONFLICT`：`internal/store/postgres.go:52`。
- ParadeDB 本身可以作为 PostgreSQL 数据库运行，并使用标准 PostgreSQL 连接方式，参见 [ParadeDB 安装文档](https://docs.paradedb.com/documentation/getting-started/install)。

因此，针对独立部署且允许读写和建表的 ParadeDB，可以直接尝试：

```bash
export AI_AGENT_STORE_TYPE=postgres
export AI_AGENT_STORE_DSN='postgresql://user:password@host:5432/ai_agent?sslmode=require'
export AI_AGENT_STORE_VECTOR_SEARCH=in_process

go run ./cmd/server
```

`in_process` 是最稳妥的初次接入方式，不依赖额外扩展权限。

## pgvector 支持

项目已有 pgvector 检索路径：

- 自动执行 `CREATE EXTENSION IF NOT EXISTS vector`：`internal/store/postgres.go:634`。
- 创建 `vector` 字段及可选 HNSW 索引：`internal/store/postgres.go:647`。
- 使用 `<=>` 余弦距离排序：`internal/store/postgres.go:722`。
- 配置入口位于 `config.yaml:40`。

ParadeDB 官方 Docker 镜像预装了 pgvector，因此这条路径在标准镜像上具有兼容基础，参见 [ParadeDB 扩展文档](https://docs.paradedb.com/deploy/third-party-extensions)。

配置示例：

```bash
export AI_AGENT_STORE_TYPE=postgres
export AI_AGENT_STORE_DSN='postgresql://user:password@host:5432/ai_agent?sslmode=require'
export AI_AGENT_STORE_VECTOR_SEARCH=pgvector
export AI_AGENT_STORE_PGVECTOR_DIMENSIONS=1536
```

连接用户必须能创建扩展和修改表。如果没有 `CREATE EXTENSION` 权限，服务会在初始化阶段失败。此时可以由管理员预先执行：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

或者继续使用 `in_process`。

## 尚未支持的 ParadeDB 核心能力

当前业务代码和配置中没有发现以下内容：

- `pg_search`
- `USING bm25`
- ParadeDB 查询操作符
- ParadeDB BM25 索引迁移
- 全文结果与向量结果融合

所以即使底层数据库换成 ParadeDB，目前也只会把它当普通 PostgreSQL/pgvector 使用，不会获得 ParadeDB 的 BM25、模糊全文检索或混合搜索优势。ParadeDB 原生全文检索需要创建 `USING bm25` 索引并使用对应查询接口，参见 [BM25 索引文档](https://docs.paradedb.com/documentation/indexing/create-index)。

此外，项目的无向量关键词检索仍然是拉取候选记录后在 Go 进程内排序，而不是下推给 ParadeDB，相关实现位于 `internal/store/postgres.go:828`。

## 使用限制

如果 ParadeDB 是 PostgreSQL 的逻辑副本，则不能直接作为当前应用的 Store：

- 当前 Store 启动时会执行 `CREATE TABLE` 和 `ALTER TABLE`。
- 运行时会持续执行 INSERT、UPDATE 和 DELETE。
- ParadeDB 官方说明逻辑复制不会复制 DDL，需要单独管理 schema，参见 [ParadeDB 限制说明](https://docs.paradedb.com/welcome/limitations)。

仓库目前只有通过 `TEST_POSTGRES_DSN` 启用的通用 PostgreSQL 集成测试，没有 ParadeDB 专项测试。

本次执行了：

```bash
go test ./internal/store ./internal/config
```

两组测试均通过，但这不能替代真实 ParadeDB 连接验证。

## 最终判断

**可将可读写 ParadeDB 作为 PostgreSQL 后端接入，也可使用 pgvector；但项目尚未原生利用 ParadeDB 的 `pg_search`、BM25 和混合检索能力，因此不能称为完整支持。**
