### 1. 内存存储（ MemoryStore ）异步索引去重与并发安全优化 (Bug #12)

  • 现状问题：在  MemoryStore.SaveFullTask  中，对于已完成的任务会异步启动 Embedding 计算并索引为 RAG
  长期记忆。由于异步任务的耗时性（如需请求远程接口），若外部快速连续调用  SaveFullTask ，会在第一个协程尚未写入  m.memories  前多次触发
  SaveFullTask ，从而并发启动重复的 Embedding 计算协程。
  • 改进方案：
      • 在  MemoryStore  结构体中新增  indexing map[string]bool  字典，用于同步标记与阻断正在进行中的异步 Embedding 计算。
      •  SaveFullTask  在写锁保护下原子性判断  !alreadyIndexed && !alreadyIndexing  并预先将  indexing[task.ID] = true  占位，任务执行完成后再在
      defer  中删除。
      • 为此新增单元测试 memory_test.go，覆盖高并发调用时的去重及安全性，运行并通过  -race  检查。


  ### 2. Redis 存储（ RedisStore ）分布式多实例迁移锁优化 (Bug #18)

  • 现状问题：当对旧版本索引数据进行  tasksIndexV2  平滑迁移时（ ensureTaskIndexes ），原本仅使用了进程内的  migrationMu sync.Mutex
  互斥锁。如果生产环境有多实例部署，各实例会同时检测迁移状态并执行数据重建，存在并发竞态与数据库写入放大。
  • 改进方案：
      • 使用 Redis 的  SetNX  原语设计了分布式锁机制（带 5 分钟超时防死锁），配合 Ticker
      轮询机制，确保任一实例在做索引迁移时，其他实例均挂起并静默等待迁移标志位，避免重复执行数据回填。


  ### 3. RAG 余弦相似度计算维度不匹配（CosineSimilarity）调试优化 (Bug #14)

  • 现状问题： CosineSimilarity  在遇到本地 128 维与远程高维模型向量（如 768 / 1536 维）混合查询时，会直接静默返回  0 ，使得 RAG
  回路处于退化状态且无任何排查线索。
  • 改进方案：
      • 对  CosineSimilarity  引入显式检查，当检测到两个非空向量的维度不匹配时输出  log.Warn  警告日志。
      • 重构了  MemoryStore  中的  cosineSimilarity  本地拷贝，将其统一收拢至并复用  internal/memory.CosineSimilarity ，减少冗余代码。

  ## 变更总结 (Summary of Changes)

  ### 1. 跨平台支持的  O_NOFOLLOW  标志定义

  由于 Go 标准库的  os  包不直接提供跨平台的  O_NOFOLLOW  标志，我们在 policy 下定义了平台专用的文件，使用 Go 构建标签（Build
  Tags）实现安全兼容：

  • nofollow_unix.go：在 Unix/macOS 系统下，将  policy.O_NOFOLLOW  映射为底层的  syscall.O_NOFOLLOW  标志，从而通知内核在  open
  系统调用时拒绝跟踪任何符号链接（Symlink）。
  • nofollow_windows.go：在 Windows 下将其定义为  0 （不启用），确保在不支持该原生 open 标志的平台上代码依然能够无缝编译运行。

  ### 2. 工具写入和读取逻辑防御升级

  • write.go：
      • 将  os.WriteFile  替换为底层的  os.OpenFile(full, os.O_WRONLY|os.O_CREATE|os.O_TRUNC|policy.O_NOFOLLOW, 0644) 。
      • 若目标路径已被操纵成外部符号链接， open  会被内核直接拒绝（返回  ELOOP  或  os.ErrPermission  等错误），阻止其逃逸写入到沙箱外部。
  • apply_patch.go：
      • 对  applySearchReplaceBlocks  进行了重大安全增强，增加了  workspace  参数。
      • 写前/读前即时复核：在具体读取和具体写入前，分别立即调用  policy.ValidateReadPath  和  policy.ValidateWritePath ，缩小 TOCTOU
      路径校验与实际文件访问之间的时间窗（Symlink Swap Window）。
      • 配合  policy.O_NOFOLLOW  进行安全的底层文件读写操作。


  ### 3. 单元测试与安全性验证

  • 新增测试文件 symlink_toctou_test.go：
      •  TestWriteFile_SymlinkBlocked ：创建包含真实文件和对应符号链接的工作空间，当尝试通过  WriteFile
      写入该符号链接路径时，断言该操作失败，且真实文件未被覆盖。
      •  TestApplyPatch_SymlinkBlocked ：对符号链接应用  applySearchReplaceBlocks  时，验证操作会被安全拒绝，原文件保留完整。
