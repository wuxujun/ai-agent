# Langfuse Prompt 管理优化记录

> 日期：2026-07-18
>
> 范围：Multi-Agent system prompt 从 Langfuse 获取的隐藏问题核查与修复

## 结论

本次核查确认，Langfuse Prompt 管理能力已接入 Multi-Agent 的 Planner、Replanner、Writer、Verifier，但初始实现存在几个生产隐患：

- `teams.yaml` 已配置自定义 `system_prompt` 时，仍会先请求 Langfuse，再被本地 team prompt 覆盖，造成无意义网络调用和潜在 3 秒延迟。
- Langfuse `prompt` 字段只按字符串解析，无法兼容 chat prompt 数组格式。
- 缓存 key 只使用 prompt name，热加载或切换 host/key 后可能复用旧环境下的 prompt。
- prompt name 直接拼接到 URL path，包含 `/`、空格、中文等字符时会构造错误请求路径。

以上问题已完成修复，并补充对应回归测试。

## 一、优化内容

### 1. Team Prompt 优先级修正

涉及文件：

- `internal/multiagent/planner_agent.go`
- `internal/multiagent/writer_agent.go`

调整前逻辑：

```text
先从 Langfuse 获取 prompt
再检查 teams.yaml system_prompt
如果存在，则覆盖 Langfuse 结果
```

调整后逻辑：

```text
先检查 teams.yaml system_prompt
存在则直接使用本地 team prompt
不存在才从 Langfuse 获取
```

效果：

- 避免 team prompt 场景下的无意义 Langfuse 请求。
- 避免 Langfuse 故障或超时影响本地自定义 team prompt。
- 保持本地 team 配置的显式优先级。

Verifier 当前没有 team prompt 分支，因此继续使用 `Langfuse -> fallback` 逻辑。

### 2. 兼容 Langfuse Text Prompt 与 Chat Prompt

涉及文件：

- `internal/promptmanager/client.go`
- `internal/promptmanager/client_test.go`

调整前：

```go
type PromptResponse struct {
	Name   string `json:"name"`
	Prompt string `json:"prompt"`
}
```

该实现只能解析：

```json
{
  "prompt": "text prompt"
}
```

调整后：

```go
type PromptResponse struct {
	Name   string          `json:"name"`
	Prompt json.RawMessage `json:"prompt"`
}
```

并新增 `renderPromptContent`：

- 当 `prompt` 是字符串时，直接作为 text prompt 使用。
- 当 `prompt` 是 chat messages 数组时，按 `role: content` 渲染为 system prompt 文本。
- 当 `prompt` 为空、`null` 或无法识别时，返回错误并走 fallback。

示例 chat prompt：

```json
{
  "prompt": [
    {"role": "system", "content": "Follow the evidence."},
    {"role": "user", "content": "Return JSON only."}
  ]
}
```

渲染结果：

```text
system: Follow the evidence.

user: Return JSON only.
```

### 3. 缓存维度隔离

涉及文件：

- `internal/promptmanager/client.go`
- `internal/promptmanager/client_test.go`

调整前缓存 key：

```text
name
```

风险：

- 同名 prompt 在不同 Langfuse host 下可能复用旧缓存。
- 切换 public key 后可能仍命中旧租户或旧环境 prompt。
- 后续如果支持 label/stage，会继续扩大误命中风险。

调整后缓存 key：

```text
host + public_key + name + label
```

当前 label 固定为 `production`。这样即使运行中热加载配置或切换环境，同名 prompt 也不会错误复用旧缓存。

失败 fallback 也使用相同缓存 key，仅短缓存 1 分钟，避免 Langfuse 故障时每次请求都打远端。

### 4. URL 构造安全化

涉及文件：

- `internal/promptmanager/client.go`
- `internal/promptmanager/client_test.go`

调整前：

```go
fmt.Sprintf("%s/api/public/v2/prompts/%s?label=production", host, name)
```

问题：

- prompt name 包含 `/` 时会被误认为多级 path。
- prompt name 包含空格、中文等字符时，URL 语义不稳定。
- host 缺少 scheme/host 时没有明确配置错误。

调整后新增 `buildPromptURL`：

- 默认 host 仍为 `https://cloud.langfuse.com`。
- 校验 host 必须包含 scheme 和 host。
- prompt name 执行 `url.PathEscape`。
- `label=production` 使用 query API 设置。
- 空 prompt name 返回错误并走 fallback。

示例：

```text
name = "folder/a b/中文"
```

生成路径：

```text
/api/public/v2/prompts/folder%2Fa%20b%2F%E4%B8%AD%E6%96%87?label=production
```

## 四、当前行为基线

Langfuse Prompt 管理当前生效范围：

- `multiagent_planner_prompt`
- `multiagent_replanner_prompt`
- `multiagent_writer_prompt`
- `multiagent_verifier_prompt`

Prompt 优先级：

```text
teams.yaml system_prompt
    > Langfuse prompt
    > 代码内置 fallback prompt
```

其中 Verifier 暂无 `teams.yaml` 自定义 system prompt 分支，因此实际为：

```text
Langfuse prompt
    > 代码内置 fallback prompt
```

## 五、后续建议

建议后续将 Langfuse Prompt 管理能力继续收敛为更完整的通用模块：

- 增加可配置 `label`，不固定为 `production`。
- 增加 prompt 获取指标，例如 hit/miss/fallback/error/latency。
- 在日志中区分 fallback 原因：disabled、missing credentials、remote error、invalid response、invalid URL。
- 考虑对 prompt 内容增加最小结构校验，避免错误 prompt 破坏 JSON 输出约束。
- 如需覆盖单智能体链路，可把 promptmanager 从 Multi-Agent 逐步推广到 planner/finalizer/checker 等 LLM 场景，但应先明确每个 scene 的 prompt name 命名规范和 fallback 策略。
