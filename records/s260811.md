### 10.2 checkpoint 原位更新持久化缺陷

取消复验首次发现：内存中的 checkpoint 已从 `plan=running` 更新为 `plan=failed`，但 SQLite
重新读取后仍是 running。根因是 DAG 为每个 graph/route 原位更新同一条 checkpoint Trace，而
SQLite/PostgreSQL 的增量 Trace 保存只插入新 step，历史 step 一律跳过。

修复为：普通 Trace 继续保持 append-only；仅对 action 为
`multiagent_workflow_checkpoint` 的既有 step 执行定向 UPDATE。SQLite 和 PostgreSQL 的
`ReplaceTraces`、`SaveFullTask` 两条路径均已覆盖，并新增 SQLite 回归验证 running checkpoint
可被 failed checkpoint 覆盖。

### 10.5 answer_audit 最终发布稿语义

修复 `answer_verify` 审计导入遍历所有历史 Trace 的问题。Reviewed 自适应深挖可能先拒绝一个草稿，
补充证据后再发布 supported 草稿；旧逻辑仍会把首个草稿的 issue 提升为最终
`answer_verify=warned`。

现改为只从最后一次最终答案尝试（最新 `verify` 或 `write` Trace）生成发布稿 findings：

- 最终 supported 且无 issue：不再携带历史 warning；
- 最终仍 unsupported：仅报告最终尝试的 issue；
- 被拒草稿的历史 Trace 不删除，继续用于诊断和不确定性上下文。

新增回归覆盖“旧 contradiction + 最终 supported”和“两次 unsupported 只采用最新 findings”。
`internal/answerpipeline`、`internal/orchestrator`、`internal/multiagent` 测试通过。

剩余优化项收敛为中文 workspace 意图鲁棒性与 DAG 默认 runtime 决策。

### 10.6 中文 workspace 意图确定性门禁

现有 JIT 路由已能识别“工作区、项目中、仓库中、本地文件、源代码、代码库”等中文本地目标，
但 LLM Planner 仍可能直接返回纯 `rag_search` 计划，且原后置校正只覆盖外部事实误用 workspace
工具的单向漂移。

新增对称门禁：当目标明确指向 workspace/repository，且计划全部由 `rag_search`、
`memory_search`、`web_search`、`http_fetch` 等外部检索动作组成时，将计划确定性修复为：

1. `find_files` 发现任务 workspace 文件；
2. `search_text` 使用原目标搜索本地内容。

混合计划或已有任何 workspace/tool 动作时不改写。门禁覆盖初始 Plan、Legacy Replan、Critic
Replan、Research DAG Replan 和 Reviewed DAG adaptive-depth Replan。新增中文误路由及混合计划
保留测试，Planner/MultiAgent/Orchestrator 测试通过。

中文 workspace 的已知单样本失败已有确定性防护；是否切换默认 DAG 仍应以扩大后的真实样本矩阵和
延迟/成功率指标决定，不在本次会话中仅凭单次 Canary 自动切换生产默认值。
