取消复验首次发现：内存中的 checkpoint 已从 `plan=running` 更新为 `plan=failed`，但 SQLite

修复为：普通 Trace 继续保持 append-only；仅对 action 为
`multiagent_workflow_checkpoint` 的既有 step 执行定向 UPDATE。SQLite 和 PostgreSQL 的
`ReplaceTraces`、`SaveFullTask` 两条路径均已覆盖，并新增 SQLite 回归验证 running checkpoint
可被 failed checkpoint 覆盖。

### 10.13 software 团队稳定分桶 DAG Canary

现有部署只有单实例 systemd 服务，直接把 `software.runtime` 改成 `dag` 会一次性切换 100%，无法表达

- 以 active team 和 task ID 的 SHA-256 摘要映射到 0–99，跨进程和重启结果稳定；

- 分桶 Trace 不进入 Replanner prompt，也不计入工具步数；
- 显式 `runtime=dag` 保持 100% DAG 语义，百分比非法或未配置时安全回退为 0；
- team config digest 包含灰度比例，继续受既有 `resume_config_policy` 保护。

默认配置仍为 `software.runtime=legacy`、`dag_canary_percent=0`，没有自动改变线上流量。新增 systemd
环境示例与启用/观测/回滚清单；推荐从 5% 开始，通过 `/api/metrics` 和 OTel histogram 对比完成率、
失败率、fallback、审批、Replan、平均延迟和 P95。回滚将比例设为 0 并重启，新任务立即回到 Legacy，
