# Answer Audit API

> 版本：P3
>
> 日期：2026-07-17

## 认证与租户隔离

所有 `/api/*` 接口均需认证。`api.auth.mode` 支持：

- `api_key`：使用 `X-API-Key` 或 `Authorization: Bearer <静态密钥>`。
- `jwt`：只接受 `Authorization: Bearer <JWT>`。
- `introspection`：使用 GET 请求固定的第三方验证端点，并在 `Authorization: Bearer` 请求头中转发 Token。
- `hybrid`：兼容静态 Key，并通过 `bearer.validation_mode` 选择 `jwks` 或 `introspection`。

JWT 模式会通过 JWKS 校验 RSA 签名，并强制校验 `iss`、`aud`、`exp`，
同时校验存在的 `nbf`；全部通过后才读取默认名为 `code` 的租户 Claim。默认只接受
`api.tenants` 中已配置的租户，管理员权限始终取自本地配置，不读取 JWT
中自报的管理员字段。

```yaml
api:
  auth:
    mode: hybrid
    jwt:
      issuer: "https://auth.example.com"
      audience: "ai-agent"
      jwks_url: "https://auth.example.com/.well-known/jwks.json"
      tenant_claim: "code"
      allowed_algorithms: ["RS256"]
      require_known_tenant: true
  tenants:
    project_a:
      admin: false
      daily_llm_call_budget: 100
```

第三方验证使用 GET + Bearer Header：只有 HTTP 200、合法 JSON、`data.active=true`
且 `data.userid`、可选 `iss/aud/exp` 约束全部通过后才建立租户身份。字段配置支持
点分隔路径。失败结果不缓存；
成功结果按 Token 的 SHA-256 缓存短时间，明文 Token 不进入缓存或日志。

```yaml
api:
  auth:
    mode: hybrid
    bearer:
      validation_mode: introspection
    introspection:
      url: "https://auth.example.com/oauth/introspect"
      tenant_claim: "data.userid"
      active_claim: "data.active"
      require_known_tenant: true
      timeout_seconds: 3
      cache_ttl_seconds: 10
```

- 普通租户只能读取和重审自身任务；跨租户任务 ID 返回 `404`，避免泄露任务是否存在。
- 管理员可通过 `tenant_id` 查询指定租户，省略时查询全部租户。
- 审计列表不返回 `final_answer`，只返回任务标识、任务状态和结构化 `answer_audit`。

## Task 中的审计字段

`GET /api/tasks/:id` 的兼容响应新增可选字段：

```json
{
  "answer_audit": {
    "pipeline_version": "p2-v1",
    "draft_hash": "...",
    "evidence_hash": "...",
    "started_at": "2026-07-17T08:00:00Z",
    "completed_at": "2026-07-17T08:00:01Z",
    "final_confidence": "medium",
    "enforcement": "strict",
    "publishable": true,
    "stages": [
      {
        "name": "fact_freshness_check",
        "status": "warned",
        "fingerprint": "...",
        "findings": [
          {"kind": "staleness", "detail": "Evidence date is incomplete", "source_id": "E1"}
        ],
        "token_usage": {"total_tokens": 320},
        "duration_ms": 420
      }
    ]
  }
}
```

Stage 状态固定为：`passed`、`warned`、`not_applicable`、`disabled`、`budget_insufficient`、`dependency_failed`、`failed`。

## 分页查询审计

```http
GET /api/audits?limit=50&offset=0
```

可选过滤条件：

| 参数 | 含义 |
|---|---|
| `tenant_id` | 管理员限定租户；普通租户传入后会被忽略 |
| `task_status` | `completed`、`partial` 或 `failed` 等任务状态 |
| `stage` | Stage 名称 |
| `stage_status` | Stage 状态 |
| `confidence` | `high`、`medium`、`low` |
| `enforcement` | `observe`、`advisory`、`strict` |
| `publishable` | `true` 或 `false` |
| `limit` | 默认 50，最大 200 |
| `offset` | 匹配结果偏移量 |

响应：

```json
{
  "audits": [],
  "count": 0,
  "limit": 50,
  "offset": 0,
  "has_more": false,
  "next_offset": 0
}
```

下一页使用返回的 `next_offset`。查询通过 Store 的稳定 Task ID 顺序分批扫描，因此 SQLite、PostgreSQL、Redis 和 MemoryStore 语义一致。

## Dashboard 汇总

```http
GET /api/audits/summary?tenant_id=project_a
```

支持与审计列表相同的过滤条件，返回：

- `eligible_tasks`：具有非空答案的终态任务数。
- `audited_tasks` 和 `coverage_rate`：匹配过滤条件的审计覆盖量及比例。
- `publishable_tasks`。
- `confidence_counts`。
- `enforcement_counts`。
- `stage_status_counts`：按 Stage 和状态聚合，可直接用于覆盖率、失败率和跳过原因 Dashboard。

## 显式重审

```http
POST /api/tasks/:id/re-audit
Content-Type: application/json

{"force": false}
```

- 仅接受 `completed`、`partial`、`failed` 且 `final_answer` 非空的任务。
- `force=false` 会复用相同指纹的 Stage；答案、证据、Pipeline 版本或 Freshness 日期变化时自动重新执行。
- `force=true` 忽略旧 Report 的 Stage 缓存，但保留历史 Trace TokenUsage，因此仍受任务和租户预算约束。
- 请求使用任务分布式租约，运行中的任务或其他实例正在重审时返回 `409`。
- Pipeline 成功后同步调用 `SaveFullTask`；失败时恢复调用前的 Task 快照。
- `strict` 或 `advisory` 重审可能把原 `completed` 任务调整为 `partial/failed`，并更新 `publishable`。

## 租户级策略

租户可覆盖全局 enforcement 和 required stages：

```yaml
api:
  tenants:
    project_a:
      api_key: "<secret>"
      answer_pipeline_enforcement: strict
      answer_pipeline_required_stages:
        - fact_freshness_check
        - numeric_consistency_check
        - answer_uncertainty_calibrate
        - safety_guard_output
```

配置热加载后，下一个 Pipeline 或 re-audit 请求立即读取新策略。未知或重复 Stage 会导致配置校验失败。
