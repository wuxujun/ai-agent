# Multi-Agent 双工作流方案可行性分析报告

**日期**：2026-07-20  
**分析对象**：当前项目 Multi-Agent 双工作流架构（方案一：`planner_researcher_writer` 与 方案二：`planner_critic_executor_verifier`）

---

## 一、 背景与方案概述

在最新的架构演进中（参见 [records/260720.md](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/records/260720.md)），项目实现了 Multi-Agent 的**双工作流支持**，旨在兼顾“高效率开放生成”与“高严谨受控执行”两种不同的业务需求。

目前系统中并存的两种 Multi-Agent 方案如下：

1. **方案一：3 角色工作流 (`planner_researcher_writer`)**
   - **拓扑结构**：`Planner` $\rightarrow$ `Researcher` $\rightarrow$ `Writer`
   - **核心定位**：开放生成、数据检索、知识梳理与研讨写作类任务。

2. **方案二：4 角色工作流 (`planner_critic_executor_verifier`)**
   - **拓扑结构**：`Planner` $\rightarrow$ `Critic` $\rightarrow$ `Executor` $\rightarrow$ `Verifier`
   - **核心定位**：受控代码变更、系统配置执行、高风险命令运行与高准确度校验类任务。

---

## 二、 2 种工作流拓扑对比

| 维度 | 方案一：3 角色工作流 (`planner_researcher_writer`) | 方案二：4 角色工作流 (`planner_critic_executor_verifier`) |
| :--- | :--- | :--- |
| **工作流程** | 1. Planner 拆解规划步骤<br>2. Researcher 检索与执行工具<br>3. Writer 综合信息输出最终结果 | 1. Planner 制定初步计划<br>2. **Critic 前置审查**（不通过则触发 Replan）<br>3. Executor 受控执行工具<br>4. **Verifier 后置验证**（校验对齐度与置信度） |
| **交互链路** | 短（3 阶段） | 长（4 阶段，驳回时递增） |
| **响应时延** | 较低 | 稍高 |
| ** Token 消耗** | 较低 | 较高 |
| **防错/防幻觉能力**| 基础依赖 LLM 自约束 | 强（前置审查 + 后置证据校验双重保障） |
| **适用场景** | 开放式查询、总结分析、文档撰写 | 复杂代码重构、系统变更、高风险脚本运行、强一致性校验 |

## 三、 可行性支撑与核心技术机制

通过对 [internal/multiagent](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent) 模块的深入分析，该架构在以下五个关键维度提供了扎实的可行性保障：

### 1. 动态解耦与向后兼容
- 通过 [teams.go](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/teams.go) 中的 `Workflow` 拓扑类型进行解耦，支持在 [teams.yaml](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/teams.yaml) 中通过 `workflow` 节点或环境变量（`AI_AGENT_MULTIAGENT_WORKFLOW`）无缝切换。
- 未指定工作流时，系统自动回退至默认 3 角色拓扑，保证了原有接口与场景的向后兼容。

### 2. 前置安全与逻辑闭环（Critic 审查）
- 方案二引入 [CriticAgent](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/critic_agent.go)，在工具真正执行前对计划的完整性、步骤依赖、安全风险和可行性进行结构化审查。
- **Replan 驳回机制**：若 Critic 否决计划，Coordinator 会将评审意见反馈给 Planner 进行计划修订（最多重试 1 次），大幅规避了因错误/高风险计划直接运行带来的破坏性后果。

### 3. 执行安全护栏（策略层隔离）
- [ExecutorAgent](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/researcher_agent.go) 与 `ResearcherAgent` 共享底层受保护的工具执行逻辑，强制受控于 `internal/policy` 护栏。
- 所有工具调用均须通过 Workspace 目录边界校验、高风险动作人工审批以及 Token/步数预算拦截，确保拓扑切换不会绕过策略控制。

### 4. 后置反幻觉与置信度降级（Verifier 校验）
- [VerifierAgent](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/verifier_agent.go) 根据 Executor 收集的真实证据，生成包含 `final_answer`、`evidence_summary`、`draft_confidence` 及 `supported` 的结构化校验报告。
- 识别 `unsupported_claim`（无证据主张）、`evidence_gap`（证据缺失）或 `contradiction`（矛盾）等问题。一旦校验未通过（`supported=false`），自动降级置信度至 `low` 并做保守提示。

### 5. Prompt 统一演进（Langfuse 集成）
- 两种方案的所有角色均接入了 Langfuse Prompt 统一管理（通过 [resolveAgentPrompt](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/teams.go#L34)）。
- 支持远程线上优化提示词，并在网络异常或服务不可用时按 `Langfuse -> System Prompt -> Code Default` 的层级平滑降级，具备极高的鲁棒性。

## 五、 潜在风险与优化建议

在实际生产应用中，建议关注以下潜在风险点并进行后续优化：

1. **时延与 Token 开销平衡**
   - **风险**：4 角色流程至少需要 4 次 LLM 调用，若触发 Replan 耗时与开销将翻倍。
   - **优化建议**：引入**自适应路由（Adaptive Routing）**机制，根据输入任务的风险度与复杂度自动分流（简单查询走 3 角色，写操作/复杂代码走 4 角色）。

2. **Critic 审核死锁风险**
   - **风险**：若 Critic 提示词要求过严，可能导致 Planner 连续 Replan 均被驳回而导致任务提前失败。
   - **优化建议**：在 [teams.yaml](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/teams.yaml) 中为 Critic 补充针对性的 Few-Shot 样例，建立清晰合理的否决边界。

3. **图编排拓扑演进（DAG Graph）**
   - **风险**：当前 3 角色与 4 角色均属于固定顺序的线性流转。
   - **优化建议**：未来可将 [Coordinator](file:///Users/xujunwu/Documents/IDEAProject/ai-agent/internal/multiagent/coordinator.go) 扩展为基于 DAG 的图编排引擎，支持专家 Agent 并行调度与条件分支跳转。
