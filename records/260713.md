# 2026-07-13 变更记录

## 一、功能增强

### 1. Context Compressor — Token 总量维度触发

**背景**：原有压缩触发仅依赖 Trace 条数（`context_compression_trace_threshold`），单条 Observation 非常长时（如大型代码执行结果）即使步数很少也可能导致上下文膨胀。

**变更内容**：

- `internal/config/config.go`：新增 `ContextCompressionTokenThreshold int` 字段（`mapstructure: context_compression_token_threshold`），默认 0（禁用）；同时补充配置校验（不允许负数）。
- `internal/planner/llm.go`：`PlanNext` 中在计算步数触发 (`traceLimitHit`) 之外，新增对所有新 Trace 的 `TokenUsage.TotalTokens` 累加，形成 `tokenLimitHit` 维度；两者满足其一即触发压缩，并携带 `reason: "trace_count" | "token_budget"` 区分。
- `config.yaml`：补充 `context_compression_token_threshold` 配置注释示例（默认注释掉）。

**回归测试**：`TestLLMPlannerTokenThresholdTrigger`（`internal/planner/llm_test.go`）
- 设置 Trace 阈值 999（不触发）、Token 阈值 100，构造 3 条 ×40 Token 的 Trace（总计 120）
- 断言 Compressor 被调用恰好 1 次，压缩触发 reason 为 `token_budget`

---

### 2. ApprovalBus — 重复/过期消息幂等告警

**背景**：Redis Pub/Sub 在消费者重连或多实例场景下可能重复投递审批消息。原代码 `ResolveApprovalByID` 返回 false 时无任何反馈，运营难以区分"正常已处理"与"消息路由异常"。

**变更内容**：

- `internal/orchestrator/approval_bus.go`：`dispatchApproval` 中当 `ApprovalID != ""` 且 `ResolveApprovalByID` 返回 false 时，增加 `busLog.Warn` 日志标注为"stale or duplicate message"，并附注不做 fallthrough 的安全原因（防止意外批准其他待审批操作）。

---

### 3. OTel 可观测性增强

**变更内容**：

- `internal/planner/llm.go`：
  - 压缩触发时调用 `span.AddEvent("context_compression_triggered")` 并附带 `compression.reason`、`compression.new_trace_count`、`compression.accumulated_tokens` 三个 span 属性，在 Jaeger/Grafana 中可直接筛选。
  - PlanNext 返回前追加 `llm.usage.prompt_tokens`、`llm.usage.completion_tokens`、`llm.usage.total_tokens` 到 span，无需查询 metrics 接口即可在 trace 层面看到 Token 消耗。

---

### 4. 配置热重载 Diff 报告增强

**背景**：在 `internal/config/config.go` 中，当配置文件或环境变量发生更改并触发热重载时，`diffConfigs` 辅助函数用于记录已更改配置项的对比信息。然而，新增的 `llm.context_compression_token_threshold` 和现有的 `embedding.model` 未在 `diffConfigs` 中进行比较，导致其在热重载时变更无法被正确输出到日志中。

**变更内容**：
- `internal/config/config.go`：在 `diffConfigs` 函数中补充对 `llm.context_compression_token_threshold` 和 `embedding.model` 字段的比对逻辑，确保这二者变更可被正确输出。
- `internal/config/config_test.go`：新增 `TestDiffConfigs_IncludesNewFields` 单元测试，专门验证 `diffConfigs` 能在热重载比较时捕获这两个字段的变化。

## 四、LLM 场景与可靠性优化（追加）

### 1. LLM 场景配置继承与显式覆盖

**变更内容**：

- `internal/config/config.go`：统一场景配置解析，调用方继续使用解析后的 `ResolvedLLMConfig`。
- `fallback_scene`、`max_retries`、`min_remaining_tokens` 改为可区分“未配置”和“显式零值”的配置字段。
- 场景现在可以使用 `fallback_scene: ""` 清除网关回退场景，使用 `max_retries: 0` 禁用重试，使用 `min_remaining_tokens: 0` 清除最低 Token 限制。
- 未出现的字段继续从 `llm.gateway` 和旧版扁平 LLM 配置继承，保持现有配置兼容。
- 增加网关和场景负数策略校验，并在 `config.yaml` 中补充显式覆盖示例。
- 增加程序构造及真实 YAML 解码回归测试。

### 2. LiteLLM Readiness 与缓存并发控制

**变更内容**：

- `internal/llm/health.go`：LiteLLM 场景先检查 `/health/liveliness`，再通过 `/v1/models` 验证当前凭证能否访问目标模型。
- `/ready` 的场景结果新增 `model`、`configured`、`gateway_reachable`、`model_available` 字段；保留原有 `provider`、`healthy` 和 `error` 字段。
- 场景结果新增 `verified` 和 `status`；状态明确区分 `ready`、`configured_unverified`、`unhealthy`。
- `/ready` 顶层新增 `llm_verified`，只有全部场景都经过验证时才为 true。
- OpenAI、Gemini、Ollama 等直接 Provider 不发送可能收费的生成探测；配置完整时保持 `healthy=true`，但标记为 `verified=false`、`status=configured_unverified`，不再伪报为已验证健康。
- 模型不存在、凭证无权限或网关不可达时，该场景标记为不健康，整体 `/ready` 返回 HTTP 503。
- 使用 `singleflight` 合并相同配置快照的并发探测，避免缓存失效时请求穿透。
- 健康缓存键包含 Provider、模型、Base URL 和非明文凭证指纹；模型、地址或凭证变更后不会复用旧结果。
- 不同虚拟 Key 的模型权限探测结果相互隔离，缓存和错误信息均不保存或输出明文 Key。

### 3. LLM 日志与上游错误脱敏

**变更内容**：

- `internal/planner/gemini_provider.go`：移除 Info 日志中的 System Prompt、User Prompt 和模型响应正文预览，仅保留模型、文本长度和 Token 指标。
- `internal/llm/errors.go`：统一构造 `HTTPStatusError`，不再向日志和 Trace 传播上游原始错误正文或 `message`。
- 仅保留经过长度和字符白名单限制的 `error.type`、`error.code`；非结构化正文统一显示 `response body omitted`。
- `internal/llm/transport.go` 和 `internal/planner/provider.go` 使用相同的安全错误处理逻辑。
- 增加敏感 message 丢弃、非结构化正文隐藏及安全元数据提取测试。

### 4. 重试与限流响应处理

**变更内容**：

- 支持解析 `Retry-After` 秒数及 HTTP 日期格式。
- 服务端建议等待时间最多采纳 30 秒，避免异常响应造成过长阻塞。
- 无 `Retry-After` 时使用带上限的 full jitter 指数退避，降低多实例同步重试风险。
- Structured LLM 和 Planner 的主场景、回退场景均传递实际错误到统一等待逻辑。
- 所有重试等待继续响应 Context 取消；429、408 和 5xx 状态仍按原有规则判定为可重试。
- 新增 Runtime 级跨请求熔断器，按场景、Provider、模型和端点隔离状态；默认连续 5 次可重试失败后打开，冷却 30 秒。
- 冷却结束后仅允许一个半开探测；探测成功关闭熔断器，失败则重新进入冷却。
- 新增每 Runtime 每分钟共享重试预算，默认允许 60 次额外重试；预算耗尽后快速失败，防止并发请求放大上游故障。
- Structured LLM、主 Planner 和 Planner fallback 共用 Context Runtime 的熔断状态与重试预算。
- 新增 `llm.circuit_breaker_failure_threshold`、`llm.circuit_breaker_cooldown_seconds`、`llm.retry_budget_per_minute` 配置及热重载 Diff；任一值设为 0 可禁用对应保护。

### 5. LLM Eval 命令加固

**变更内容**：

- `cmd/llm-eval` 重构为可测试的 `run` 入口，输入或参数错误不再直接 `panic`。
- 新增 `-timeout`，默认对每个用例设置 30 秒 Deadline。
- 新增 `-max-line-bytes`，默认允许最大 4 MiB JSONL 行，支持长 Prompt。
- 新增 `-format text|json`；JSON 模式输出逐用例结果及机器可读汇总。
- 支持 `expected_contains`、`expected_exact`、`expected_regex` 文本断言，并在逐用例结果中输出实际断言类型。
- 支持 `expected_json_path` + `expected_json_value` JSON 结构断言，可访问根节点、嵌套对象字段和数组索引，并按 JSON 类型和值进行语义比较。
- 新增 `-max-total-tokens` 总 Token 预算；达到上限后不再启动后续用例，单次调用导致超限时标记 `max_total_tokens_exceeded`。
- 新增输入/输出 Token 单价和 `-max-total-cost-usd` 费用预算；逐用例及汇总输出估算美元费用。
- JSONL 用例可通过 `input_cost_per_million_usd`、`output_cost_per_million_usd` 覆盖全局单价，支持不同场景模型分别计价。
- 支持 `judge_criteria` LLM-as-judge 断言，默认使用 `answer_verifier` 场景和 0.7 最低分，可覆盖 Judge 场景、阈值及独立 Token 单价。
- Judge 返回的分数、理由、Token 和估算费用进入逐用例结果及总预算。
- 新增 `-parallelism` 固定 Worker 池；执行可并发但结果始终按 JSONL 输入顺序输出。
- 输入改为执行前完整校验，任意行非法时不会产生部分 LLM 调用费用。
- 严格 Token 总预算与并行模式互斥，避免已在途调用突破聚合预算。
- 输入错误包含准确行号，并校验 `name`、`scene` 及三种断言字段必须且只能配置一个。
- 退出码约定：全部通过为 0，存在评测失败为 1，参数、输入或输出错误为 2。
- 增加成功、失败、超时、长输入、非法参数和 JSON 汇总测试。
- `deploy/litellm/README.md` 补充 CI 调用示例和退出码说明。

- Compose 配置校验和原有单元测试步骤保持不变。

### 7. 全局状态与测试隔离

**变更内容**：

- `internal/llm/structured.go` 新增可实例化的 `llm.Runtime`，由实例独立持有 Structured Caller 和 Observer。
- Runtime 的主调用、重试、fallback 递归及 Observer 事件均保持在同一实例内；不同 Runtime 之间互不修改状态。
- 新增 `WithRuntime`、`RuntimeFromContext` 和 `ObserveContext`；包级 `CallJSON` 会优先使用 Context 中的 Runtime，缺省时才回落默认实例。
- `cmd/server` 创建带 Metrics Observer 的独立 Runtime，并通过 Gin middleware 注入请求 Context；生产启动不再调用进程级 `RegisterObserver`。
- Planner 的调用事件通过 `ObserveContext` 上报，Finalizer、Memory 和 Multi-agent 的包级调用自动使用请求 Runtime。
- Memory、SQLite、PostgreSQL 和 Redis Store 的异步记忆索引使用 `context.WithoutCancel` 保留 Runtime 等 Context 值，再单独施加 30 秒超时。
- 现有包级 `CallJSON`、`Observe` 和 `Register*` API 继续作为兼容层，避免破坏 CLI 和外部调用方。
- `RegisterStructuredCaller` 和 `RegisterObserver` 返回幂等恢复函数，并使用版本号防止旧恢复函数覆盖后续注册。
- 禁止注册 nil Structured Caller；Observer 仍允许使用 nil 显式关闭观察。
- `internal/config/config.go` 新增 `OverrideForTesting`，通过克隆配置快照执行临时覆盖，并提供幂等、带版本保护的恢复函数。
- LLM 场景 Map 及策略指针执行深拷贝，避免测试修改原始配置快照。
- LLM、Planner、Multi-agent 和 API 测试已移除对 `config.Get()` 返回对象的直接赋值。
- API 认证测试不再修改环境后调用全局 Reload，改为按测试生命周期覆盖独立配置快照。
